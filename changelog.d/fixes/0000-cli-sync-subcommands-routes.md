- **fix(cli):** the `omniroute sync` subcommands now match the routes the server actually serves. `sync push` sent `{parts, dryRun, target}` to `POST /api/sync/cloud`, which only accepts `{action}`, so it always failed with 400; it now runs one cloud sync (`{action: "sync"}`, never retried) and explains a disabled cloud sync or a missing manage-scoped credential. `sync bundle` sent the API key and an ignored `?parts=` to `GET /api/sync/bundle`, which only accepts a sync token; it now takes `--token` (or `OMNIROUTE_SYNC_TOKEN`), fails before any request when none is given, and writes the `{version, bundle}` JSON to an owner-only file that it never overwrites. `sync diff` and `sync resolve` were removed: no server route computes a diff or lists conflicts, and both silently printed the cloud status instead. The ignored `--target/--bundle/--dry-run` (push), `--include` (bundle) and `--from-cloud` (initialize) options were dropped. Failures report the HTTP status, the server message and a hint, with the usual CLI exit codes.
