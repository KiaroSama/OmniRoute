- **fix(sync):** sync token management now stays authenticated when login is disabled. With `requireLogin=false`, an anonymous caller could issue a sync token and use it to download the config bundle (decrypted provider credentials and API keys), even though `/api/settings/export-json` already refused the same caller; the token also kept working after login was turned back on. Issuing, listing and revoking sync tokens now need a dashboard session or the local CLI in every login mode (`/api/sync/tokens` joins the always-protected tier), and tokens issued that way by earlier releases (`issuedBy: "open"`) no longer open the bundle — issue a new one from the dashboard or the CLI.
