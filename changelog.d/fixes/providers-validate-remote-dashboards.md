- **fix(authz): stop loopback-locking `/api/providers/{validate,import,bulk}` — the devin spawn is call-site gated.** A reverse-proxied OmniRoute dashboard (docker + nginx) could never validate ANY provider key: `POST /api/providers/validate` returned 403 LOCAL_ONLY for every request arriving through the proxy hop, and the Add API Key "Check" button rendered that as a bare red "Invalid" badge — the object-shaped `{code:"LOCAL_ONLY",message}` error body was silently swallowed by the modal (it only rendered string errors). The blanket LOCAL_ONLY pattern came from #15242 (audit #15159 S-01) to cover the only spawn reachable from these routes — the devin CLI-key fallback validator (webProvidersB.ts, fixed binary + argv). #15766 later established the precise pattern for exactly this class (gate the spawn at its call site on the trusted peer-locality header, the `/api/providers/[id]/models` cursor precedent) and threaded `allowLocalSpawn` into the test/create/test-batch routes, but the blunt regex stayed and kept every remote dashboard locked out. Now: the pattern is dropped; validate/bulk/import thread `allowLocalSpawn: getRequestPeerLocality(request) !== "remote"` into `validateProviderApiKey` (#15766 shape) so a remote peer still cannot reach the devin CLI-spawn fallback; and `validationErrorMessage()` renders `{code,message}` envelopes so a pipeline rejection can never masquerade as a key rejection again. Discovered live on a docker/nginx v3.8.52 deployment: a TokenRouter key that returns 200 OK from `api.tokenrouter.com/v1/models` showed as "Invalid" through the proxy and validated fine once the gate moved.
