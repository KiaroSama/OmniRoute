- **fix(api):** `/api/v1/registered-keys` (list, issue, fetch, revoke) is now a management-only surface like `/api/keys`: it takes a dashboard session, the local CLI token, or an API key with `manage`/`admin` scope, and refuses inference-only API keys with `403`. Before, the `/api/v1/` prefix routed these handlers through the inference-key check, so any active API key — whatever its scope — could list every registered provider key and revoke them all. Response shapes on the allowed path are unchanged; `docs/openapi.yaml` and `docs/reference/API_REFERENCE.md` now document the auth tier.
