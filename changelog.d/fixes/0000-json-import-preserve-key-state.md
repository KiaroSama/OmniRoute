- **fix(db):** restoring a settings JSON backup (`POST /api/settings/import-json`) no longer loses API key and provider connection state. The importer rewrote every key from only 8 columns, so revocation, expiry, ban, connection/combo allow-lists, scopes, IP allow-lists, rate limits and spend limits fell back to their defaults on restore; it now maps every column the backup carries from the live table schema, updates existing rows only with the columns the backup has, and only ever makes a key's lifecycle stricter (a key revoked, banned, expired or deactivated since the backup stays that way, and its stored secret is never replaced). Connection credentials now go through the same at-rest encryption as normal writes, and `max_concurrent`, `group`, proxy toggles and other later columns are restored instead of reset — thanks @xiaoyaner0201
