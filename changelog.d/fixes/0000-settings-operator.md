- **fix(security):** machine credentials can no longer take over the operator identity or weaken the login defenses through the settings routes. `POST /api/settings/require-login` is operator-only once a password exists (dashboard session, local CLI, or an instance with login disabled) — API keys of any scope and `oma_` access tokens get `403` — and a dashboard session must send `currentPassword` to replace the password; the local CLI keeps the recovery path and the first-run bootstrap window is unchanged. `PATCH /api/settings` refuses machine credentials on every security-policy key (`requireLogin`, `newPassword`, `oidc*`, `corsOrigins`, `bruteForceProtection`, the LOCAL_ONLY bypass list) even when they know the password, `oma_` tokens need the `admin` scope for any `/api/settings` mutation, and `corsOrigins` / `bruteForceProtection` now take the password re-auth and are dropped by the JSON import — the Security tab asks for the current password before changing them. Refusals are audited as `settings.update_failed` with `reason: OPERATOR_REQUIRED`.
