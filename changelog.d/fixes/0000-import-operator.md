- **fix(security):** restoring a backup now requires an operator credential, exactly like exporting one. `POST /api/db-backups/import` (uploaded `.sqlite`, `dryRun=true` included), `POST /api/db-backups` (restore a stored backup by id) and `POST /api/settings/import-json` (legacy JSON restore) accepted any `manage`-scoped API key, so a machine credential handed to automation could replace the live database or the whole settings/connections/API-key set irreversibly. The three routes now go through the same `requireOperatorCredential()` boundary as the exports: a signed-in dashboard session, the local CLI credential or an instance with login disabled pass; API keys of any scope and `oma_` access tokens get `403` with the live data untouched; a missing credential stays `401`. Listing, creating, retention and cleanup of backups keep ordinary management auth. `omniroute sync import` keeps working on the server host (it already sends the local CLI credential) and its 401/403 hint now names the operator rule instead of suggesting a `manage` key.
