- **fix(cli):** `omniroute sync import --dry-run` no longer replaces the live database. The command sent `?dryRun=true` to `POST /api/db-backups/import`, a flag the route never read, so a "dry run" overwrote the operator's data. The route now honours `dryRun` (query string or multipart field): it runs the same integrity and table checks and returns the row counts and schema version a real import would load, without the pre-import backup and without touching the live database. The CLI goes further and never contacts the server in dry-run mode (an older server would still ignore the flag): it validates the backup locally and prints the summary. A real import now goes through the local CLI credential, which the route accepts next to the dashboard session and `manage`-scoped API keys; JSON files such as the output of `sync bundle` are refused before upload, and 401/403/400 end in a readable error instead of a bare status.
