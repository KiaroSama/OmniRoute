> **അവസാനം അപ്ഡേറ്റ് ചെയ്തത്:** 2026-08-29 — v3.8.51 (വീഡിയോ ബ്രിഡ്ജ് ട്രാൻസ്ക്രിപ്റ്റ് പ്രൂവനെൻസ് കോളർ-പ്രഖ്യാപിച്ചതാണ്,
> ഇതുവരെ സെർവർ-പരിശോധിച്ചിട്ടില്ല — #11661 അനുസരിച്ച് വ്യക്തമാക്കിയത്)

OmniRoute-നും അപ്സ്ട്രീം പ്രൊവൈഡർമാർക്കും ഇടയിലുള്ള അതിർത്തിയിൽ സുരക്ഷ, നയം, ഉള്ളടക്ക പരിവർത്തനങ്ങൾ എന്നിവ ഗാർഡ്റെയിലുകൾ നടപ്പിലാക്കുന്നു. ഓരോ ഗാർഡ്റെയിലിനും അഭ്യർത്ഥന പേലോഡുകളും (`preCall`) അപ്സ്ട്രീം പ്രതികരണങ്ങളും (`postCall`) പരിശോധിക്കാൻ (ഓപ്ഷണലായി നിരസിക്കുകയോ, രൂപാന്തരപ്പെടുത്തുകയോ, വ്യാഖ്യാനിക്കുകയോ ചെയ്യാം) കഴിയും.

സിസ്റ്റം **ഫെയിൽ-ഓപ്പൺ** ആണ്: ഒരു ഗാർഡ്റെയിൽ പ്രവർത്തിക്കുമ്പോൾ പിശക് സംഭവിച്ചാൽ, രജിസ്ട്രി പിശക് രേഖപ്പെടുത്തുകയും അഭ്യർത്ഥന പരാജയപ്പെടുത്തുന്നതിന് പകരം അടുത്ത ഗാർഡ്റെയിലുമായി മുന്നോട്ട് പോകുകയും ചെയ്യുന്നു. തടയുന്നത് ഒരു വ്യക്തമായ തീരുമാനമാണ് (`block: true`), ഒരിക്കലും ഒരു അപകടമല്ല.

## ബിൽറ്റ്-ഇൻ ഗാർഡ്റെയിലുകൾ

ഇമ്പോർട്ട് ചെയ്യുമ്പോൾ രജിസ്ട്രി മുൻഗണനാക്രമത്തിൽ ആറ് ഗാർഡ്റെയിലുകൾ സ്വയമേവ ലോഡ് ചെയ്യുന്നു
(`registry.ts` → `registerDefaultGuardrails()` കാണുക):

| മുൻഗണന | പേര്                | ഘട്ടം(ങ്ങൾ)    | ഫയൽ                   |
| ------ | ------------------- | -------------- | --------------------- |
| `5`    | `vision-bridge`     | `preCall`      | `visionBridge.ts`     |
| `6`    | `audio-bridge`      | `preCall`      | `audioBridge.ts`      |
| `7`    | `video-bridge`      | `preCall`      | `videoBridge.ts`      |
| `10`   | `pii-masker`        | `pre` + `post` | `piiMasker.ts`        |
| `20`   | `prompt-injection`  | `preCall`      | `promptInjection.ts`  |
| `95`   | `credential-masker` | `pre` + `post` | `credentialMasker.ts` |

കുറഞ്ഞ മുൻഗണനാ നമ്പറുകളുള്ളവ **ആദ്യം** പ്രവർത്തിക്കുന്നു.

### വിഷൻ ബ്രിഡ്ജ് (`visionBridge.ts`) — മോഡാലിറ്റി ബ്രിഡ്ജ് PR-1

**വിഷൻ പിന്തുണയില്ലാത്ത മോഡലുകളെ** ലക്ഷ്യമിടുന്ന, ചിത്രങ്ങൾ ഉൾക്കൊള്ളുന്ന അഭ്യർത്ഥനകളെ തടഞ്ഞുപിടിച്ച്, മുഴുവൻ അഭ്യർത്ഥനയും വിഷൻ പിന്തുണയുള്ള ഒരു മോഡലിലേക്ക് തിരിച്ചുവിടുകയോ, അപ്സ്ട്രീം കോൾ നടത്തുന്നതിന് മുമ്പ് ക്രമീകരിക്കാവുന്ന ഒരു വിഷൻ മോഡൽ സൃഷ്ടിക്കുന്ന ടെക്സ്റ്റ് വിവരണങ്ങൾകൊണ്ട് ചിത്രഭാഗങ്ങൾ മാറ്റിസ്ഥാപിക്കുകയോ ചെയ്യുന്നു. ഇതിലൂടെ ടെക്സ്റ്റ് മാത്രം പിന്തുണയ്ക്കുന്ന പ്രൊവൈഡർമാർക്ക് മൾട്ടിമോഡൽ പേലോഡുകൾ സുതാര്യമായി കൈകാര്യം ചെയ്യാനാകും.

പ്രവാഹം:

1. ലക്ഷ്യ മോഡൽ ഇതിനകം വിഷൻ പിന്തുണയ്ക്കുന്നുണ്ടെങ്കിൽ ഒഴിവാക്കുക (`isVisionBridgeForcedModel` നിർബന്ധിത-ബ്രിഡ്ജ് പട്ടികയിൽ അത് ഉൾപ്പെട്ടിട്ടില്ലെങ്കിൽ).
2. `extractImageParts(messages)` ഉപയോഗിച്ച് ചിത്രഭാഗങ്ങൾ എക്സ്ട്രാക്റ്റ് ചെയ്യുക
   (`visionBridgeHelpers.ts`); ഇത് `open-sse/utils/mediaParts.ts`-ലെ
   **ഏകീകൃത മീഡിയ ഡിറ്റക്ടർ** `detectMediaParts()`-ലേക്ക് ചുമതല കൈമാറുന്നു — കോംബോ കോംപാറ്റിബിലിറ്റി ഫിൽട്ടറുമായി പങ്കിടുന്ന ഏക ആധികാരിക ഉറവിടമാണിത്.
   `replaceImageParts`-ന് തിരികെ ചേർക്കാൻ കഴിയുന്ന രൂപങ്ങളിലുള്ള ടോപ്പ്-ലെവൽ ഭാഗങ്ങൾ മാത്രമേ എക്സ്ട്രാക്ഷൻ അനുവദിക്കൂ (എക്സ്ട്രാക്റ്റ്↔റീപ്ലേസ് കരാർ): OpenAI
   `image_url`, Anthropic base64 `source.type:"base64"`, Anthropic URL
   `source.type:"url"`, Responses API `input_image`. നെസ്റ്റഡ് പൊരുത്തങ്ങളും
   ഇൻഡിക്കേറ്റർ മാത്രമുള്ള രൂപങ്ങളും കോംബോ-ഫിൽട്ടറിനുള്ളവയാണ്; അവ ഒരിക്കലും എക്സ്ട്രാക്റ്റ് ചെയ്യില്ല.
   ഒന്നും കണ്ടെത്തിയില്ലെങ്കിൽ ഒഴിവാക്കുക.
3. `resolveVisionBridgeRuntimeSettings()` വഴി റൺടൈം കോൺഫിഗ് കണ്ടെത്തുക
   (`src/shared/constants/modalityBridgeDefaults.ts`): പുതിയ `modalityBridge*`
   ക്രമീകരണ കീകൾക്ക് മുൻഗണന ലഭിക്കും; പഴയ `visionBridge*` കീകൾ **ഒരു സൈക്കിൾ മാത്രം നീളുന്ന
   ഫാൾബാക്കായി** തുടരും (റോൾബാക്ക് കാലയളവ്). ബ്രിഡ്ജ് പ്രവർത്തനരഹിതമാണെങ്കിൽ ഏതെങ്കിലും മീഡിയ ട്രാവേഴ്സലിനു മുമ്പ് ഒഴിവാക്കുക.
4. മോഡ് സെലക്ടർ (`modalityBridgeVisionMode`, താഴെയുള്ള പട്ടിക കാണുക)
   റീറൂട്ട് വേണോ വിവരിക്കണോ എന്ന് തീരുമാനിക്കുന്നു. റീറൂട്ട് ചെയ്യുമ്പോൾ `model`
   മാത്രം മാറ്റിയ `modifiedPayload`, കൂടാതെ `{ rerouted, fromModel, toModel, imagesKept }` മെറ്റാ എന്നിവ മടക്കിനൽകുന്നു.
5. വിവരണ പാത: ചിത്രങ്ങളുടെ എണ്ണം `maxImages` ആയി പരിമിതപ്പെടുത്തുക, ടാസ്ക്-അവെയർ പ്രോംപ്റ്റ് തയ്യാറാക്കുക,
   വിവരണ കാഷ് പരിശോധിക്കുക, വിഷൻ മോഡലിനെ **സമാന്തരമായി**
   (`Promise.allSettled`) വിളിക്കുക, തുടർന്ന് ചിത്രങ്ങളുടെ സ്ഥാനത്ത് `[Image N]: <description>` ടെക്സ്റ്റ് ഭാഗങ്ങൾ ചേർക്കുക.
   വിവരണം പരാജയപ്പെട്ടാൽ `null` ലഭിക്കുകയും യഥാർത്ഥ ചിത്രഭാഗം
   **നിലനിർത്തുകയും** ചെയ്യും (#4012) — എന്നാൽ കോംബോ വിവരണ പാതയിൽ എല്ലാ
   വിവരണങ്ങളും പരാജയപ്പെടുകയും അപ്സ്ട്രീം വിഷൻ പിന്തുണയ്ക്കുന്നില്ലെന്ന് സ്ഥിരീകരിക്കുകയും ചെയ്താൽ,
   പകരം `(ലഭ്യമല്ല — വിഷൻ പിന്തുണയുള്ള ഒരു പ്രൊവൈഡറും കണക്റ്റ് ചെയ്തിട്ടില്ല)` എന്ന സ്റ്റബ് ഉപയോഗിക്കും (#8430).
6. `modifiedPayload` + മെറ്റാ (`imagesProcessed`, `descriptions`,
   `processingTimeMs`, `visionModel`) മടക്കിനൽകുക.

| `auto`     | ✔         | മാറ്റമില്ലാത്ത പഴയ ഹ്യൂറിസ്റ്റിക് (#6640/#7204): യഥാർത്ഥ മോഡലിന് ഇതിനകം ഉപയോഗയോഗ്യമായ ക്രെഡൻഷ്യലുകൾ ഇല്ലെങ്കിൽ, നോൺ-കോംബോ/`auto/` മോഡലുകൾ മികച്ച വിഷൻ മോഡലിലേക്ക് റീറൂട്ട് ചെയ്യും (അവ ഉണ്ടെങ്കിൽ വിവരിക്കും); കോംബോ ലക്ഷ്യങ്ങൾ എല്ലായ്പ്പോഴും വിവരിക്കും.                                                                      |

| `reroute`  |           | റീറൂട്ട് നിർബന്ധിക്കുക: ക്രെഡൻഷ്യലുകളുള്ള മോഡൽ നിലനിർത്തുന്നതിനുള്ള ഗാർഡ് മറികടക്കപ്പെടും. റീറൂട്ട്-**ടാർഗറ്റ്** ക്രെഡൻഷ്യൽ ഗാർഡ് തുടർന്നും ബാധകമാണ് — ഉപയോഗയോഗ്യമായ വിഷൻ ടാർഗറ്റ് ഒന്നും ഇല്ലെങ്കിൽ, അസംസ്കൃത ചിത്രങ്ങൾ ടെക്സ്റ്റ് മാത്രമുള്ള ബാക്കെൻഡിൽ ഒരിക്കലും എത്താതിരിക്കാൻ അഭ്യർത്ഥന വിവരണ പാതയിലേക്ക് നീങ്ങും (#8430). |

`auto` ഹ്യൂറിസ്റ്റിക് പ്രവർത്തിക്കുന്നതിന് **മുമ്പ്** തന്നെ നിർബന്ധിത മോഡുകൾ ഷോർട്ട്-സർക്യൂട്ട് ചെയ്യും; `auto` പെരുമാറ്റം
PR-1-ന് മുമ്പുള്ള ഗാർഡ്റെയിലുമായി ബൈറ്റ് തലത്തിൽ അതേപടി നിലനിൽക്കുന്നു.

#### API-കീ സ്കോപ്പ് (`visionBridgeKeyScope.ts`)

കോളറുടെ API കീ `allowedConnections`, ക്വോട്ട പൂളുകൾ
(`allowedQuotas`) അല്ലെങ്കിൽ മോഡലുകൾ (`allowedModels` / `blockedModels` /
`modelAccessMode: "restricted"` / `disableNonPublicModels`) നിയന്ത്രിക്കുമ്പോൾ, ആ കീയ്ക്ക് ഉപയോഗിക്കാവുന്ന കണക്ഷനുകളിൽ, കീയ്ക്ക് ഉപയോഗിക്കാൻ അനുമതിയുള്ള റീറൂട്ട്, വിവരണ മോഡലുകൾ മാത്രമേ ബ്രിഡ്ജ് തിരഞ്ഞെടുക്കൂ.
തുടർന്ന് വിവരണ കോൾ എല്ലായ്പ്പോഴും `x-omniroute-self-loop-key-id` ഹെഡറോടുകൂടിയ OmniRoute സെൽഫ്-ലൂപ്പിലൂടെ കടന്നുപോകുന്നതിനാൽ, സ്വീകരിക്കുന്ന ചാറ്റ് അഭ്യർത്ഥന ആ കീയുടെ കണക്ഷൻ, മോഡൽ നയം വീണ്ടും നടപ്പിലാക്കുന്നു. `enforceApiKeyPolicy()`
ആ ഹെഡറിനെ സെൽഫ്-ലൂപ്പ് ബെയററിനൊപ്പം മാത്രമേ അംഗീകരിക്കൂ; അതിനാൽ അതിന് ആക്സസ് കൂടുതൽ പരിമിതപ്പെടുത്താൻ മാത്രമേ കഴിയൂ, കൂടാതെ പരിഹരിക്കാൻ കഴിയാത്ത ഒരു id നിരസിക്കപ്പെടും.

കീയ്ക്കായി ഒരു വിഷൻ മോഡലിനും അനുമതിയില്ലെങ്കിൽ, വിവരണ പാത മാറിനിൽക്കുകയും
അഭ്യർത്ഥന മാറ്റമില്ലാതെ കടന്നുപോകുകയും ചെയ്യും; ഇത് പ്രവർത്തനരഹിതമായ ഒരു
ഗാർഡ്റെയിലിന്റെ അതേ ഫെയിൽ-ഓപ്പൺ പെരുമാറ്റമാണ് (മെറ്റാ `{ skipped: true, reason: "no_permitted_vision_model" }`).
കീ ഇല്ലാത്ത അഭ്യർത്ഥനകളും ഈ നിയന്ത്രണങ്ങളില്ലാത്ത കീകളും മുമ്പത്തെപ്പോലെ തന്നെയാണ് പ്രവർത്തിക്കുന്നത്.

#### ടാസ്ക്-അവെയർ വിവരണ പ്രോംപ്റ്റ് (`modalityBridgeVisionTaskAware`)

സ്ഥിരസ്ഥിതി **true** ആണ്. `composeVisionPrompt()` (`visionBridgeHelpers.ts`) അടിസ്ഥാന
വിവരണ പ്രോംപ്റ്റിലേക്ക് **അവസാന ഉപയോക്തൃ സന്ദേശത്തിന്റെ** ടെക്സ്റ്റ് (500 അക്ഷരങ്ങളായി
ചുരുക്കിയത്) ചേർക്കുന്നു; ഇതിലൂടെ ഉപയോക്താവ് യഥാർത്ഥത്തിൽ ചോദിച്ചതിലേക്ക് വിവരണം
നയിക്കുകയും (codex-vision-proxy മാതൃക) ദൃശ്യമാകുന്ന ടെക്സ്റ്റ് പകർത്തിയെഴുതാൻ വിഷൻ
മോഡലിനോട് ആവശ്യപ്പെടുകയും ചെയ്യുന്നു. ഫ്ലാഗ് ഓഫായിരിക്കുമ്പോൾ — അല്ലെങ്കിൽ ഉപയോക്തൃ
ടെക്സ്റ്റ് ഇല്ലെങ്കിൽ — അടിസ്ഥാന പ്രോംപ്റ്റ് മാറ്റമില്ലാതെ ഉപയോഗിക്കുന്നു.

ഡിസ്ക്രൈബ് സെൽഫ്-ലൂപ്പിന്റെ സ്വന്തം OpenAI-അനുയോജ്യ അഭ്യർത്ഥന
(`visionBridgeHelpers.ts`-ലെ `callVisionModelSingle()`) എല്ലായ്പ്പോഴും
`image_url.detail: "high"` അഭ്യർത്ഥിക്കുന്നു — ഓരോ കോളർ/പ്രൊവൈഡറിനും, യാതൊരു ക്ലയന്റ്
സിഗ്നലിനെയും ആശ്രയിക്കാതെ. ഈ പ്രോംപ്റ്റ് ആവശ്യപ്പെടുന്ന ടെക്സ്റ്റ്-ട്രാൻസ്ക്രിപ്ഷൻ
ടാസ്കിന് ലോ-ഡീറ്റെയിൽ സാംപ്ലിങ് OCR കൃത്യത കുറയ്ക്കുന്നതിനാൽ, യഥാർത്ഥ ഇൻബൗണ്ട്
അഭ്യർത്ഥന ഏത് ഡീറ്റെയിൽ ലെവൽ ഉപയോഗിച്ചാലും ഡിസ്ക്രൈബ് കോൾ എല്ലായ്പ്പോഴും ഉയർന്ന
ഡീറ്റെയിൽ ആവശ്യപ്പെടുന്നു. ഇത് ആന്തരിക ഡിസ്ക്രൈബ് അഭ്യർത്ഥന ബോഡിയെ മാത്രമേ
ബാധിക്കൂ; പ്രാഥമിക അഭ്യർത്ഥനയിൽ കോളറുടെ സ്വന്തം `image_url.detail` OmniRoute
ഫോർവേഡ് ചെയ്യുന്ന രീതിയെ ഇത് മാറ്റുന്നില്ല — ആ സ്ഥിരസ്ഥിതി പ്രത്യേകം പ്രയോഗിക്കുന്നു,
അതും കണ്ടെത്തിയ OpenCode ക്ലയന്റുകൾക്ക് മാത്രം,
`defaultImageDetail()` (`open-sse/handlers/chatCore/upstreamBody.ts`)-ൽ. ഡിസ്ക്രൈബ്
സെൽഫ്-ലൂപ്പിന്റെ Anthropic വയർ-ഫോർമാറ്റ് ബ്രാഞ്ചിന് `detail` ഫീൽഡ് ഇല്ലാത്തതിനാൽ
ഒരു സ്ഥിരസ്ഥിതിയും അതിനെ ബാധിക്കില്ല.

#### ഡിസ്ക്രൈബ് ഔട്ട്പുട്ട് പരിധി (`modalityBridgeVisionMaxChars`)

| കീ                             | സ്ഥിരസ്ഥിതി | പരിധി                    |
| ------------------------------ | ----------- | ------------------------ |
| `modalityBridgeVisionMaxChars` | `0`         | `0` അല്ലെങ്കിൽ 100–50000 |

`0` (സ്ഥിരസ്ഥിതി) എന്നാൽ **പരിധിയില്ല** എന്നാണ് — `callVisionModel()` നൽകുന്ന
വിവരണം മാറ്റമില്ലാതെ കടത്തിവിടുകയും നിലവിലുള്ള പെരുമാറ്റം നിലനിർത്തുകയും ചെയ്യുന്നു.
100–50000 പരിധിയിലുള്ള ഏത് മൂല്യവും വിവരണം `[Image N]: <description>` ആയി തിരികെ
ചേർക്കുന്നതിന് മുമ്പ് `…` സഫിക്സ് ഉപയോഗിച്ച് ചുരുക്കുന്നു
(`src/lib/guardrails/visionBridge.ts`-ലെ `VisionBridgeGuardrail.preCall()`).
ഡൗൺസ്ട്രീം മോഡലിന് പൂർണ്ണ ട്രാൻസ്ക്രിപ്ഷൻ ആവശ്യമായ, ധാരാളം വിശദാംശങ്ങളുള്ള OCR
ടാസ്കുകൾക്കായി ഇത് ഉയർത്തുക; അമിതമായി പ്രതികരിക്കുന്ന വിഷൻ മോഡലുകളുടെ ടോക്കൺ
ഉപയോഗം പരിമിതപ്പെടുത്താൻ ഇത് കുറയ്ക്കുക. ഡാഷ്ബോർഡ് ഫീൽഡ് Vision ടാബിലെ Advanced
പാനലിലാണ് (`ModalityBridgeVisionTab.tsx`-ലെ `modality-bridge-max-chars`); വ്യക്തമായി
നൽകിയ `0` മാറ്റാതെ നിലനിർത്തിക്കൊണ്ട്, 1-നും 99-നും ഇടയിലുള്ള ഏത് മൂല്യവും ഇത്
കുറഞ്ഞ പരിധിയായ 100-ലേക്ക് ഉയർത്തുന്നു — `0` എന്നത് വെറും "സജ്ജീകരിക്കാത്ത"
സ്ഥിരസ്ഥിതിയല്ല, അതിന്റേതായ സാധുവായ Zod മൂല്യമാണ്
(`z.union([z.literal(0), z.number().int().min(100).max(50000)])`).

#### ഡിസ്ക്രൈബ് കാഷ് (`modalityBridge/bridgeCache.ts`)

ഡിസ്ക്രൈബ് ഔട്ട്പുട്ടുകൾക്കായുള്ള ഇൻ-മെമ്മറി LRU + TTL കാഷ്, പ്രോസസ് മുഴുവൻ
പങ്കിടുന്നു. കീ = `sha256(imageRef + composedPrompt + configuredBridgeModel)`,
ലെങ്ത്-പ്രിഫിക്സ് ഫ്രെയിമിങ്ങോടുകൂടി (ഫീൽഡ്-ബൗണ്ടറി കൂട്ടിയിടികളില്ല). മോഡൽ ഘടകം
**കോൺഫിഗർ ചെയ്ത** ബ്രിഡ്ജ് മോഡലാണ്, യഥാർത്ഥത്തിൽ മറുപടി നൽകിയ മോഡലല്ല —
`callVisionModel` ആന്തരികമായി ഫാൾബാക്ക് ചെയ്തേക്കാം; ഓരോ ശ്രമത്തിനും പ്രത്യേകം കീ
നൽകുന്നത് കാഷിനെ വിഘടിപ്പിക്കും. പരാജയപ്പെട്ട ഡിസ്ക്രൈബുകൾ ഒരിക്കലും കാഷ്
ചെയ്യില്ല. ക്രമീകരണങ്ങൾ:

| കീ                              | സ്ഥിരസ്ഥിതി | പരിധി   |
| ------------------------------- | ----------- | ------- |
| `modalityBridgeCacheEnabled`    | `true`      | —       |
| `modalityBridgeCacheTtlMinutes` | `60`        | 1–1440  |
| `modalityBridgeCacheMaxEntries` | `200`       | 10–5000 |

#### റിമോട്ട് ഇമേജ് നോർമലൈസേഷൻ (സെൽഫ്-ലൂപ്പ് ഡിസ്ക്രൈബ്/base64 ഫെച്ച്)

ബ്രിഡ്ജ് സ്വയം ഒരു **റിമോട്ട്** ഇമേജ് ഫെച്ച് ചെയ്യുമ്പോൾ — Anthropic ഡിസ്ക്രൈബ്
സെൽഫ്-കോളും claude-wire-format base64 പരിവർത്തനവും
(`ensureBase64ImagesForClaudeWire`), ഇവ രണ്ടും `visionBridgeHelpers.ts`-ലെ
`fetchRemoteImageAsDataUri()` വഴിയാണ് — ലഭിക്കുന്ന ഡാറ്റ URI, വിഷൻ-മോഡൽ
അഭ്യർത്ഥനയിൽ എംബെഡ് ചെയ്യുന്നതിന് മുമ്പ് `normalizeDataUri()`
(`open-sse/utils/imageNormalize.ts`) വഴി കടത്തിവിടുന്നു. അതിവലുപ്പമുള്ള ഇമേജുകൾ
**2048px നീളമുള്ള വശത്തിലേക്ക്** ഡൗൺസ്കെയിൽ ചെയ്യുന്നു (OpenAI/Anthropic ഇതിനകം
സെർവർ-സൈഡിൽ പ്രയോഗിക്കുന്ന റീസൈസ് പരിധിയുമായി പൊരുത്തപ്പെടുന്നു); വിഷൻ മോഡൽ
കാണുന്നതിൽ മാറ്റം വരുത്താതെ ഇത് അപ്ലോഡ് ബൈറ്റുകൾ/ലേറ്റൻസി കുറയ്ക്കുന്നു.

1. `getResolvedModelCapabilities()` വഴി `supportsAudio` പരിഹരിക്കുക. വ്യക്തമായി നൽകിയ
   പ്രൊവൈഡർ-രജിസ്ട്രി മെറ്റാഡാറ്റയ്ക്ക് മുൻഗണന ലഭിക്കുന്നു; തുടർന്ന് സ്റ്റാറ്റിക് മോഡൽ മെറ്റാഡാറ്റയ്ക്കും, അതിനുശേഷം
   സിങ്ക് ചെയ്ത `modalities_input`-നും. `audio` ഇല്ലാത്തതായി പ്രഖ്യാപിച്ച ഇൻപുട്ട് ലിസ്റ്റ് `false` ആണ്;
   ശേഷി സംബന്ധിച്ച തെളിവുകളൊന്നുമില്ലെങ്കിൽ `null` ആയി തുടരുന്നു. `false`, `null` എന്നിവ രണ്ടും
   കൺസർവേറ്റീവ് ബ്രിഡ്ജ് സജീവമാക്കുന്നു; `true` അതിനെ ബൈപാസ് ചെയ്യുന്നു.
2. `modalityBridgeAudio*` ക്രമീകരണങ്ങൾ പരിഹരിച്ച്, പങ്കിട്ട `detectMediaParts()`
   ഡിറ്റക്ടർ വഴി ഓരോ സന്ദേശത്തിൽനിന്നും സ്പ്ലൈസ് ചെയ്യാവുന്ന ടോപ്പ്-ലെവൽ ഓഡിയോ ഭാഗങ്ങൾ എക്സ്ട്രാക്റ്റ് ചെയ്യുക.
   പിന്തുണയ്ക്കുന്ന വയർ രൂപങ്ങൾ OpenAI `input_audio`, `audio_url`,
   `source.media_type: "audio/*"` എന്നിവയാണ്. നെസ്റ്റഡ് ഓഡിയോ റൂട്ടിംഗിനായി കണ്ടെത്തപ്പെടുന്നു, എന്നാൽ
   സ്പ്ലൈസ് പാത അതിനെ നീക്കം ചെയ്യുന്നില്ല. പ്രവർത്തനത്തിന്റെ പരിധി `modalityBridgeAudioMaxClips`
   നിർണ്ണയിക്കുന്നു; തുടർന്നുള്ള ഭാഗങ്ങൾ മാറ്റമില്ലാതെ തുടരുന്നു.
3. കോൺഫിഗർ ചെയ്ത `provider/model` മാനിക്കുക, അല്ലെങ്കിൽ സ്ഥിരതയുള്ള കാറ്റലോഗ് ക്രമത്തിൽ
   `AUDIO_TRANSCRIPTION_PROVIDERS` പരിശോധിച്ച് ഉപയോഗയോഗ്യമായ സജീവ പ്രൊവൈഡർ ക്രെഡൻഷ്യലുള്ള
   ആദ്യ മോഡൽ തിരഞ്ഞെടുക്കാൻ `selectAudioBridgeModel()`-നെ അനുവദിക്കുക.
4. `callAudioTranscription()` base64/data-URI ഓഡിയോയെ ഒരു മൾട്ടിപാർട്ട്
   `file` ആക്കി മാറ്റുന്നു, അല്ലെങ്കിൽ DNS പിന്നിംഗും 25 MB പരിധിയുമുള്ള പബ്ലിക്-ഒൺലി ഔട്ട്ബൗണ്ട്
   ഗാർഡിലൂടെ ഒരു റിമോട്ട് `audio_url` ഡൗൺലോഡ് ചെയ്യുന്നു. തുടർന്ന് അത് ഫയലും തിരഞ്ഞെടുത്ത
   മോഡലും ലോക്കൽ `/v1/audio/transcriptions` സെൽഫ്-ലൂപ്പിലേക്ക് POST ചെയ്യുന്നു,
   `resolveSelfLoopBearer()` ഉപയോഗിച്ച് ഓതന്റിക്കേറ്റ് ചെയ്തുകൊണ്ട്. നിലവിലുള്ള ട്രാൻസ്ക്രിപ്ഷൻ റൂട്ട് സാധാരണ
   ക്രെഡൻഷ്യൽ ലുക്കപ്പ്, കൂൾഡൗൺ/റേറ്റ്-ലിമിറ്റ് കൈകാര്യം ചെയ്യൽ, പ്രൊവൈഡർ ഡിസ്പാച്ച് എന്നിവ നിർവഹിക്കുന്നു.
5. വിജയകരമായ കോളുകൾ അവയുടെ ഭാഗങ്ങളെ `[Audio N]: <transcript>` ഉപയോഗിച്ച് മാറ്റിസ്ഥാപിക്കുന്നു. കോളുകൾ
   `Promise.allSettled` ഉപയോഗിച്ച് പ്രവർത്തിക്കുന്നു: ഒരു വ്യക്തിഗത പരാജയം ആ യഥാർത്ഥ
   ഓഡിയോ ഭാഗം നിലനിർത്തുന്നു (#4012 കരാർ). എല്ലാ കോളുകളും പരാജയപ്പെടുകയും ടാർഗറ്റ്
   `supportsAudio === false` ആണെന്ന് തെളിയിക്കപ്പെടുകയും ചെയ്താൽ, ഭാഗങ്ങൾ
   `[Audio N]: (ലഭ്യമല്ല — STT പ്രൊവൈഡറൊന്നും ബന്ധിപ്പിച്ചിട്ടില്ല)` ആയി മാറുന്നു (#8430 കരാർ). ഒരു
   അജ്ഞാത ടാർഗറ്റിനായി (`null`), എല്ലാം പരാജയപ്പെട്ട ഫലം മാറ്റമില്ലാതെ തുടരുന്നു. ഉപയോഗയോഗ്യമായ
   STT ക്രെഡൻഷ്യൽ ഇല്ലാത്ത, ടെക്സ്റ്റ്-മാത്രമാണെന്ന് തെളിയിക്കപ്പെട്ട ടാർഗറ്റിന് നെറ്റ്വർക്ക് കോൾ നടത്താതെ
   അതേ വ്യക്തമായ സ്റ്റബ് ലഭിക്കുന്നു.

വിജയകരമായ ട്രാൻസ്ക്രിപ്റ്റുകൾ പ്രോസസ്-വ്യാപകമായ Modality Bridge LRU/TTL കാഷ് ഉപയോഗിക്കുന്നു.
കീയിൽ ഓഡിയോ റഫറൻസ്, സ്ഥിരമായ `audio-transcription` ഓപ്പറേഷൻ
ലേബൽ, തിരഞ്ഞെടുത്ത STT മോഡൽ എന്നിവ സംയോജിപ്പിക്കുന്നു; പരാജയങ്ങൾ ഒരിക്കലും കാഷ് ചെയ്യപ്പെടുന്നില്ല. ഓഡിയോ ശ്രമങ്ങൾ
പങ്കിട്ട `bridged`, `cacheHits`, `failures`, `lastUsedAt` കൗണ്ടറുകൾ അപ്ഡേറ്റ് ചെയ്യുന്നു.
പരിവർത്തനം ചെയ്ത പ്രതികരണങ്ങൾ
`x-omniroute-modality-bridge: audio->text;model=<sttModel>;parts=<n>` ഉൾക്കൊള്ളുന്നു; മാറ്റമില്ലാത്ത
അഭ്യർത്ഥനകൾക്ക് Audio Bridge സെഗ്മെന്റ് ലഭിക്കില്ല.

റൺടൈം ക്രമീകരണങ്ങൾ DB-ബാക്ക്ഡ് ആയതും Zod ഉപയോഗിച്ച് വാലിഡേറ്റ് ചെയ്തതുമാണ്:

| കീ                            | ഡിഫോൾട്ട് | പരിധി                  |
| ----------------------------- | --------- | ---------------------- |
| `modalityBridgeAudioEnabled`  | `true`    | —                      |
| `modalityBridgeAudioModel`    | `""`      | Auto അല്ലെങ്കിൽ STT ID |
| `modalityBridgeAudioTimeout`  | `60000`   | 1000–300000            |
| `modalityBridgeAudioMaxClips` | `3`       | 1–10                   |

പങ്കിട്ട കാഷ് ഇപ്പോഴും `modalityBridgeCacheEnabled`,
`modalityBridgeCacheTtlMinutes`, `modalityBridgeCacheMaxEntries` എന്നിവയാൽ നിയന്ത്രിക്കപ്പെടുന്നു.

### വീഡിയോ ബ്രിഡ്ജ് (`videoBridge.ts`, `videoBridgePipeline.ts`)

നേറ്റീവ് വീഡിയോ പിന്തുണയുള്ളതായി അറിയപ്പെടാത്ത ഒരു ടാർഗെറ്റ് വിളിക്കപ്പെടുന്നതിന് മുമ്പ്, Chat Completions `messages`, Responses
API `input` എന്നിവയിലെ ടോപ്പ്-ലെവൽ വീഡിയോ ഭാഗങ്ങൾ ഇന്റർസെപ്റ്റ് ചെയ്യുന്നു.
പിന്തുണയ്ക്കുന്ന രൂപങ്ങൾ `input_video`, `video_url`, `video_source`, HTTPS URL-കൾ,
`data:video/*;base64,...` ഡാറ്റ URI-കൾ എന്നിവയാണ്. ടെക്സ്റ്റിലുള്ള പ്ലെയിൻ ഫയൽനാമങ്ങൾ വീഡിയോയായി പരിഗണിക്കപ്പെടുന്നില്ല.

`VideoBridgeGuardrail.preCall` (`videoBridge.ts`) റിക്വസ്റ്റ് ട്രാവേഴ്സൽ,
കപ്പബിലിറ്റി/പോളിസി പരിശോധന, ഓരോ റിക്വസ്റ്റിലെയും അഗ്രിഗേഷൻ, റെസ്പോൺസ് പേലോഡ് എന്നിവ കൈകാര്യം ചെയ്യുന്നു.
ഓരോ വീഡിയോയ്ക്കുമുള്ള പ്രവർത്തനം — അക്വിസിഷൻ, പൂർണ്ണ-ഫല കാഷ്, ഫ്രെയിം
സീക്വൻസിന്റെ വിവരണം (കോളർ പ്രഖ്യാപിച്ചിട്ടുള്ള ഏതൊരു ഓഡിയോ ട്രാൻസ്ക്രിപ്റ്റും ഇതിൽ സംയോജിപ്പിക്കുന്നു), ഓരോ ശ്രമത്തിനുമുള്ള
മെട്രിക്സ്/അബോർട്ട്/ക്ലീനപ്പ് എന്നിവ — `videoBridgePipeline.ts`-ലെ
`processVideoPart`-ന്റെ പിന്നിൽ മറച്ചിരിക്കുന്നു; `preCall`-ന്റെ ലൂപ്പിനുള്ളിൽ ഓരോ വീഡിയോ ഭാഗത്തിനും ഇത് ഒരിക്കൽ വിളിക്കപ്പെടുന്നു.
ആ മൊഡ്യൂൾ വ്യക്തമായ പോർട്ട് അതിരുകളായ `VideoMediaBrokerPort`
(ബൈറ്റുകൾ നേടുകയും സാമ്പിൾ ചെയ്ത ഫ്രെയിമുകൾ എക്സ്ട്രാക്റ്റ് ചെയ്യുകയും ചെയ്യുന്നത്), `VideoAudioTranscriptionPort`
(കോളർ പ്രഖ്യാപിച്ച ഓഡിയോ ട്രാൻസ്ക്രിപ്റ്റിനെ സാമ്പിൾ ചെയ്ത ക്യാപ്ഷനുകളുമായി സംയോജിപ്പിക്കുന്നത്),
`VideoDrilldownPort` (ഫ്രെയിം ഡ്രിൽ-ഡൗൺ പെർസിസ്റ്റൻസ് അതിര്; ഇത് ഇതുവരെ
`processVideoPart`-ലേക്ക് ബന്ധിപ്പിച്ചിട്ടില്ല — നിലവിൽ വേറിട്ട `/api/modality-bridge/video/drilldown`
റൂട്ട് മാത്രമാണ് ഡ്രിൽ-ഡൗൺ എൻട്രികൾ എഴുതുന്നത്) എന്നിവയും നിർവചിക്കുന്നു.

പബ്ലിക് `/v1` റിക്വസ്റ്റ് പാത്ത് ഒരിക്കലും ഒരു സബ്പ്രോസസ് ഇംപോർട്ട് ചെയ്യുകയോ ഇൻവോക്ക് ചെയ്യുകയോ ഇല്ല. റിമോട്ട്
വീഡിയോകൾ 50 MiB പരിധിക്കുള്ളിൽ ഡൗൺലോഡ് ചെയ്യപ്പെടുന്നു; മോഡൽ/മെസേജുകൾ/ഫ്രെയ്മിംഗ് എൻവലപ്പ്
50 MiB എന്ന പബ്ലിക് JSON റിക്വസ്റ്റ് അഡ്മിഷൻ പരിധിക്കുള്ളിൽ നിലനിർത്താൻ, ഇൻലൈൻ base64 വീഡിയോകൾക്ക്
ഓരോ വീഡിയോയ്ക്കും കൺസർവേറ്റീവ് ആയ 36 MiB ഡീകോഡ് ചെയ്ത പരിധിയുണ്ട്. അലോക്കേഷനുമുമ്പ് ഇൻലൈൻ
ദൈർഘ്യവും ഡീകോഡ് ചെയ്ത വലുപ്പത്തിന്റെ എസ്റ്റിമേറ്റുകളും പരിശോധിക്കുന്നു. പ്രാരംഭ റിമോട്ട് URL-ലും ഓരോ റീഡയറക്റ്റിലും
HTTPS നിർബന്ധമാണ്; ഇതിനായി DNS പിന്നിംഗ് ഉള്ള നിലവിലെ
പബ്ലിക്-ഒൺലി ഔട്ട്ബൗണ്ട് ഗാർഡ് ഉപയോഗിക്കുന്നു. തുടർന്ന് ബൈറ്റുകൾ കൃത്യമായ ഇന്റേണൽ
`POST /api/modality-bridge/video/extract` ബ്രോക്കർ അതിര് കടക്കുന്നു. ആ റൂട്ട്
`LOCAL_ONLY`-യും `SPAWN_CAPABLE`-യും ആണ്; ഓരോ പ്രോസസിനും ഓതന്റിക്കേറ്റ് ചെയ്ത,
വിശ്വസനീയമായ ലൂപ്പ്ബാക്ക് റിക്വസ്റ്റുകൾ മാത്രമേ അത് സ്വീകരിക്കൂ, കൂടാതെ URL, ഫയൽസിസ്റ്റം പാത്ത്, എക്സിക്യൂട്ടബിൾ,

ഘടനാപരമായ മൂല്യങ്ങൾ നിർണായകമായ സാമ്പിളിങ് തെളിവുകളാണ്; അർത്ഥപരമായ വീഡിയോ ഗ്രഹണമല്ല. അവ വിഷയങ്ങൾ, പ്രവർത്തനങ്ങൾ, ക്യാപ്ഷനുകൾ, സംഭാഷണം, അല്ലെങ്കിൽ ഉപയോക്തൃ ഉദ്ദേശ്യം എന്നിവ അനുമാനിക്കുന്നില്ല. സീൻ, ഫ്രീസ് അതിരുകൾ സെഗ്മെന്റുകൾ രൂപപ്പെടുത്തുന്നു; ഫ്രീസ് കവറേജ്, ബ്ലർ, എക്സ്പോഷർ, സ്പേഷ്യൽ വിശദാംശം, ടെംപറൽ മാറ്റം എന്നിവ നിലവിലുള്ള 1–16 ഫ്രെയിം ബജറ്റ് എങ്ങനെ വകയിരുത്തുന്നു എന്നതിനെ മാത്രമാണ് സ്വാധീനിക്കുന്നത്. പൂർണമായി ഫ്രീസ് ചെയ്ത ഒരു സെഗ്മെന്റ് ഒരു ഫ്രെയിമായി പരിമിതപ്പെടുത്തുന്നു; ഫ്രീസ് ചെയ്യാത്ത സെഗ്മെന്റുകൾ ശേഷിക്കുന്ന ബജറ്റിനായി മത്സരിക്കുന്നു. അതിരുകളുടെ എണ്ണം ഫ്രെയിമുകളെക്കാൾ കൂടുതലാകുമ്പോൾ, വേഗത്തിലുള്ള ആദ്യകാല കട്ടുകൾ നീണ്ട അവസാന സെഗ്മെന്റിനെ മറയ്ക്കാതിരിക്കാൻ ടൈംലൈനിലുടനീളമുള്ള ഏകീകൃത കവറേജ് നിലനിർത്തുന്നു. ഫ്രീസ് അതിരിന്റെ 1-സെക്കൻഡ് അനാലിസിസ് റെസല്യൂഷനിലുള്ള സീൻ അതിരുകൾ ഏകീകരിക്കുന്നു.

ഫിൽട്ടറുകൾ ലഭ്യമല്ലാതിരിക്കൽ, വികലമായതോ ശൂന്യമായതോ ആയ തെളിവ്, ഡിറ്റക്ടർ പിശക്, അല്ലെങ്കിൽ പരിധിയുള്ള പ്രീ-അനാലിസിസ് ടൈംഔട്ട് എന്നിവ സംഭവിച്ചാൽ കൃത്യമായ ഏകീകൃത മിഡ്പോയിന്റ് പോളിസിയിലേക്ക് തുറന്ന രീതിയിൽ പരാജയപ്പെടുന്നു. കോളർ അബോർട്ടോ ബ്രോക്കർ ഡെഡ്ലൈനോ തുറന്ന രീതിയിൽ പരാജയപ്പെടുന്നില്ല: അത് പ്രവർത്തിച്ചുകൊണ്ടിരിക്കുന്ന സബ്പ്രോസസ് അവസാനിപ്പിക്കുകയും തുടർന്നുള്ള ഫ്രെയിം എക്സ്ട്രാക്ഷൻ തടയുകയും ചെയ്യുന്നു; സ്വകാര്യ താൽക്കാലിക ട്രീ `finally`-ൽ നീക്കംചെയ്യുന്നു.

`scripts/perf/video-bridge-fu07-eval.ts`, ഡീഡ്യൂപ്ലിക്കേഷനുശേഷമുള്ള ക്യാപ്ഷൻ-കോൾ ലാഭം, സാന്ദ്ര-ചലന ബജറ്റ് വകയിരുത്തൽ, ബ്ലർ/എക്സ്പോഷർ/SI-TI തെളിവ്, നീണ്ട ടെയിലോടുകൂടിയ ദ്രുത കട്ടുകൾ, ക്രമേണയുള്ള ഫേഡ് തെറ്റായ പോസിറ്റീവുകൾ എന്നിവയ്ക്കായി നിർണായകമായ യഥാർഥ FFmpeg ഫിക്ചറുകൾ സൃഷ്ടിക്കുന്നു. ഇത് പ്രീ-അനാലിസിസ് വാൾ സമയം രേഖപ്പെടുത്തുന്നു; `/usr/bin/time` ലഭ്യമായിടത്ത് ചൈൽഡ് CPU-വും പീക്ക് RSS-ഉം രേഖപ്പെടുത്തുന്നു. ഇതിന്റെ ഗുണനിലവാര പരിശോധനകൾ ഘടനാപരമായ ഓറക്കിളുകൾ മാത്രമാണ്. ഈ ഹാർണസിന് അംഗീകൃത എൻഡ്പോയിന്റോ ഫ്രോസൺ ജഡ്ജോ ഇല്ലാത്തതിനാൽ യഥാർഥ ക്യാപ്ഷൻ-മോഡൽ ഗുണനിലവാരം `HOLD` ആയി തുടരുന്നു. `--caption-cost-per-call-usd` വ്യക്തമായ ഒരു പോസിറ്റീവ് പെർ-കോൾ എസ്റ്റിമേറ്റ് നൽകുന്നില്ലെങ്കിൽ സാമ്പത്തിക ലാഭവും `HOLD` ആയി തുടരും; സ്ക്രിപ്റ്റ് ഈ ഫലങ്ങളിൽ ഒന്നും കെട്ടിച്ചമയ്ക്കുന്നില്ല.

ഓരോ ഫ്രെയിമും 4 MiB-ലേക്ക്, എല്ലാ റോ ഫ്രെയിമുകളും ചേർന്ന് 23 MiB-ലേക്ക്, സീരിയലൈസ് ചെയ്ത ബ്രോക്കർ റെസ്പോൺസ് 32 MiB-ലേക്ക് പരിമിതപ്പെടുത്തിയിരിക്കുന്നു. ഒരു സ്വകാര്യ താൽക്കാലിക ഡയറക്ടറി `finally`-ൽ നീക്കംചെയ്യുന്നു. OmniRoute, FFmpeg ബണ്ടിൽ ചെയ്യുന്നില്ല; കസ്റ്റം എക്സിക്യൂട്ടബിൾ പാത്തും സ്വീകരിക്കുന്നില്ല. ക്യാപ്ഷനിങ്ങിന് മുമ്പ് ബ്രിഡ്ജ് സൂക്ഷ്മമായ ഒരു വിഷ്വൽ ഡീഡ്യൂപ്ലിക്കേഷൻ പാസ് പ്രയോഗിക്കുന്നു: ഓരോ JPEG-യും 16×16 ഗ്രേസ്കെയിൽ ബഫറാക്കി ചുരുക്കുകയും അവസാനം നിലനിർത്തിയ ഫ്രെയിമുമായി മാത്രം താരതമ്യം ചെയ്യുകയും ചെയ്യുന്നു. ഒരു ഫ്രെയിമിനുമുകളിലുള്ള അഭ്യർത്ഥിത ക്യാപ്ഷൻ ബജറ്റിന്, എക്സ്ട്രാക്ഷൻ ആ ബജറ്റിന്റെ ഇരട്ടി വരെയുള്ളതും ഒരിക്കലും 16 ഫ്രെയിമുകളിൽ കൂടുതലല്ലാത്തതുമായ പരിധിയുള്ള ഒരു കാൻഡിഡേറ്റ് പൂൾ നൽകുന്നു. ഡീഡ്യൂപ്ലിക്കേഷനുശേഷം മാത്രമാണ് അഭ്യർത്ഥിത പരിധി പ്രയോഗിക്കുന്നത്; ബജറ്റ് കുറഞ്ഞത് രണ്ടെങ്കിലുമാണെങ്കിൽ അന്തിമമായി ഫ്രെയിമുകളുടെ എണ്ണം കുറയ്ക്കുമ്പോൾ ആദ്യം തിരഞ്ഞെടുത്തതും അവസാനമായി തിരഞ്ഞെടുത്തതുമായ കാൻഡിഡേറ്റുകൾ സംരക്ഷിക്കുന്നു. പതിപ്പിട്ട
`grayscale-16x16-mean-cells-v2` പോളിസി ശരാശരി ലൂമ ഡെൽറ്റയിലും നോർമലൈസ് ചെയ്ത ഡെൽറ്റ കുറഞ്ഞത് 0.05 ആയ തംബ്നെയിൽ സെല്ലുകളുടെ അനുപാതത്തിലും വലുതായത് ഉപയോഗിക്കുന്നു. ഡ്യൂപ്ലിക്കേറ്റ് ത്രെഷോൾഡ് 0.04 എന്ന സ്ഥിരാങ്കമാണ്; റൺടൈം ക്രമീകരണമായി തുറന്നുകാട്ടുന്നതിനുപകരം പ്രവചനക്ഷമതയ്ക്കായാണ് ഇത് തിരഞ്ഞെടുത്തിരിക്കുന്നത്. ശരാശരി മാത്രമുള്ള താരതമ്യം മറച്ചുവയ്ക്കാനിടയുള്ള ചെറിയ ചലനങ്ങളും ദൃശ്യമായ ടെക്സ്റ്റ് മാറ്റങ്ങളും ഈ ദ്വിതീയ ഹൈ-കോൺട്രാസ്റ്റ് സിഗ്നൽ സംരക്ഷിക്കുന്നു. കംപാരേറ്റർ അല്ലെങ്കിൽ ഡീകോഡർ പിശകുകൾ സംഭവിച്ചാൽ തുറന്ന രീതിയിൽ പരാജയപ്പെടുകയും കവറേജ് നിലനിർത്തുകയും ചെയ്യുന്നു. ഔട്ട്പുട്ട് മെറ്റാഡാറ്റ, എക്സ്ട്രാക്റ്റ് ചെയ്ത കാൻഡിഡേറ്റുകൾ, വിജയകരമായി ഉപയോഗിച്ച ഫ്രെയിമുകൾ, ഒഴിവാക്കിയ വിഷ്വൽ ഡ്യൂപ്ലിക്കേറ്റുകൾ എന്നിവ വേർതിരിക്കുന്നു.

വ്യക്തമായി അടയാളപ്പെടുത്തിയ ഒരു വീഡിയോ പാർട്ടിന് ടൈംസ്റ്റാമ്പുള്ള കോൺടാക്ട് ഷീറ്റ് അഭ്യർത്ഥിക്കാം. ബ്രിഡ്ജ് പരമാവധി 4 കോളവും 16 ഫ്രെയിമുമുള്ള JPEG ഗ്രിഡ് നിർമ്മിക്കുന്നു. ഓരോ 512-പിക്സൽ സെല്ലും അതിന്റെ സോഴ്സ് ടൈംസ്റ്റാമ്പ് ഹൈ-കോൺട്രാസ്റ്റ് താഴത്തെ ബാൻഡിൽ പതിപ്പിക്കുന്നു; അതേ ടൈംസ്റ്റാമ്പുകൾ തുടർന്നുള്ള അസോസിയേഷനും ഓഡിറ്റിനുമായി ടെക്സ്റ്റ് മെറ്റാഡാറ്റയിലും നിലനിർത്തുന്നു. പൂർണ JPEG 32 MiB-ലേക്ക് പരിമിതപ്പെടുത്തിയിരിക്കുന്നു. `sharp`-ന് ഗ്രിഡ് ഡീകോഡ് ചെയ്യാനോ കമ്പോസ് ചെയ്യാനോ കഴിയുന്നില്ലെങ്കിൽ, ബ്രിഡ്ജ് ഓരോ JPEG ഫ്രെയിമിലേക്കും ഫാൾബാക്ക് ചെയ്യുന്നു; ക്ലയന്റ് അബോർട്ട് അപ്പോഴും ഷീറ്റ് പ്രവർത്തനത്തിലൂടെ പ്രചരിക്കുന്നു.

പ്രമോഷൻ തെളിവുകൾ സിന്തറ്റിക് കമ്പോസിഷൻ മൈക്രോബെഞ്ച്മാർക്കിൽനിന്ന് മനഃപൂർവം വേർതിരിച്ചിരിക്കുന്നു. `scripts/perf/video-bridge-contact-sheet-eval.ts`, യഥാർഥ OpenAI-അനുയോജ്യ വിഷൻ മോഡലുകൾക്കായി സ്കീമ-പതിപ്പിട്ട A/B ഹാർണസ് നിർവചിക്കുന്നു. പ്രൊവൈഡർ റിപ്പോർട്ട് ചെയ്ത ടോക്കണുകൾ, എൻഡ്-ടു-എൻഡ് വാൾ ലേറ്റൻസി—ഷീറ്റ് കമ്പോസിഷൻ ഉൾപ്പെടെ—മോഡൽ-കോൾ എണ്ണം, മാനിഫെസ്റ്റ് നിർവചിച്ച വസ്തുതാ നിലനിർത്തൽ എന്നിവ ഇത് അളക്കുന്നു. റോ മോഡൽ റെസ്പോൺസുകൾ റിപ്പോർട്ടിൽ എഴുതുന്നില്ല; SHA-256 ഡൈജസ്റ്റുകളും പൊരുത്തപ്പെട്ട ഫാക്റ്റ് ID-കളും മാത്രമാണ് നിലനിർത്തുന്നത്. `--execute-real` നൽകുകയും `--model`, `OMNIROUTE_BASE_URL`, `OMNIROUTE_API_KEY` എന്നിവ കോൺഫിഗർ ചെയ്യുകയും ചെയ്തിട്ടില്ലെങ്കിൽ ഹാർണസ് നെറ്റ്വർക്ക് കോളോ പണമടച്ചുള്ള മോഡൽ കോളോ നടത്തുന്നില്ല. അത്തരം വ്യക്തമായ യഥാർഥ റൺ ഇല്ലെങ്കിൽ, അതിന്റെ മെഷീൻ-റീഡബിൾ വിധി `HOLD` ആയി തുടരും; സിന്തറ്റിക് പേലോഡ്/കോൾ-കൗണ്ട് അളവുകൾ മാത്രം പ്രമോഷൻ തെളിവല്ല.

കോളർമാരുടെ കൈവശം ഇതിനകം അലൈൻ ചെയ്ത ടെക്സ്റ്റ് ഉണ്ടെങ്കിൽ, പിന്തുണയ്ക്കുന്ന ഒരു വീഡിയോ പാർട്ടിൽ ഓപ്ഷണൽ `transcript.cues` അറേ അറ്റാച്ച് ചെയ്യാം. ഓരോ ക്യൂവിലും `text`, പ്രോബ് ചെയ്ത ദൈർഘ്യത്തിനുള്ളിലെ പരിമിതമായ `start`/`end` ഇടവേള, അനുവദനീയ ലിസ്റ്റിലുള്ള `source` (`client`, `embedded`, അല്ലെങ്കിൽ `audio-bridge`) എന്നിവ ഉണ്ടായിരിക്കണം; `confidence`-ന്റെ ഡിഫോൾട്ട് `1` ആണ്, അത് `0`-നും `1`-നും ഇടയിൽ തുടരണം. കൃത്യമായി ഡ്യൂപ്ലിക്കേറ്റായ ക്യൂകൾ ഒന്നാക്കി ചുരുക്കുന്നു. ഈ മെറ്റാഡാറ്റയിൽനിന്ന് OmniRoute ഒരിക്കലും ട്രാൻസ്ക്രിപ്ഷൻ ആരംഭിക്കുന്നില്ല: സാധൂകരിച്ച ക്യൂകൾ സോഴ്സ്, കോൺഫിഡൻസ്, ഇടവേള എന്നിവയോടെ വിവരിച്ച ഫലത്തിലേക്ക് പകർത്തുകയും ഫ്രെയിം ക്യാപ്ഷനുകൾക്കൊപ്പം വിശ്വസിക്കാനാവാത്ത നിരീക്ഷണങ്ങളായി റെൻഡർ ചെയ്യുകയും ചെയ്യുന്നു. അസാധുവായതോ പരിധിക്ക് പുറത്തുള്ളതോ ഉറവിട തെളിവില്ലാത്തതോ ആയ ടെക്സ്റ്റ് ക്യാപ്ഷൻ സ്ട്രീമിൽ കലർത്തുന്നതിനുപകരം നിരസിക്കുന്നു. സ്വയം അവകാശപ്പെടുന്ന `embedded` അല്ലെങ്കിൽ `audio-bridge` ലേബലുകൾ ഉൾപ്പെടെ, രണ്ട് റിക്വസ്റ്റ്-ബോഡി ട്രാൻസ്ക്രിപ്റ്റ് ചാനലുകളും നൽകിയ പ്രൊവനൻസ് `client` ആയി നോർമലൈസ് ചെയ്യുന്നു. സെർവർ ഉടമസ്ഥതയിലുള്ള അഡാപ്റ്ററിന് മാത്രമേ കോഡ്-മാത്രമായ `trustedSource` ആർഗ്യുമെന്റിലൂടെ ആ വിശ്വസനീയ ലേബലുകൾ നൽകാനാകൂ; റിക്വസ്റ്റ് JSON ഫീൽഡിന് ആ ആർഗ്യുമെന്റിലെത്താനാകില്ല. പ്രൊവനൻസ് എന്തായാലും, ട്രാൻസ്ക്രിപ്റ്റ് ടെക്സ്റ്റ് വിശ്വസിക്കാനാവാത്ത മീഡിയയിൽനിന്ന് ലഭിച്ച ഉള്ളടക്കമായി തുടരുന്നു; അത് ഒരിക്കലും ഓതറൈസേഷൻ നിർണയിക്കരുത്.

ടെക്സ്റ്റ് മാർക്കറുകളായി മാറുന്നു; അതിനാൽ ഒരു റോ വീഡിയോയും ശേഷിക്കില്ല. ശേഷി അജ്ഞാതമായിരിക്കുമ്പോൾ, ആ ഭാഗങ്ങൾ
അവയുടെ വീഡിയോ കാരിയർ നിലനിർത്തുന്നു; ഏതെങ്കിലും ഫാൾബാക്ക് ട്രാൻസ്ക്രിപ്റ്റ് മുകളിലുള്ള പരിധിയിട്ട ടെക്സ്റ്റ്
പരിവർത്തനം പിന്തുടരുന്നു. `supportsVideo === true` ഉള്ള ടാർഗെറ്റുകൾ ബ്രിഡ്ജ് ബൈപാസ് ചെയ്യുന്നു.
ക്ലയന്റ് അഭ്യർത്ഥനയുടെ അബോർട്ട് സിഗ്നൽ ഡൗൺലോഡ്, ബ്രോക്കർ ക്യൂ,
സബ്പ്രോസസുകൾ, ക്യാപ്ഷൻ കോളുകൾ എന്നിവയിലൂടെ പ്രൊപ്പഗേറ്റ് ചെയ്യുന്നു; അബോർട്ടുകൾ വീഡിയോകൾക്കിടയിൽ പ്രവർത്തനം നിർത്തുകയും
റോ മീഡിയയിലേക്ക് ഒരിക്കലും ഫെയിൽ-ഓപ്പൺ ചെയ്യാതിരിക്കുകയും ചെയ്യുന്നു.

റൺടൈം ക്രമീകരണങ്ങൾ DB പിന്തുണയുള്ളതും Zod ഉപയോഗിച്ച് വാലിഡേറ്റ് ചെയ്തതുമാണ്:

| കീ                                  | ഡിഫോൾട്ട്   | പരിധി / പ്രവർത്തനം                                                                                                                          |
| ----------------------------------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `modalityBridgeVideoEnabled`        | `false`     | ഐച്ഛിക റൺടൈം, തിരഞ്ഞെടുക്കുന്നവർക്ക് മാത്രം                                                                                                 |
| `modalityBridgeVideoAnalysisMode`   | `"full"`    | `full` പൊതുവായ അടിക്കുറിപ്പുകൾ നിലനിർത്തുന്നു; `focused` പരിധിയിട്ടതും വിശ്വസനീയമല്ലാത്തതുമായ ഏറ്റവും പുതിയ ഉപയോക്തൃ സന്ദർഭം ഉപയോഗിക്കുന്നു |
| `modalityBridgeVideoModel`          | `""`        | Vision Bridge മോഡൽ പാരമ്പര്യമായി സ്വീകരിക്കുക                                                                                               |
| `modalityBridgeVideoFrameCount`     | `8`         | 1–16                                                                                                                                        |
| `modalityBridgeVideoSamplingPolicy` | `"uniform"` | `uniform`, `scene_aware`, അല്ലെങ്കിൽ ആനുപാതികമായ `segment_aware`; ഡിറ്റക്ടർ പരാജയപ്പെട്ടാൽ `uniform`-ലേക്ക് മടങ്ങും                         |
| `modalityBridgeVideoMaxVideos`      | `1`         | 1–4                                                                                                                                         |
| `modalityBridgeVideoTimeout`        | `120000`    | 1000–120000 ms                                                                                                                              |

120 സെക്കൻഡിൽ കൂടുതലുള്ള, മുമ്പ് നിലനിർത്തിയിട്ടുള്ള Video കാലഹരണപ്പെടൽ മൂല്യങ്ങൾ
ബ്രോക്കർ സമയപരിധിയിലേക്ക് പരിമിതപ്പെടുത്തുന്നു; ആ പരിധിക്ക് മുകളിലുള്ള പുതിയ ക്രമീകരണ എഴുത്തുകൾ നിരസിക്കുന്നു.
`GET /api/modality-bridge/video/runtime`-ന് പ്രാമാണീകരണത്തിനോ റൺടൈം പരിശോധനയ്ക്കോ മുമ്പ്,
വിശ്വസനീയമായി മുദ്രയിട്ട ലൂപ്പ്ബാക്ക് ലോക്കാലിറ്റി ആവശ്യമാണ്; തുടർന്ന് മാനേജ്മെന്റ്
പ്രാമാണീകരണവും ആവശ്യമാണ്. ഇത് `available`, ശുദ്ധീകരിച്ച FFmpeg/ffprobe പതിപ്പുകൾ, റൺടൈം
ലഭ്യമല്ലാത്തപ്പോൾ ഒരു സ്ഥിരമായ കാരണം എന്നിവ മാത്രമാണ് നൽകുന്നത്. ആന്തരിക എക്സ്ട്രാക്ഷൻ എൻഡ്പോയിന്റ്
ഒരു പൊതു അപ്ലോഡ് API അല്ല: ക്യൂ സാച്ചുറേഷൻ `503`-നൊപ്പം `Retry-After` നൽകുന്നു, കോളർ
വിച്ഛേദിക്കുമ്പോൾ `499` നൽകുന്നു, സ്ഥിരമായ ബ്രോക്കർ സമയപരിധി `504` നൽകുന്നു. പരിവർത്തനം ചെയ്ത പ്രതികരണങ്ങൾ,
Vision അല്ലെങ്കിൽ Audio സെഗ്മെന്റുകൾ നീക്കം ചെയ്യാതെ, കേന്ദ്ര
`x-omniroute-modality-bridge` ഹെഡറിലേക്ക്
`video->text;model=<visionModel>;parts=<videos>` ചേർക്കുന്നു.

### PII മാസ്കർ (`piiMasker.ts`)

**രണ്ട്** ഘട്ടങ്ങളിലും പ്രവർത്തിക്കുന്നു.

- **`preCall`** പേലോഡ് ക്ലോൺ ചെയ്യുകയും `system`, `messages`, `input`,
  `prompt` എന്നിവയിലൂടെ (പ്ലെയിൻ സ്ട്രിംഗ് ഇനങ്ങൾ ഉൾപ്പെടെ) സഞ്ചരിക്കുകയും, സ്ട്രിംഗ്
  `content`/`text` ഫീൽഡുകളിൽ `processPII()` (`@/shared/utils/inputSanitizer`-ൽ നിന്ന്)
  പ്രയോഗിക്കുകയും ചെയ്യുന്നു. `PII_REDACTION_ENABLED=true` ആയിരിക്കുമ്പോൾ, കണ്ടെത്തിയ PII
  ഔട്ട്ബൗണ്ട് പേലോഡിൽ റിഡാക്റ്റ് ചെയ്യപ്പെടുന്നു. ഇത് `INPUT_SANITIZER_MODE`-ൽ നിന്ന്
  സ്വതന്ത്രമാണ് (അത് പ്രോംപ്റ്റ്-ഇൻജക്ഷൻ നയം മാത്രമാണ് നിയന്ത്രിക്കുന്നത്). റിഡാക്ഷൻ ഓഫ്
  ആയിരിക്കുമ്പോൾ, ഉള്ളടക്കം മാറ്റിയെഴുതാതെ കോൾ കണ്ടെത്തൽ എണ്ണങ്ങൾ രേഖപ്പെടുത്തുന്നു.
- **`postCall`** പ്രതികരണത്തിന്റെ ഡീപ്പ് ക്ലോൺ സൃഷ്ടിക്കുകയും `sanitizePIIResponse()`-നൊപ്പം
  Responses-API-ആകൃതിയിലുള്ള മാസ്കർ (`maskResponsesOutput` — `output_text`,
  `output[].content[].text` എന്നിവ ഉൾക്കൊള്ളുന്നു) പ്രവർത്തിപ്പിക്കുകയും ചെയ്യുന്നു. ഏതെങ്കിലും
  റിഡാക്ഷൻ സംഭവിച്ചാൽ, പരിഷ്കരിച്ച പ്രതികരണം യഥാർത്ഥ പ്രതികരണത്തെ മാറ്റിസ്ഥാപിക്കുന്നു.

ഗാർഡ്റെയിൽ ഒരിക്കലും തടയുന്നില്ല; അത് വ്യാഖ്യാനങ്ങൾ ചേർക്കുകയോ (`meta.detections`,
`meta.redacted`) മാറ്റിയെഴുതുകയോ മാത്രമാണ് ചെയ്യുന്നത്.

#### തരംപ്രകാരമുള്ള തിരഞ്ഞെടുപ്പ്, ഇഷ്ടാനുസൃത പാറ്റേണുകൾ, കണ്ടെത്തൽ കൗണ്ടറുകൾ

**Dashboard → Settings → Security → PII masking** മാസ്ക് ചെയ്യേണ്ടത് _എന്താണെന്ന്_
തിരഞ്ഞെടുക്കുന്നു. ഇത് മാസ്കിംഗ് ഓൺ ചെയ്യുന്നില്ല: അതിനായി ഇപ്പോഴും `PII_REDACTION_ENABLED`
(അഭ്യർത്ഥന), `PII_RESPONSE_SANITIZATION` (പ്രതികരണം + SSE) എന്നിവയാണ് ഉപയോഗിക്കുന്നത്;
രണ്ടും ഡിഫോൾട്ടായി ഓഫ് ആണ്.

- **തരംപ്രകാരമുള്ള തിരഞ്ഞെടുപ്പ്** — ബിൽറ്റ്-ഇൻ id-കൾ
  `src/shared/constants/piiTypes.ts`-ലെ (`PII_BUILTIN_TYPES`) പട്ടികയിൽ നൽകിയിരിക്കുന്നു.
  സജ്ജീകരിച്ചിട്ടില്ലെങ്കിൽ എല്ലാ തരങ്ങളും എന്നാണ് അർത്ഥം (ഈ ക്രമീകരണം നിലവിൽ വരുന്നതിന്
  മുമ്പുള്ള പ്രവർത്തനം). അഭ്യർത്ഥന എൻജിന്റെ `ssn_us` പാറ്റേൺ `ssn`-ലേക്ക് മാപ്പ് ചെയ്യുന്നു.
  ടെംപ്ലേറ്റുകൾ (Minimal, Standard, Financial, Brazilian, USA, Full) UI-യിലെ
  ചെക്ക്ബോക്സുകൾ പൂരിപ്പിക്കുക മാത്രമാണ് ചെയ്യുന്നത്.
- **ഇഷ്ടാനുസൃത പാറ്റേണുകൾ** — പരമാവധി 20 regex അല്ലെങ്കിൽ വൈൽഡ്കാർഡ് പാറ്റേണുകൾ
  (`*` = പരമാവധി 64 നോൺ-വൈറ്റ്സ്പേസ് പ്രതീകങ്ങൾ, `?` = ഒന്ന്). പൊരുത്തങ്ങൾ
  `[CUSTOM_REDACTED]` ആയി മാറുന്നു. ഓരോ പാറ്റേണും `compilePiiCustomPattern()`
  (`src/shared/utils/piiCustomPatterns.ts`) വഴി കടന്നുപോകുന്നു: പരമാവധി 500 പ്രതീകങ്ങൾ,
  ഫ്ലാഗുകൾ `g i m s u` ആയി പരിമിതപ്പെടുത്തിയിരിക്കുന്നു, കംപൈൽ ചെയ്യാൻ കഴിയണം,
  `safe-regex` (വിനാശകരമായ ബാക്ക്ട്രാക്കിംഗ്) കടന്നുപോകണം, കൂടാതെ ശൂന്യമായ സ്ട്രിങ്ങുമായോ
  റിഡാക്ഷൻ പ്ലേസ്ഹോൾഡറുമായോ പൊരുത്തപ്പെടരുത്. പരാജയപ്പെടുന്ന പാറ്റേൺ സേവ് ചെയ്യുമ്പോഴും
  പരീക്ഷിക്കുമ്പോഴും നിരസിക്കപ്പെടുന്നു; പരാജയപ്പെടുന്ന ഒരു സംഭരിച്ച റോ കംപൈൽ ചെയ്യുന്നതിനുപകരം
  റൺടൈമിൽ ഒഴിവാക്കുന്നു. മാസ്കിംഗ് ഓൺ ആയിരിക്കുമ്പോൾ മാത്രമാണ് ഇഷ്ടാനുസൃത പാറ്റേണുകൾ പ്രവർത്തിക്കുന്നത്.
- **കണ്ടെത്തൽ കൗണ്ടറുകൾ** — തരംപ്രകാരമുള്ള എണ്ണങ്ങൾ (പൊരുത്തപ്പെട്ട മൂല്യങ്ങൾ ഒരിക്കലും
  സൂക്ഷിക്കില്ല), മെമ്മറിയിൽ നിലനിർത്തുകയും പുനരാരംഭിക്കുമ്പോൾ പുനഃസജ്ജമാക്കുകയും ചെയ്യുന്നു
  (`src/lib/pii/piiDetectionStats.ts`). മാസ്കിംഗ് ഓൺ ആയിരിക്കുമ്പോൾ മാത്രമാണ് അവ വർധിക്കുന്നത്.

ക്രമീകരണങ്ങൾ `key_value` പട്ടികയിലാണ് (നെയിംസ്പേസ് `pii_settings`,
`src/lib/db/piiSettings.ts`) സൂക്ഷിക്കുന്നത്; 1 s കാഷിലൂടെയാണ് അവ വായിക്കുന്നത്. API:

| രീതി   | പാത്ത്                   | ഉദ്ദേശ്യം                                                                             |
| ------ | ------------------------ | ------------------------------------------------------------------------------------- |
| `GET`  | `/api/settings/pii`      | ഫ്ലാഗ് നില, `enabledTypes`, `customPatterns`, കണ്ടെത്തൽ കൗണ്ടറുകൾ                     |
| `PUT`  | `/api/settings/pii`      | `enabledTypes` (`null` = എല്ലാം) കൂടാതെ/അല്ലെങ്കിൽ `customPatterns` മാറ്റിസ്ഥാപിക്കുക |
| `POST` | `/api/settings/pii/test` | പരമാവധി 8 KB സാമ്പിളിനെതിരെ ഒരു പാറ്റേൺ ഡ്രൈ-റൺ ചെയ്യുക; ഒന്നും സംഭരിക്കില്ല          |

മൂന്നിനും മാനേജ്മെന്റ് പ്രാമാണീകരണം ആവശ്യമാണ്; കൂടാതെ Zod ഉപയോഗിച്ച്
(`src/shared/validation/schemas/piiSettings.ts`) ബോഡി സാധൂകരിക്കുന്നു.

### പ്രോംപ്റ്റ് ഇൻജക്ഷൻ (`promptInjection.ts`)

ഉപയോക്താവ് നൽകിയ ഉള്ളടക്കത്തിലെ പ്രതികൂല ഘടനകൾ കണ്ടെത്തുകയും ക്രമീകരിച്ച
നയം നടപ്പാക്കുകയും ചെയ്യുന്നു. പ്രവർത്തനം എൻവയോൺമെന്റ് വേരിയബിളുകളും കൺസ്ട്രക്ടർ
ഓപ്ഷനുകളും നിയന്ത്രിക്കുന്നു:

| ക്രമീകരണം              | എൻവ് വേരിയബിൾ                                                                                               | ഡിഫോൾട്ട് | പ്രഭാവം                                                                                                                                                                                                                                |
| ---------------------- | ----------------------------------------------------------------------------------------------------------- | --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| പ്രവർത്തനക്ഷമമാക്കിയത് | `INPUT_SANITIZER_ENABLED`                                                                                   | `true`    | `false` ആയിരിക്കുമ്പോൾ, ഗാർഡ്റെയിൽ ഷോർട്ട്-സർക്യൂട്ട് ചെയ്യുന്നു.                                                                                                                                                                      |
| മോഡ്                   | `INJECTION_GUARD_MODE` / `INPUT_SANITIZER_MODE`                                                             | `warn`    | ഇൻജക്ഷൻ നയം: `block`, `warn`, അല്ലെങ്കിൽ `log`. (പിന്നോട്ടുള്ള അനുയോജ്യതയ്ക്കായി `redact` സ്വീകരിക്കുമെങ്കിലും അത് ഇൻജക്ഷൻ ടെക്സ്റ്റ് നീക്കം ചെയ്യുകയില്ല; അഭ്യർത്ഥനയിലെ PII റീറൈറ്റ് നിയന്ത്രിക്കുന്നത് `PII_REDACTION_ENABLED` ആണ്.) |
| ബ്ലോക്ക് പരിധി         | `blockThreshold` ഓപ്ഷൻ / `INPUT_SANITIZER_BLOCK_THRESHOLD` (`INJECTION_GUARD_BLOCK_THRESHOLD` എന്ന അപരനാമം) | `high`    | ബ്ലോക്ക് ചെയ്യുന്നതിന് ആവശ്യമായ ഏറ്റവും കുറഞ്ഞ തീവ്രത. ഡിഫോൾട്ടായി Medium നിരീക്ഷണത്തിന് മാത്രമുള്ളതാണ്.                                                                                                                               |

**മോഡ് മുൻഗണന** (`getMode`): കോളറിന്റെ `options.mode` →
`INJECTION_GUARD_MODE` **DB ഫീച്ചർ-ഫ്ലാഗ് ഓവർറൈഡ്** (Dashboard → Settings →
Feature Flags) → `INJECTION_GUARD_MODE` എൻവ് → `INPUT_SANITIZER_MODE` എൻവ് →
`warn`. അതിനാൽ ഒരു ഡാഷ്ബോർഡ് ഓവർറൈഡിന് എൻവ് വേരിയബിളുകളെക്കാൾ മുൻഗണന ലഭിക്കുന്നു; അതുകൊണ്ട് Feature
Flags UI-ക്ക് പ്രവർത്തിച്ചുകൊണ്ടിരിക്കുന്ന ഗാർഡിനെ തത്സമയം നിയന്ത്രിക്കാനാകും (പുനരാരംഭിക്കേണ്ടതില്ല). DB റീഡ് പരാജയസുരക്ഷിതമാണ്:
അതിൽ പിശക് സംഭവിച്ചാൽ, ഗാർഡ് എൻവ് അധിഷ്ഠിതമായ പെരുമാറ്റത്തിലേക്ക് മടങ്ങും; കൂടാതെ
ഓവർറൈഡ് സജ്ജീകരിച്ചിട്ടില്ലെങ്കിൽ, പെരുമാറ്റം എൻവ്-മാത്രം ഉപയോഗിച്ചുള്ള പരിഹാരത്തിന് സമാനമായിരിക്കും.

കണ്ടെത്തൽ ഉറവിടങ്ങൾ:

1. `@/shared/utils/inputSanitizer`-ൽ നിന്നുള്ള `sanitizeRequest()` (പൈപ്പ്ലൈനിലെ
   മറ്റ് ഭാഗങ്ങളിലും ഉപയോഗിക്കുന്ന പങ്കിട്ട ഡിറ്റക്ടർ സെറ്റ്).
2. ബിൽറ്റ്-ഇൻ `DEFAULT_GUARD_PATTERNS` (നിലവിൽ `system_override_inline`,
   `markdown_system_block` എന്നിവ; രണ്ടിനും `high` തീവ്രത).
3. കൺസ്ട്രക്റ്റർ ഓപ്ഷനുകളിലൂടെ നൽകുന്ന ഐച്ഛിക `customPatterns` (സ്ട്രിങ്ങുകൾ, റെഗെക്സ്,
   അല്ലെങ്കിൽ `{ name, pattern, severity }` റെക്കോർഡുകൾ).

`mode === "block"` ആയിരിക്കുകയും കുറഞ്ഞത് ഒരു കണ്ടെത്തലെങ്കിലും തീവ്രതാ
പരിധിയിലെത്തുകയും ചെയ്യുമ്പോൾ, `preCall` `{ block: true, message: "Request rejected:
suspicious content detected" }` മടക്കിനൽകുന്നു. `warn`/`log` മോഡുകളിൽ ഗാർഡ്റെയിൽ ലോഗ്
ചെയ്യുമെങ്കിലും കോൾ അനുവദിക്കുന്നു. രജിസ്ട്രിയിലൂടെ കടന്നുപോകാതെ പ്രോംപ്റ്റുകൾ
വിലയിരുത്തേണ്ട കോളർമാർക്കായി പങ്കിട്ട ഹെൽപ്പറായ `evaluatePromptInjection()`-ഉം എക്സ്പോർട്ട് ചെയ്യുന്നു.

**സ്കാൻ പരിധി (v3.8.20):** ഡിറ്റക്ടർ സംയോജിപ്പിച്ച പ്രോംപ്റ്റ് ടെക്സ്റ്റിന്റെ **ആദ്യത്തെ 16 KB** മാത്രമാണ്
പരിശോധിക്കുന്നത് — `src/shared/utils/inputSanitizer.ts`-ൽ
`MAX_INJECTION_SCAN_BYTES = 16 * 1024` (16 384 ബൈറ്റുകൾ). പാറ്റേൺ ലൂപ്പ് പ്രവർത്തിപ്പിക്കുന്നതിന് മുമ്പ്
`detectInjection()`-ഉം `evaluatePromptInjection()`-ഉം `slice(0, MAX_INJECTION_SCAN_BYTES)`
ഉപയോഗിക്കുന്നു. ഇൻജക്ഷൻ നിർദ്ദേശങ്ങൾ സാധാരണയായി ഇൻപുട്ടിന്റെ മുകൾഭാഗത്താണ് വരുന്നത്; അതിനാൽ ഇത്
കണ്ടെത്തൽ ദുർബലമാക്കാതെ നൂറുകണക്കിന്-KB വലുപ്പമുള്ള പേലോഡുകളിൽ റെഗെക്സ് CPU/GC ഉപയോഗം
പരിമിതപ്പെടുത്തുന്നു (cf. #3932, #4041).

### ക്രെഡൻഷ്യൽ മാസ്കർ (`credentialMasker.ts`)

ഡിഫോൾട്ട് ശൃംഖലയിൽ അവസാനമായി (മുൻഗണന `95`) **രണ്ട്** ഘട്ടങ്ങളിലും പ്രവർത്തിക്കുന്നു. ഔട്ട്ബൗണ്ട്
പേലോഡിൽനിന്നും (സന്ദേശ ഉള്ളടക്കം, ടൂൾ-കോൾ ആർഗ്യുമെന്റുകൾ, ടൂൾ ഫലങ്ങൾ) പ്രൊവൈഡർ
റെസ്പോൺസിൽനിന്നും സുപരിചിതമായ API-കീ / രഹസ്യ-ടോക്കൺ പാറ്റേണുകൾ റിഡാക്റ്റ് ചെയ്യുന്നു. അതിനാൽ
ഒരു പ്രോംപ്റ്റിൽ പേസ്റ്റ് ചെയ്ത ക്രെഡൻഷ്യലോ (അല്ലെങ്കിൽ ടൂൾ ഫലം തിരികെ എക്കോ ചെയ്തതോ) അപ്സ്ട്രീം
പ്രൊവൈഡറിലേക്കോ ക്ലയന്റിലേക്കോ ചോരുന്നില്ല.

- **ഓപ്റ്റ്-ഇൻ മാത്രം**, PII റിഡാക്ഷന്റെ അതേ രീതി (Hard Rule #20-ന് സമീപമുള്ളത്):
  `settings.credentialRedactionEnabled === true` **അല്ലെങ്കിൽ**
  `CREDENTIAL_REDACTION_ENABLED=true` അല്ലാത്തപക്ഷം പ്രവർത്തനരഹിതമായിരിക്കും. ഇത് ഓഫ് ആയിരിക്കുമ്പോൾ, ഗാർഡ്റെയിൽ ഒന്നും ചെയ്യില്ല —
  അത് ഒരിക്കലും ബ്ലോക്ക് ചെയ്യുകയോ റീറൈറ്റ് ചെയ്യുകയോ ഇല്ല.
- `redactCredentials()` മുഴുവൻ പേലോഡ്/റെസ്പോൺസ് ട്രീയിലൂടെയും സഞ്ചരിക്കുകയും (`walkValue()`,
  പ്രോട്ടോടൈപ്പ്-പൊല്യൂഷനിൽനിന്ന് സുരക്ഷിതം, `WeakSet` വഴി സൈക്കിൾ-സുരക്ഷിതം) പൊരുത്തങ്ങളെ
  `[REDACTED:<type>]` പ്ലേസ്ഹോൾഡർ ഉപയോഗിച്ച് മാറ്റിസ്ഥാപിക്കുകയും ചെയ്യുന്നു; യഥാർത്ഥത്തിൽ
  മാറിയ ബ്രാഞ്ചുകൾ മാത്രമേ ക്ലോൺ ചെയ്യൂ.
- `CREDENTIAL_PATTERNS` LLM പ്രൊവൈഡർ കീകൾ (OpenAI, OpenAI-proj,
  Anthropic, Google, Hugging Face, Replicate), VCS/SaaS ടോക്കണുകൾ (GitHub, Slack,
  Linear, Notion, npm, Postman, Discord), പേയ്മെന്റ് കീകൾ (Stripe, Square), ക്ലൗഡ്
  കീകൾ (AWS ആക്സസ് കീ, Twilio, SendGrid, Mailgun), സ്വകാര്യ കീകൾ / JWT-കൾ,
  ക്രെഡൻഷ്യൽ അടങ്ങിയ കണക്ഷൻ സ്ട്രിങ്ങുകൾ (`mongodb://user:pass@...` മുതലായവ), കൂടാതെ
  പൊതുവായ `Authorization`/`x-api-key`/`api-key`/`apikey` ഹെഡർ-വാല്യു
  പാറ്റേൺ എന്നിവ ഉൾക്കൊള്ളുന്നു. ഹെഡർ രൂപത്തിലുള്ള കീകൾ (`authorization`, `x-api-key`, `api-key`,
  `apikey`) പൊതുവായ ടെക്സ്റ്റ് റെഗെക്സ് ഉപയോഗിക്കുന്നതിനുപകരം ഘടനാപരമായി റിഡാക്റ്റ് ചെയ്യുന്നു
  (വാല്യു മാത്രം; `Bearer `/`Basic ` പോലുള്ള സ്കീം പ്രിഫിക്സ് നിലനിർത്തുന്നു).
- ഗാർഡ്റെയിൽ ഒരിക്കലും ബ്ലോക്ക് ചെയ്യില്ല; അത് റീറൈറ്റ് (`modifiedPayload` /
  `modifiedResponse`) ചെയ്യുകയും അനോട്ടേറ്റ് (`meta.credentialsRedacted`, `meta.count`) ചെയ്യുകയും മാത്രമാണ് ചെയ്യുന്നത്.

റിഗ്രഷൻ ഗാർഡ്: `tests/unit/credential-masker-guardrail.test.ts`.

## അടിസ്ഥാന കരാർ (base.ts)

```typescript
class BaseGuardrail {
  enabled: boolean;
  name: string;
  priority: number;

  constructor(name: string, options?: { enabled?: boolean; priority?: number });

  async preCall(payload: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;

  async postCall(response: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;
}

interface GuardrailResult<TValue = unknown> {
  block?: boolean; // true short-circuits the chain
  message?: string; // തടയുമ്പോൾ ഇത് ദൃശ്യമാകും
  meta?: Record<string, unknown> | null;
  modifiedPayload?: TValue; // അഭ്യർത്ഥന മാറ്റിയെഴുതാൻ preCall തിരികെ നൽകുന്നത്
  modifiedResponse?: TValue; // പ്രതികരണം മാറ്റിയെഴുതാൻ postCall തിരികെ നൽകുന്നത്
}

interface GuardrailContext {
  apiKeyInfo?: Record<string, unknown> | null;
  disabledGuardrails?: string[] | null;
  endpoint?: string | null;
  headers?: Headers | Record<string, unknown> | null;
  log?: GuardrailLog | Console | null;
  method?: string | null;
  model?: string | null;
  provider?: string | null;
  signal?: AbortSignal;
  sourceFormat?: string | null;
  stream?: boolean;
  targetFormat?: string | null;
}
```

ഒരു ഗാർഡ്റെയിൽ "മാറ്റമില്ല" എന്ന് സൂചിപ്പിക്കുന്നത് ``void`, `{}`, അല്ലെങ്കിൽ `{ block: false }`തിരികെ നൽകിക്കൊണ്ടാണ്.`modifiedPayload`/`modifiedResponse`തിരികെ നൽകുന്നത്, താഴെയുള്ള ഗാർഡ്റെയിലുകൾക്കായി ചെയിനിലൂടെ ഒഴുകുന്ന മൂല്യത്തെ മാറ്റിസ്ഥാപിക്കുന്നു.`signal?: AbortSignal` കോളർ ലൈഫ്സൈക്കിളിനെ ഗാർഡ്റെയിലുകളിലേക്ക് എത്തിക്കുന്നു. ഒരു അഭ്യർത്ഥന റദ്ദാക്കൽ എന്നത് മനഃപൂർവമായ ഒരു ഫെയിൽ-ഓപ്പൺ അപവാദമാണ്: മീഡിയ ബ്രിഡ്ജുകൾ പ്രവർത്തിക്കുന്നത് നിർത്തുകയും, അസംസ്കൃത മീഡിയയെ പിന്തുണയ്ക്കാത്ത ഒരു ലക്ഷ്യസ്ഥാനത്തേക്ക് പുനഃസ്ഥാപിക്കാതെ വൃത്തിയാക്കുകയും ചെയ്യുന്നു.

## രജിസ്ട്രി (registry.ts)

സിംഗിൾട്ടൺ `guardrailRegistry` താഴെ പറയുന്നവ നൽകുന്നു:

- `register(guardrail)` — ഒരു ഗാർഡ്റെയിൽ ചേർക്കുന്നു (അല്ലെങ്കിൽ സാധാരണമാക്കിയ പേര് ഉപയോഗിച്ച് മാറ്റിസ്ഥാപിക്കുന്നു) കൂടാതെ ആരോഹണ ക്രമത്തിൽ `priority` അനുസരിച്ച് വീണ്ടും ക്രമീകരിക്കുന്നു.
- `clear()` / `list()` — അഡ്മിനിസ്ട്രേറ്റീവ് സഹായികൾ.
- `runPreCallHooks(payload, context)` — സജീവ ഗാർഡ്റെയിലുകളിലൂടെ ആവർത്തിക്കുന്നു, `modifiedPayload` വഴി പേലോഡിനെ കടത്തിവിടുന്നു, കൂടാതെ ആദ്യത്തെ `block: true` വരുമ്പോൾ നിർത്തുന്നു.
- `runPostCallHooks(response, context)` — പ്രതികരണ ഭാഗത്തും ഇതേ പ്രവാഹം.
- `resetGuardrailsForTests({ registerDefaults })` — നിലവിലെ അവസ്ഥ മായ്ക്കുന്നു കൂടാതെ വൃത്തിയുള്ള ടെസ്റ്റ് ഐസൊലേഷനായി ഡിഫോൾട്ടുകൾ ഓപ്ഷണലായി വീണ്ടും രജിസ്റ്റർ ചെയ്യുന്നു.

രണ്ട് റണ്ണറുകളും `{ blocked, payload|response, results, guardrail?, message? }` തിരികെ നൽകുന്നു, ഇവിടെ `results` എന്നത് `GuardrailExecutionResult` റെക്കോർഡുകളുടെ ഒരു നിരയാണ്, അതിൽ ഓരോ ഗാർഡ്റെയിലിനുമുള്ള `blocked`, `skipped`, `modified`, `error`, `meta` ഫീൽഡുകൾ ഉൾപ്പെടുന്നു, ഇത് ട്രേസിംഗിന് ഉപയോഗപ്രദമാണ്.

### ഓരോ അഭ്യർത്ഥനയ്ക്കും ഗാർഡ്റെയിലുകൾ പ്രവർത്തനരഹിതമാക്കുന്നു

`resolveDisabledGuardrails({ apiKeyInfo, body, headers })` നിലവിലെ അഭ്യർത്ഥനയ്ക്കായി ഒഴിവാക്കേണ്ട ഗാർഡ്റെയിൽ പേരുകളുടെ ഡ്യൂപ്ലിക്കേഷൻ ഒഴിവാക്കിയ ഒരു ലിസ്റ്റ് ശേഖരിക്കുന്നു. ഉറവിടങ്ങൾ (എല്ലാം ഓപ്ഷണൽ, എല്ലാം ലയിപ്പിച്ചത്):

- `apiKeyInfo.disabledGuardrails`
- അഭ്യർത്ഥന ബോഡി `disabledGuardrails` (ടോപ്പ്-ലെവൽ)
- അഭ്യർത്ഥന ബോഡി `metadata.disabledGuardrails`
- ഹെഡർ `x-omniroute-disabled-guardrails` (അല്ലെങ്കിൽ പഴയ `x-disabled-guardrails`)

മൂല്യങ്ങൾ സ്ട്രിംഗുകളുടെ നിരകളോ കോമയാൽ വേർതിരിച്ച സ്ട്രിംഗോ ആകാം; പേരുകൾ ലോവർകേസ് കെബാബ്-കേസിലേക്ക് സാധാരണമാക്കുന്നു (`pii_masker` → `pii-masker`). ഫലം `context.disabledGuardrails` വഴി രജിസ്ട്രിയിലേക്ക് കൈമാറുന്നു, ഇത് പൊരുത്തപ്പെടുന്ന ഗാർഡ്റെയിലുകളെ ഒഴിവാക്കുന്നു (`results`-ൽ `skipped: true`).

## എക്സിക്യൂഷൻ ഓർഡർ

`src/sse/handlers/chat.ts`, `open-sse/handlers/chatCore.ts` എന്നിവയിലൂടെ ഒഴുകുന്ന ഓരോ അഭ്യർത്ഥനയ്ക്കും:

1. `resolveDisabledGuardrails(...)` API കീ, ബോഡി, ഹെഡറുകൾ എന്നിവയിൽ നിന്ന് സ്കിപ്പ് ലിസ്റ്റ് നിർമ്മിക്കുന്നു.
2. `guardrailRegistry.runPreCallHooks(body, ctx)` ഗാർഡ്റെയിലുകൾ ആരോഹണ മുൻഗണനാ ക്രമത്തിൽ പ്രവർത്തിപ്പിക്കുന്നു:
   - പ്രവർത്തനരഹിതമാക്കിയ ഗാർഡ്റെയിലുകൾ `skipped` എന്ന് രേഖപ്പെടുത്തുന്നു.
   - ഓരോ ഗാർഡ്റെയിലിന്റെയും `preCall` `modifiedPayload` വഴി പേലോഡ് മാറ്റിയെഴുതിയേക്കാം.
   - ആദ്യത്തെ `block: true` ചെയിൻ ചുരുക്കുകയും ഹാൻഡ്ലർ ഒരു ഗാർഡ്റെയിൽ നിരസിക്കൽ പ്രതികരണം നൽകുകയും ചെയ്യുന്നു.
3. (സാധ്യതയുള്ള മാറ്റിയെഴുതിയ) പേലോഡ് കോംബോ റൂട്ടിംഗിലേക്കും അപ്സ്ട്രീം ഡിസ്പാച്ചിലേക്കും ഒഴുകുന്നു.
4. പ്രതികരണം കൂട്ടിച്ചേർത്ത ശേഷം, `guardrailRegistry.runPostCallHooks(...)` പ്രതികരണത്തിൽ അതേ ചെയിൻ പ്രവർത്തിപ്പിക്കുന്നു. ഇവിടെ `block: true` അപ്സ്ട്രീം പ്രതികരണം ഒഴിവാക്കുന്നു.

തെറ്റ് വരുത്തുന്ന ഗാർഡ്റെയിലുകൾ `error: <message>` എന്ന് രേഖപ്പെടുത്തുകയും `logger.warn` വഴി ലോഗ് ചെയ്യുകയും ചെയ്യുന്നു, പക്ഷേ ചെയിൻ തുടരുന്നു — രൂപകൽപ്പന പ്രകാരം ഫെയിൽ-ഓപ്പൺ.

## കോൺഫിഗറേഷൻ

ബിൽറ്റ്-ഇൻ ഗാർഡ്റെയിലുകൾ വായിക്കുന്ന എൻവയോൺമെന്റ് വേരിയബിളുകൾ:

| വേരിയബിൾ                              | ഉപയോഗിക്കുന്നത്           | പ്രഭാവം                                                                                                             |
| ------------------------------------- | ------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `INPUT_SANITIZER_ENABLED`             | `prompt-injection`        | കണ്ടെത്തൽ പൂർണ്ണമായും പ്രവർത്തനരഹിതമാക്കാൻ `false` എന്ന് സജ്ജമാക്കുക.                                               |
| `INPUT_SANITIZER_MODE`                | `prompt-injection`        | ഇൻജക്ഷൻ പോളിസി: `warn`, `block`, അല്ലെങ്കിൽ `log`. പഴയ മൂല്യം `redact` ഇൻജക്ഷൻ ടെക്സ്റ്റ് മാറ്റിയെഴുതുന്നില്ല.      |
| `INJECTION_GUARD_MODE`                | `prompt-injection`        | ഇൻജക്ഷൻ ഗാർഡിനായുള്ള മോഡ്; എൻവയോൺമെന്റ് വേരിയബിളുകളെ **അസാധുവാക്കുന്ന** ഒരു DB ഫീച്ചർ ഫ്ലാഗ് കൂടിയാണിത് (DB > ENV). |
| `INPUT_SANITIZER_BLOCK_THRESHOLD`     | `prompt-injection`        | `MODE=block` നിരസിക്കുന്ന ഏറ്റവും കുറഞ്ഞ തീവ്രത: `high` (സ്ഥിരസ്ഥിതി), `medium`, അല്ലെങ്കിൽ `low`.                  |
| `INJECTION_GUARD_BLOCK_THRESHOLD`     | `prompt-injection`        | `INPUT_SANITIZER_BLOCK_THRESHOLD` എന്നതിന്റെ പഴയ പേര്.                                                              |
| `PII_REDACTION_ENABLED`               | `pii-masker`              | `true` ആയിരിക്കുമ്പോൾ, അഭ്യർത്ഥന PII റെഡാക്ട് ചെയ്യപ്പെടുന്നു (ഇൻജക്ഷൻ മോഡിൽ നിന്ന് സ്വതന്ത്രമായി).                 |
| `PII_RESPONSE_SANITIZATION` / `_MODE` | `pii-masker` (ഡൗൺസ്ട്രീം) | പ്രതികരണ-വശത്തുള്ള മാസ്കർ സ്വഭാവം നിയന്ത്രിക്കുന്നു.                                                                |

മോഡാലിറ്റി ബ്രിഡ്ജ് ഗാർഡ്റെയിലുകൾ DB-ബാക്ക്ഡ് സെറ്റിംഗ്സ് സ്റ്റോറിൽ നിന്ന് (`getSettings()`) റൺടൈം കോൺഫിഗറേഷൻ വായിക്കുന്നു, എൻവയോൺമെന്റ് വേരിയബിളുകളിൽ നിന്നല്ല. വിഷന്റെ പ്രാഥമിക കീകൾ `modalityBridgeVisionEnabled`, `modalityBridgeVisionMode`, `modalityBridgeVisionModel`, `modalityBridgeVisionTaskAware`, `modalityBridgeVisionPrompt`, `modalityBridgeVisionTimeout`, `modalityBridgeVisionMaxImages`, `modalityBridgeVisionMaxChars`, `modalityBridgeCacheEnabled`, `modalityBridgeCacheTtlMinutes`, `modalityBridgeCacheMaxEntries` എന്നിവയാണ്. പഴയ `visionBridge*` കീകൾ ഡോക്യുമെന്റ് ചെയ്ത വൺ-സൈക്കിൾ റീഡ് ഫാൾബാക്കായി മാത്രമേ സ്വീകരിക്കുകയുള്ളൂ; ഡാഷ്ബോർഡ് റൈറ്റുകൾ പ്രാഥമിക കീകൾ ഉപയോഗിക്കുന്നു. സ്ഥിരസ്ഥിതികളും ഫാൾബാക്ക് റെസല്യൂവറും `src/shared/constants/modalityBridgeDefaults.ts` എന്നതിലാണ്, പഴയ സ്ഥിരാങ്കങ്ങൾ `src/shared/constants/visionBridgeDefaults.ts` എന്നതിൽ നിലനിർത്തുന്നു.

ഓഡിയോ `modalityBridgeAudioEnabled`, `modalityBridgeAudioModel`, `modalityBridgeAudioTimeout`, `modalityBridgeAudioMaxClips` എന്നിവയും പങ്കിട്ട `modalityBridgeCache*` ക്രമീകരണങ്ങളും ഉപയോഗിക്കുന്നു. മോഡാലിറ്റി ബ്രിഡ്ജ് സ്കീമയോടൊപ്പം ഈ കീകൾ അവതരിപ്പിച്ചതിനാൽ ഓഡിയോയ്ക്ക് പഴയ-കീ ഫാൾബാക്ക് ഇല്ല.

വീഡിയോ `modalityBridgeVideoEnabled`, `modalityBridgeVideoAnalysisMode`, `modalityBridgeVideoModel`, `modalityBridgeVideoFrameCount`, `modalityBridgeVideoSamplingPolicy`, `modalityBridgeVideoMaxVideos`, `modalityBridgeVideoTimeout` എന്നിവയും പങ്കിട്ട `modalityBridgeCache*` ക്രമീകരണങ്ങളും ഉപയോഗിക്കുന്നു. FFmpeg/ffprobe ഓപ്ഷണൽ ഓപ്പറേഷണൽ ഡിപൻഡൻസികളും ഫ്രെയിം ക്യാപ്ഷനിംഗ് ലേറ്റൻസിയും മോഡൽ ചെലവും വർദ്ധിപ്പിക്കുന്നതിനാൽ ഇത് സ്ഥിരസ്ഥിതിയായി പ്രവർത്തനരഹിതമാക്കിയിരിക്കുന്നു.

## കസ്റ്റം ഗാർഡ്റെയിലുകൾ

```typescript
import { BaseGuardrail, guardrailRegistry } from "@/lib/guardrails";

class BudgetGuardrail extends BaseGuardrail {
  constructor() {
    super("budget", { priority: 50 });
  }

  async preCall(payload, ctx) {
    if (ctx.apiKeyInfo?.budgetExceeded) {
      return { block: true, message: "Daily budget exceeded" };
    }
    return { block: false };
  }
}

guardrailRegistry.register(new BudgetGuardrail());
```

ഘട്ടങ്ങൾ:

1.  `BaseGuardrail` വികസിപ്പിച്ച് `src/lib/guardrails/myGuardrail.ts` ഉണ്ടാക്കുക.
2.  `preCall`, `postCall` എന്നിവ നടപ്പിലാക്കുക.
3.  ഇറക്കുമതി ചെയ്യുന്ന സമയത്ത് ( `registerDefaultGuardrails` ൽ നിന്ന് പുഷ് ചെയ്യുക) അല്ലെങ്കിൽ റൺടൈമിൽ `guardrailRegistry.register(...)` വിളിക്കുക — രജിസ്ട്രി, അതേ സാധാരണവൽക്കരിച്ച പേരുള്ള മുൻ ഗാർഡ്റെയിലിനെ മാറ്റിസ്ഥാപിക്കും.
4.  `tests/unit/` ന് കീഴിൽ ടെസ്റ്റുകൾ ചേർക്കുക (നിലവിലുള്ള ഉദാഹരണങ്ങൾ: `tests/unit/guardrails-registry.test.ts`, `tests/unit/prompt-injection-guard.test.ts`, `tests/unit/guardrails/visionBridge.test.ts`).

## പരിശോധന

അറിയപ്പെടുന്ന അവസ്ഥയിൽ നിന്ന് ആരംഭിക്കാൻ ടെസ്റ്റുകൾക്കിടയിൽ `resetGuardrailsForTests()` ഉപയോഗിക്കുക. ശൂന്യമായ ഒരു രജിസ്ട്രിയിൽ നിന്ന് ആരംഭിച്ച്, പരിശോധനയിലുള്ള ഗാർഡ്റെയിലുകൾ മാത്രം രജിസ്റ്റർ ചെയ്യാൻ `{ registerDefaults: false }` നൽകുക. വിഷൻ ബ്രിഡ്ജ് ഡിപൻഡൻസി ഇൻജക്ഷൻ (`deps.getSettings`, `deps.callVisionModel`) സ്വീകരിക്കുന്നു; ഓഡിയോ ബ്രിഡ്ജ് ക്രമീകരണങ്ങൾ, കഴിവുകൾ, STT മോഡൽ തിരഞ്ഞെടുക്കൽ, ക്രെഡൻഷ്യൽ പരിശോധനകൾ, ട്രാൻസ്ക്രിപ്ഷൻ എന്നിവയ്ക്കായി സമാനമായ സീമുകൾ നൽകുന്നു. അതിനാൽ, ഡാറ്റാബേസ് അല്ലെങ്കിൽ നെറ്റ്വർക്ക് ആക്സസ് ഇല്ലാതെ തന്നെ ടെസ്റ്റുകൾക്ക് രണ്ട് ഫ്ലോകളും പ്രവർത്തിപ്പിക്കാൻ കഴിയും.

- `src/shared/constants/visionBridgeDefaults.ts` — വിഷൻ ബ്രിഡ്ജ് ഡിഫോൾട്ടുകളും നിർബന്ധിത-ബ്രിഡ്ജ് മോഡൽ ലിസ്റ്റും
- `src/shared/constants/modalityBridgeDefaults.ts` — പങ്കിട്ട വിഷൻ/ഓഡിയോ റൺടൈം ഡിഫോൾട്ടുകൾ
- `docs/architecture/RESILIENCE_GUIDE.md` — ഓർത്തോഗണൽ ലെയർ (സർക്യൂട്ട് ബ്രേക്കർ, കൂൾഡൗണുകൾ)
- `docs/reference/ENVIRONMENT.md` — പൂർണ്ണമായ എൻവയോൺമെന്റ് വേരിയബിൾ റെഫറൻസ്

## ഇൻജക്ഷൻ-ഗാർഡ് റൂട്ട് കവറേജ് & റെഡ്-ടീം (ഘട്ടം 8 · ബ്ലോക്ക് D)

ഇൻജക്ഷൻ-ഗാർഡ് (`createInjectionGuard` / `withInjectionGuard`) ഉപയോക്തൃ പ്രോംപ്റ്റുകൾ സ്വീകരിക്കുന്ന എല്ലാ റൂട്ടുകളെയും ഉൾക്കൊള്ളുന്നു. ഇത് `INJECTION_GUARD_MODE` നെ മാനിക്കുന്നു (സ്ഥിരസ്ഥിതി `warn` = ലോഗ് മാത്രം; `block` = HTTP 400 `SECURITY_001` തിരികെ നൽകുന്നു).

| തരം             | റൂട്ടുകൾ                                                                                                                                      | സ്ഥിരസ്ഥിതി മോഡ് |
| :-------------- | :-------------------------------------------------------------------------------------------------------------------------------------------- | :--------------- |
| Text (existing) | `/v1/chat/completions`, `/v1/completions`, `/v1/relay/chat/completions`                                                                       | warn             |
| Generative      | `/v1/messages`, `/v1/responses`, `/v1/images/generations`, `/v1/edits`, `/v1/videos/generations`, `/v1/music/generations`, `/v1/audio/speech` | warn             |
| Data            | `/v1/embeddings`, `/v1/rerank`, `/v1/search`, `/v1/moderations`                                                                               | warn             |

ടെക്സ്റ്റ് എക്സ്ട്രാക്ഷൻ (`extractMessageContents`) `messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system` എന്നിവയെ ഉൾക്കൊള്ളുന്നു.

**റെഡ്-ടീം (രാത്രികാല, `nightly-llm-security.yml`):** `INJECTION_GUARD_MODE=block` ആയിരിക്കുമ്പോൾ ഓരോ റൂട്ടും OWASP-LLM കോർപ്പസിനെ തടയുന്നുവെന്ന് promptfoo സാധൂകരിക്കുന്നു; garak പ്രോബുകൾ പ്രവർത്തിപ്പിക്കുന്നു (രഹസ്യമില്ലാതെ ഒഴിവാക്കുന്നു). സ്ഥിരതയ്ക്കായി `moderations` ഉൾപ്പെടുത്തിയിട്ടുണ്ട് — ബ്ലോക്ക്-മോഡിലുള്ള ഓപ്പറേറ്റർമാർക്ക് `resolveDisabledGuardrails` വഴി ഇതിനെ ഒഴിവാക്കാം.

രാത്രികാല വർക്ക്ഫ്ലോ (`.github/workflows/nightly-llm-security.yml`, cron + മാനുവൽ ഡിസ്പാച്ച്) ന് രണ്ട് ജോലികളുണ്ട്:

- **`promptfoo-guard` (തടയുന്നത്)** — `INJECTION_GUARD_MODE=block` ഉപയോഗിച്ച് `promptfoo eval -c promptfooconfig.yaml` പ്രവർത്തിപ്പിക്കുന്നു. ഓരോ പ്രതികൂല സാഹചര്യവും (ഉദാഹരണത്തിന്, "മുമ്പത്തെ എല്ലാ നിർദ്ദേശങ്ങളും അവഗണിക്കുക...", DAN-ശൈലിയിലുള്ള ജയിൽബ്രേക്കുകൾ) പ്രതികരണത്തിൽ `error.code === "SECURITY_001"` ഉണ്ടെന്ന് ഉറപ്പാക്കുന്നു, അതായത് ഗാർഡ് യഥാർത്ഥത്തിൽ അഭ്യർത്ഥന നിരസിച്ചു.
- **`garak` (ഉപദേശക)** — ഒരു പ്രാദേശിക OmniRoute ഇൻസ്റ്റൻസിനെതിരെ (`http://localhost:20128/v1`) garak `--probes promptinject,dan,leakreplay` പ്രവർത്തിപ്പിക്കുന്നു. ഒരു പ്രൊവൈഡർ രഹസ്യം (`PROMPTFOO_PROVIDER_KEY`) വഴി നിയന്ത്രിക്കപ്പെടുന്നു; ഇത് ഭംഗിയായി ഒഴിവാക്കുകയും `|| true` എന്ന് ചേർക്കുകയും ചെയ്യുന്നു, അതിനാൽ CI പരാജയപ്പെടാതെ റിപ്പോർട്ട് ചെയ്യുന്നു.

ഗാർഡ് ഹെൽപ്പറിന്റെ (`createInjectionGuard` / `withInjectionGuard`) കവറേജ് എല്ലാ പ്രോംപ്റ്റ്-ഉൾക്കൊള്ളുന്ന `/v1` റൂട്ടുകളിലും വ്യാപിക്കുന്നു; പ്രോംപ്റ്റ് ടെക്സ്റ്റ് `src/shared/utils/inputSanitizer.ts` ലെ `extractMessageContents()` വഴി `messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system` എന്നിവയിൽ നിന്ന് വലിച്ചെടുക്കുന്നു.
