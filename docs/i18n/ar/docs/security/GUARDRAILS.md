تفرض الحواجز (Guardrails) السلامة والسياسة وتحويلات المحتوى عند الحدود
بين OmniRoute ومقدمي الخدمة المصدر. يمكن لكل حاجز فحص (ورفض أو تحويل أو إضافة تعليق اختياريًا) حمولات الطلبات (`preCall`)
واستجابات المصدر (`postCall`).

النظام **مفتوح عند الفشل (fail-open)**: إذا ألقى حاجز خطأ أثناء التنفيذ، فإن السجل
يسجل الخطأ ويستمر مع الحاجز التالي بدلاً من إفشال الطلب.
المنع هو قرار صريح (`block: true`)، وليس حادثًا أبدًا.

يحمّل السجل تلقائيًا ستة حواجز حماية حسب ترتيب الأولوية عند الاستيراد
(راجع `registry.ts` ← `registerDefaultGuardrails()`):

| الأولوية | الاسم               | المرحلة (المراحل) | الملف                 |
| -------- | ------------------- | ----------------- | --------------------- |

| `6`      | `audio-bridge`      | `preCall`         | `audioBridge.ts`      |

### جسر الرؤية (`visionBridge.ts`) — جسر الوسائط PR-1

يعترض الطلبات التي تحتوي على صور والموجّهة إلى **نماذج لا تدعم الرؤية**، ثم إما
يعيد توجيه الطلب بالكامل إلى نموذج يدعم الرؤية، أو يستبدل أجزاء الصور
بأوصاف نصية ينتجها نموذج رؤية قابل للتهيئة قبل إجراء
الاستدعاء إلى الخدمة الأصلية. يتيح ذلك لموفّري النماذج النصية فقط معالجة
الحمولات متعددة الوسائط بشفافية.

التدفق:

1. التخطي إذا كان النموذج المستهدف يدعم الرؤية بالفعل (ما لم يكن مدرجًا في
   قائمة الجسر الإلزامي `isVisionBridgeForcedModel`).
2. استخراج أجزاء الصور عبر `extractImageParts(messages)`
   (`visionBridgeHelpers.ts`)، التي تفوّض المهمة إلى **كاشف الوسائط
   الموحّد** `detectMediaParts()` في `open-sse/utils/mediaParts.ts` — وهو
   مصدر الحقيقة الوحيد المشترك مع مرشح توافق combo.
   يقتصر الاستخراج، عبر قائمة سماح، على الأجزاء ذات المستوى الأعلى وبالأشكال
   التي تستطيع `replaceImageParts` إعادة إدراجها (عقد الاستخراج↔الاستبدال):‏ OpenAI
   `image_url`، وAnthropic base64 بقيمة `source.type:"base64"`، وعنوان URL في Anthropic
   بقيمة `source.type:"url"`، وResponses API ‏`input_image`. أما النتائج المتداخلة
   والأشكال الدلالية فقط فهي مخصّصة لمرشح combo ولا تُستخرج مطلقًا.
   يتم التخطي إذا لم يُعثر على أي منها.
3. تحديد تهيئة وقت التشغيل عبر `resolveVisionBridgeRuntimeSettings()`
   (`src/shared/constants/modalityBridgeDefaults.ts`): تكون لمفاتيح إعدادات
   `modalityBridge*` الجديدة الأولوية؛ بينما تظل مفاتيح `visionBridge*` القديمة
   **خيارًا احتياطيًا لدورة واحدة** (نافذة التراجع). يتم التخطي قبل أي اجتياز
   للوسائط عندما يكون الجسر معطّلًا.
4. يحدد منتقي الوضع (`modalityBridgeVisionMode`، راجع الجدول أدناه)
   ما إذا كان سيتم إعادة التوجيه أم الوصف. تُرجع إعادة التوجيه `modifiedPayload`
   مع تبديل `model` فقط، بالإضافة إلى البيانات الوصفية
   `{ rerouted, fromModel, toModel, imagesKept }`.
5. مسار الوصف: يحدّ عدد الصور عند `maxImages`، وينشئ المطالبة المدركة للمهمة،
   ويراجع ذاكرة التخزين المؤقت للوصف، ويستدعي نموذج الرؤية **بالتوازي**
   (`Promise.allSettled`)، ثم يحقن أجزاء نصية بالصيغة
   `[الصورة N]: <الوصف>` مكانها. يؤدي فشل الوصف إلى `null`، ويُحتفظ بجزء الصورة
   الأصلي **دون تغيير** (#4012) — باستثناء مسار وصف combo عندما تفشل جميع
   عمليات الوصف، إذ تتلقى الخدمة الأصلية التي تأكد أنها لا تدعم الرؤية نصًا
   بديلًا `(غير متاح — لا يوجد موفّر يدعم الرؤية متصل)` بدلًا منه (#8430).
6. إرجاع `modifiedPayload` مع البيانات الوصفية (`imagesProcessed`، و`descriptions`،
   و`processingTimeMs`، و`visionModel`).

#### منتقي الوضع (`modalityBridgeVisionMode`)

| الوضع      | الافتراضي | السلوك                                                                                                                                                                                                                                                        |
| ---------- | --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `auto`     | ✔         | الاستدلال القديم دون تغيير (#6640/#7204): يُعاد توجيه نماذج non-combo/`auto/` إلى أفضل نموذج رؤية، ما لم تكن لدى النموذج الأصلي بيانات اعتماد صالحة للاستخدام (وعندئذٍ يُستخدم الوصف)؛ أما أهداف combo فتستخدم الوصف دائمًا.                                  |
| `describe` |           | يستخدم الوصف دائمًا — يتم تخطي كتلة إعادة التوجيه بالكامل؛ ويظل النموذج الذي اختاره المستخدم هو من يجيب دائمًا.                                                                                                                                               |
| `reroute`  |           | يفرض إعادة التوجيه: يتم تجاوز حاجز الاحتفاظ بالنموذج ذي بيانات الاعتماد. ويظل حاجز بيانات اعتماد **هدف** إعادة التوجيه مطبقًا — فعندما لا يتوفر هدف رؤية صالح للاستخدام، ينتقل الطلب إلى الوصف كي لا تصل الصور الخام مطلقًا إلى واجهة خلفية نصية فقط (#8430). |

تتجاوز الأوضاع المفروضة المسار **قبل** تشغيل الاستدلال التلقائي؛ ويظل سلوك `auto`
مطابقًا على مستوى البايتات لحاجز الحماية السابق لـ PR-1.

#### نطاق مفتاح API (`visionBridgeKeyScope.ts`)

عندما يقيّد مفتاح API الخاص بالمتصل `allowedConnections`، أو مجموعات الحصص
(`allowedQuotas`)، أو النماذج (`allowedModels` / `blockedModels` /
`modelAccessMode: "restricted"` / `disableNonPublicModels`)، لا يختار الجسر
نماذج إعادة التوجيه والوصف إلا من النماذج التي يُسمح للمفتاح باستخدامها، وعلى
الاتصالات التي يُسمح له باستخدامها. بعد ذلك، يمر استدعاء الوصف دائمًا عبر
الحلقة الذاتية لـ OmniRoute مع ترويسة `x-omniroute-self-loop-key-id`، بحيث
يفرض طلب الدردشة المستقبِل سياسة الاتصال والنماذج الخاصة بذلك المفتاح مرة
أخرى. لا يعتمد `enforceApiKeyPolicy()` هذه الترويسة إلا مع رمز bearer الخاص
بالحلقة الذاتية، ولذلك لا يمكنها سوى تضييق نطاق الوصول، ويُرفض أي معرّف لا
يمكن التحقق منه.

إذا لم يكن أي نموذج رؤية مسموحًا للمفتاح، يتنحى مسار الوصف ويمر الطلب دون
تغيير، وهو سلوك الفتح عند الفشل نفسه المستخدم مع حاجز حماية معطّل
(البيانات الوصفية `{ skipped: true, reason: "no_permitted_vision_model" }`).
تتصرف الطلبات التي لا تحتوي على مفتاح، والمفاتيح التي لا تخضع لهذه القيود،
تمامًا كما كانت من قبل.

#### مطالبة الوصف المدركة للمهمة (`modalityBridgeVisionTaskAware`)

القيمة الافتراضية هي **true**. تُلحق `composeVisionPrompt()` ‏(`visionBridgeHelpers.ts`)
نص **آخر رسالة للمستخدم** (بعد اقتطاعه إلى 500 محرف) بموجّه الوصف
الأساسي، ما يوجّه الوصف نحو ما طلبه المستخدم فعليًا
(نمط codex-vision-proxy)، ويطلب من نموذج الرؤية نسخ النص المرئي.
عند تعطيل العلامة — أو في حال عدم وجود نص للمستخدم — يُستخدم الموجّه الأساسي دون تغيير.

يطلب طلب الوصف الذاتي المتكرر المتوافق مع OpenAI والخاص به (`callVisionModelSingle()`
في `visionBridgeHelpers.ts`) دائمًا `image_url.detail: "high"` —
دون أي شرط، لكل مستدعٍ/موفّر، ومن دون الاعتماد على أي إشارة من العميل.
يؤدي أخذ العينات منخفضة التفاصيل إلى تدهور دقة OCR في مهمة نسخ النص تحديدًا
التي يطلبها هذا الموجّه، ولذلك يطلب استدعاء الوصف نفسه دائمًا تفاصيل عالية
بغض النظر عن مستوى التفاصيل الذي استخدمه الطلب الوارد الأصلي. يؤثر هذا
فقط في جسم طلب الوصف الداخلي؛ ولا يغيّر كيفية تمرير
OmniRoute لقيمة `image_url.detail` الخاصة بالمستدعي ضمن الطلب الأساسي —
إذ تُطبَّق تلك القيمة الافتراضية بصورة منفصلة، ولعملاء OpenCode المكتشفين فقط، في
`defaultImageDetail()` ‏(`open-sse/handlers/chatCore/upstreamBody.ts`). لا يحتوي
فرع تنسيق Anthropic السلكي ضمن التكرار الذاتي للوصف على حقل `detail`
ولا يتأثر بأي من القيمتين الافتراضيتين.

#### الحد الأقصى لمخرجات الوصف (`modalityBridgeVisionMaxChars`)

| المفتاح                        | القيمة الافتراضية | النطاق           |
| ------------------------------ | ----------------- | ---------------- |
| `modalityBridgeVisionMaxChars` | `0`               | `0` أو 100–50000 |

تعني القيمة `0` (الافتراضية) **عدم وجود حد أقصى** — إذ يُمرَّر الوصف الذي تعيده
`callVisionModel()` دون تعديل، مع الحفاظ على السلوك الحالي.
تؤدي أي قيمة ضمن النطاق 100–50000 إلى اقتطاع الوصف وإضافة اللاحقة
`…` قبل إدراجه مجددًا بالصيغة `[Image N]: <description>`
(`VisionBridgeGuardrail.preCall()` في `src/lib/guardrails/visionBridge.ts`).
ارفع هذه القيمة لمهام OCR كثيفة التفاصيل التي يحتاج فيها النموذج اللاحق إلى
النص المنسوخ كاملًا؛ واخفضها لضبط استهلاك الرموز مع نماذج الرؤية كثيرة الإسهاب.
يوجد حقل لوحة المعلومات في لوحة الإعدادات المتقدمة ضمن علامة التبويب Vision
(`modality-bridge-max-chars` في `ModalityBridgeVisionTab.tsx`)، ويضبط أي
قيمة بين 1 و99 إلى الحد الأدنى 100، مع ترك القيمة الصريحة `0`
دون تغيير — فالقيمة `0` هي قيمة Zod صالحة بحد ذاتها
(`z.union([z.literal(0), z.number().int().min(100).max(50000)])`)، وليست مجرد
قيمة افتراضية تشير إلى «غير معيّن».

#### ذاكرة الوصف المؤقتة (`modalityBridge/bridgeCache.ts`)

ذاكرة تخزين مؤقت داخل الذاكرة من نوع LRU + TTL لمخرجات الوصف، مشتركة على مستوى العملية بأكملها.
المفتاح = `sha256(imageRef + composedPrompt + configuredBridgeModel)` مع
تأطير مسبوق بالطول (من دون تصادمات عند حدود الحقول). مكوّن النموذج هو
نموذج الجسر **المُعدّ**، وليس النموذج الذي أجاب فعليًا —
فقد تلجأ `callVisionModel` إلى نموذج احتياطي داخليًا، وسيؤدي إنشاء مفتاح لكل محاولة
إلى تجزئة ذاكرة التخزين المؤقت. لا تُخزَّن عمليات الوصف الفاشلة مؤقتًا مطلقًا. الإعدادات:

| المفتاح                         | القيمة الافتراضية | النطاق  |
| ------------------------------- | ----------------- | ------- |
| `modalityBridgeCacheEnabled`    | `true`            | —       |
| `modalityBridgeCacheTtlMinutes` | `60`              | 1–1440  |
| `modalityBridgeCacheMaxEntries` | `200`             | 10–5000 |

#### تسوية الصور البعيدة (الوصف الذاتي المتكرر/جلب base64)

عندما يجلب الجسر صورة **بعيدة** بنفسه — سواء لاستدعاء الوصف الذاتي
الخاص بـ Anthropic أو لتحويل base64 بتنسيق claude السلكي
(`ensureBase64ImagesForClaudeWire`)، وكلاهما عبر
`fetchRemoteImageAsDataUri()` في `visionBridgeHelpers.ts` — يُمرَّر معرّف URI
للبيانات الناتج عبر `normalizeDataUri()`
(`open-sse/utils/imageNormalize.ts`) قبل تضمينه في طلب نموذج الرؤية.
يُعاد تصغير الصور المفرطة في الحجم بحيث يصبح **الضلع الأطول 2048px** (بما يطابق
حد إعادة التحجيم الذي تطبّقه OpenAI/Anthropic بالفعل من جهة الخادم)، ما يقلل
حجم بايتات الرفع وزمن الانتقال دون تغيير ما يراه نموذج الرؤية. تستخدم عملية إعادة التحجيم
`sharp`، الذي يُحمَّل عبر استيراد ديناميكي: وعلى المنصات التي يتعذر فيها تحميل
ملفه الثنائي الأصلي، فإن `normalizeDataUri()` **لا تطرح استثناءً مطلقًا** — بل تعود
إلى تمرير البايتات الأصلية كما هي، بحيث يظل مسار الوصف/تحويل base64
عاملًا دائمًا. كما تُمرَّر البايتات التي لا تمثل صورة (أي عملية جلب لم تُعد
صورة قابلة لفك الترميز) دون تغيير. تقتصر هذه التسوية
على الصور التي يجلبها الجسر لاستدعائه الذاتي — ولا تُطبَّق مطلقًا
على حمولة التمرير الأولية الخاصة بالمستدعي، بما يتوافق مع
مبدأ عدم التعديل إلا بالاشتراك الصريح (القاعدة الصارمة رقم 20).

#### مخطط الإعدادات + الترحيل

يتم التحقق من صحة مفاتيح `modalityBridge*` الجديدة باستخدام Zod في `updateSettingsSchema`
(`src/shared/validation/settingsSchemas.ts`): وهي `modalityBridgeVisionEnabled`،
و`modalityBridgeVisionMode`، و`modalityBridgeVisionModel`،
و`modalityBridgeVisionTaskAware`، و`modalityBridgeVisionPrompt`،
و`modalityBridgeVisionTimeout`، و`modalityBridgeVisionMaxImages`،
و`modalityBridgeVisionMaxChars`، وثلاثية `modalityBridgeCache*`، ومجموعة
`modalityBridgeAudio*` التي يستخدمها Audio Bridge. ينسخ الترحيل
`141_modality_bridge_settings.sql` قيم `visionBridge*` القديمة الموجودة
إلى المفاتيح الجديدة المطابقة (وهو متكرر آمنًا، ولا يستبدل مطلقًا قيمة
`modalityBridge*` عيّنها المشغّل)؛ وتظل المفاتيح القديمة مقبولة بوصفها
خيارًا احتياطيًا للقراءة طوال دورة إصدار واحدة.

#### ترويسة الشفافية + الإحصاءات

تحمل الاستجابات المحوّلة بواسطة الوصف الترويسة
`x-omniroute-modality-bridge: image->text;model=<visionModel>;parts=<n>`
(التي تنشئها `buildModalityBridgeHeader()` في `modalityBridge/bridgeStats.ts`،
وتضيفها `withModalityBridgeHeader()` في `src/sse/handlers/chatHelpers.ts`).
لا تحصل الطلبات المعاد توجيهها على **أي** ترويسة — إذ لم تتغير الحمولة، كما أن تبديل
النموذج ظاهر بالفعل في حقل `model` ضمن جسم الاستجابة.

يعيد `GET /api/modality-bridge/stats` (بمصادقة إدارية، وبالمستوى نفسه الذي يستخدمه
`GET /api/settings`) العدّادات الموجودة في الذاكرة لكل نمط
`{ attempts, successes, bridged, cacheHits, failures, totalLatencyMs,
latencySamples, averageLatencyMs, lastUsedAt }` للأنماط `vision` و`audio` و
`video`. يستخدم `averageLatencyMs` قيمة `latencySamples` مقامًا، وليس جميع
المحاولات؛ فالعملية التي لا تحتوي على قياس زمني لا تنشئ عينة وهمية مدتها صفر
مللي ثانية. يظل `bridged` اسمًا مستعارًا متوافقًا مع الإصدارات السابقة لعمليات
التحويل الناجحة؛ ولا تؤدي المحاولات الفاشلة إلى زيادته.
تُصفّر العدّادات عند إعادة تشغيل العملية حسب التصميم
(بيانات قياس عن بُعد، وليست محاسبة).

#### إعداد لوحة المعلومات

صفحة لوحة المعلومات المخصصة هي
`/dashboard/settings/modality-bridge`. تحافظ علامات التبويب `Vision` و`Audio`
و`Video`، التي يمكن الوصول إليها عبر عنوان URL، على معاملات الاستعلام عند تبديل
قيمة `tab`.
تتيح علامة التبويب Vision التفعيل والوضع واختيار النموذج (بما في ذلك الإعداد
الافتراضي التلقائي) والتوجيه المراعي للمهمة وحدود المهلة/الصورة/طول الوصف/ذاكرة
التخزين المؤقت المتقدمة، بالإضافة إلى عدّادات وقت التشغيل وطلب عينة محمي.
علامة التبويب Audio فعّالة أيضًا: فهي تتيح التفعيل ومنتقي نماذج مخصصًا لـ STT
فقط مع الخيار Auto، وحدود المهلة/الحد الأقصى للمقطع، وعدّادات الصوت، واختبار
عينة `input_audio`. علامة التبويب Video وظيفية: فهي تعرض حالة وقت تشغيل
FFmpeg/ffprobe — وهي واحدة من أربع حالات صريحة لواجهة المستخدم (`unknown` أثناء
تنفيذ الفحص أو عند تعذّر إكماله، و`restricted` على مضيف لوحة معلومات غير
استرجاعي حيث يُتخطى الفحص من جانب العميل، و`unavailable` بعد إجراء الفحص
والتأكد من عدم توفره، أو `available` مع إصداري FFmpeg/ffprobe) — وتحفظ حدود
التفعيل/النموذج/الإطارات/الفيديو/المهلة، وترشّح منتقي النماذج ليقتصر على النماذج
القادرة على معالجة الرؤية، وتعرض عدّادات الفيديو.

أصبحت بطاقة Vision Bridge السابقة ضمن إعدادات AI رابط توافق إلى الصفحة
الجديدة؛ ولم تعد تمتلك نسخة ثانية من النموذج. يربط Media Providers أيضًا
سيرَي عمل Image-to-Text وSpeech-to-Text بعلامتي تبويب Modality Bridge
المقابلتين، من دون إزالة بيئة اختبار Speech-to-Text الحالية.

**تجاوز قبول الحلقة الذاتية:** عندما يُوجَّه استدعاء الوصف عبر الحلقة الذاتية
`/v1` الخاصة بـ OmniRoute (نموذج موفّر غير قياسي)، يرسل الطلب الفرعي
`x-omniroute-admission-bypass: internal` وتُجرى مصادقته باستخدام بيانات اعتماد
الحلقة الذاتية المحلولة — القيمة المحلية الخاصة `sk_omniroute` في الوضع
المحلي، أو مفتاح البيئة `OMNIROUTE_API_KEY` / `ROUTER_API_KEY` الذي يضبطه
المشغّل (#1350)، بحيث يظل بإمكان عمليات النشر التي تستخدم
`REQUIRE_API_KEY=true` تنفيذ استدعاء الوصف. لا يُعتد بالتجاوز إلا مع بيانات
الاعتماد المطابقة تمامًا، ولذلك لا يمكن للعملاء الخارجيين استخدام الترويسة
لتجاوز القبول.

توجد الإعدادات الافتراضية القديمة في `src/shared/constants/visionBridgeDefaults.ts`؛
بينما توجد الإعدادات الافتراضية الجديدة للوضع/مراعاة المهمة/ذاكرة التخزين
المؤقت ومحلّل الإعدادات في
`src/shared/constants/modalityBridgeDefaults.ts`. يوفّر حاجز الحماية خيار
المُنشئ `deps` كي تتمكن الاختبارات من حقن تنفيذات زائفة لـ `getSettings` و
`callVisionModel`.

### جسر الصوت (`audioBridge.ts`) — Modality Bridge PR-3

يعترض طلبات المحادثة التي تحتوي على صوت قبل وصولها إلى هدف غير معروف بقبوله
إدخالًا صوتيًا. ولا يعيد مطلقًا توجيه طلب المحادثة: تُنسخ الأجزاء الصوتية
نصيًا عبر نقطة النهاية الحالية متعددة الأجزاء والمتوافقة مع OpenAI، ويواصل
نموذج المحادثة المختار العمل باستخدام النصوص المنسوخة.

التدفق:

1. حلّ `supportsAudio` عبر `getResolvedModelCapabilities()`. تكون الأولوية
   لبيانات التعريف الصريحة في سجل الموفّرين، ثم بيانات تعريف النموذج الثابتة،
   ثم `modalities_input` المتزامنة. تكون قائمة الإدخال المعلنة التي لا تحتوي
   على `audio` مساوية لـ `false`؛ وإذا لم يتبقَ أي دليل على الإمكانية، تكون
   القيمة `null`. تُفعّل كل من `false` و`null` الجسر المتحفظ، بينما تتجاوزه
   القيمة `true`.
2. حلّ إعدادات `modalityBridgeAudio*` واستخراج أجزاء الصوت ذات المستوى الأعلى
   والقابلة للوَصل من كل رسالة عبر الكاشف المشترك `detectMediaParts()`.
   أشكال النقل المدعومة هي `input_audio` و`audio_url` في OpenAI، و
   `source.media_type: "audio/*"`. يُكتشف الصوت المتداخل لأغراض التوجيه، لكنه
   لا يُزال عبر مسار الوَصل. يُقيَّد العمل بواسطة
   `modalityBridgeAudioMaxClips`؛ وتبقى الأجزاء اللاحقة دون تغيير.
3. الالتزام بقيمة `provider/model` المضبوطة، أو السماح لـ
   `selectAudioBridgeModel()` بالمرور على `AUDIO_TRANSCRIPTION_PROVIDERS`
   وفق ترتيب الكتالوج الثابت واختيار أول نموذج تتوفر له بيانات اعتماد صالحة
   لموفّر نشط.
4. تحوّل `callAudioTranscription()` الصوت بترميز base64 أو بصيغة data-URI إلى
   `file` متعدد الأجزاء، أو تنزّل `audio_url` بعيدًا عبر حاجز الاتصالات
   الصادرة العامة فقط مع تثبيت DNS وحد أقصى يبلغ 25 MB. ثم ترسل الملف والنموذج
   المحدد عبر POST إلى الحلقة الذاتية المحلية `/v1/audio/transcriptions`،
   مع المصادقة باستخدام `resolveSelfLoopBearer()`. ينفّذ مسار النسخ الحالي
   البحث المعتاد عن بيانات الاعتماد، ومعالجة فترات التهدئة/حدود المعدل،
   والتوجيه إلى الموفّر.
5. تستبدل الاستدعاءات الناجحة أجزاءها بـ `[Audio N]: <transcript>`. تُنفَّذ
   الاستدعاءات باستخدام `Promise.allSettled`: يحافظ فشل فردي على جزء الصوت
   الأصلي ذاك (عقد #4012). إذا فشلت جميع الاستدعاءات وثبت أن الهدف يحقق
   `supportsAudio === false`، تصبح الأجزاء
   `[Audio N]: (unavailable — no STT provider connected)` (عقد #8430). أما
   بالنسبة إلى هدف غير معروف (`null`)، فتبقى النتيجة دون تغيير عند فشل جميع
   الاستدعاءات. ويتلقى الهدف الذي ثبت أنه نصي فقط ولا يمتلك بيانات اعتماد STT
   صالحة العنصر النائب الصريح نفسه من دون إصدار استدعاء شبكي.

تستخدم النصوص المنسوخة بنجاح ذاكرة التخزين المؤقت LRU/TTL الخاصة بـ Modality
Bridge على مستوى العملية. يجمع المفتاح بين مرجع الصوت وتسمية العملية الثابتة
`audio-transcription` ونموذج STT المحدد؛ ولا تُخزّن حالات الفشل مؤقتًا مطلقًا.
تحدّث محاولات الصوت العدّادات المشتركة `bridged` و`cacheHits` و`failures` و
`lastUsedAt`.
تحمل الاستجابات المحوّلة
`x-omniroute-modality-bridge: audio->text;model=<sttModel>;parts=<n>`؛ ولا
تتلقى الطلبات التي لم تتغير مقطع Audio Bridge.

تستند إعدادات وقت التشغيل إلى قاعدة البيانات ويجري التحقق منها باستخدام Zod:

| المفتاح                       | الافتراضي | النطاق              |
| ----------------------------- | --------- | ------------------- |
| `modalityBridgeAudioEnabled`  | `true`    | —                   |
| `modalityBridgeAudioModel`    | `""`      | تلقائي أو معرّف STT |
| `modalityBridgeAudioTimeout`  | `60000`   | 1000–300000         |
| `modalityBridgeAudioMaxClips` | `3`       | 1–10                |

تظل ذاكرة التخزين المؤقت المشتركة خاضعة للتحكم بواسطة `modalityBridgeCacheEnabled`،
و`modalityBridgeCacheTtlMinutes`، و`modalityBridgeCacheMaxEntries`.

### جسر الفيديو (`videoBridge.ts`، `videoBridgePipeline.ts`)

يعترض أجزاء الفيديو ذات المستوى الأعلى في `messages` الخاصة بواجهات Chat Completions وفي
`input` الخاصة بواجهة Responses API قبل استدعاء وجهة لا يُعرف أنها تدعم الفيديو دعمًا أصليًا.
تشمل الأشكال المدعومة `input_video`، و`video_url`، و`video_source`، وعناوين URL التي تستخدم HTTPS،
ومعرّفات URI للبيانات بالصيغة `data:video/*;base64,...`. لا تُعامل أسماء الملفات المجردة في النص
على أنها فيديو.

يتولى `VideoBridgeGuardrail.preCall` (`videoBridge.ts`) اجتياز الطلب،
والتحقق من الإمكانية/السياسة، والتجميع لكل طلب، وحمولة الاستجابة.
أما العمل الخاص بكل فيديو — جلبه، وذاكرة التخزين المؤقت للنتيجة الكاملة، ووصف تسلسل الإطارات
(الذي يدمج أي نص منسوخ للصوت صرّح به المستدعي)، ومقاييس/إلغاء/تنظيف كل محاولة —
فهو مخفي خلف `processVideoPart` في
`videoBridgePipeline.ts`، الذي يُستدعى مرة واحدة لكل جزء فيديو داخل حلقة `preCall`.
تعرّف هذه الوحدة أيضًا حدود المنافذ الصريحة `VideoMediaBrokerPort`
(لجلب البايتات واستخراج الإطارات المأخوذة كعينات)، و`VideoAudioTranscriptionPort`
(لدمج النص المنسوخ للصوت الذي صرّح به المستدعي مع شروح الإطارات المأخوذة كعينات)، و
`VideoDrilldownPort` (حد استمرارية التخزين للاستقصاء التفصيلي للإطارات؛ ولم يُوصَل بعد
بـ`processVideoPart` — إذ إن مسار `/api/modality-bridge/video/drilldown`
المنفصل وحده هو الذي يكتب إدخالات الاستقصاء التفصيلي حاليًا).

لا يستورد مسار الطلب العام `/v1` أي عملية فرعية ولا يستدعيها مطلقًا. تُنزّل
مقاطع الفيديو البعيدة ضمن حد قدره 50 MiB؛ وتخضع مقاطع الفيديو المضمنة بترميز base64
لحد محافظ قدره 36 MiB بعد فك الترميز لكل فيديو، بحيث يمكن أن يظل غلاف
النموذج/الرسائل/التأطير ضمن حد قبول طلب JSON العام البالغ 50 MiB. يُتحقق من
الطول المضمن وتقديرات الحجم بعد فك الترميز قبل التخصيص. يُشترط HTTPS في
عنوان URL البعيد الأولي وفي كل عملية إعادة توجيه، باستخدام حارس الاتصالات الصادرة الحالي
المقتصر على الوجهات العامة مع تثبيت DNS. ثم تعبر البايتات حد الوسيط الداخلي المحدد بدقة
`POST /api/modality-bridge/video/extract`. هذا المسار موسوم بكل من
`LOCAL_ONLY` و`SPAWN_CAPABLE`، ولا يقبل إلا طلبًا موثّقًا لكل عملية
قادماً من واجهة استرجاع موثوقة، ولا يقبل أبدًا عنوان URL أو مسار نظام ملفات أو ملفًا تنفيذيًا
أو قائمة وسائط. يفرض كل من مسار معالجة حجم جسم واجهة API وقارئ الجسم التزايدي
في المعالج حدًا أقصى مستقلاً قدره 50 MiB لمدخلات الوسيط. تنفذ قائمته محدودة السعة
عملية استخراج واحدة في كل مرة، وتسمح بأربع مهام معلقة، وتضع حدًا أقصى قدره
100 MiB للمدخلات المعلقة.

داخل الوسيط، يقرأ `ffprobe` ملفًا محليًا خاصًا؛ وتستبعد القائمة الثابتة
للتنسيقات المسموح بها تنسيقات قوائم التشغيل وملفات البيان. بالنسبة إلى حاويات عائلة MOV
المسموح بها، تظل مراجع بيانات MOV الخارجية معطلة افتراضيًا، ولا يفعّلها
الأمر الثابت. يستخدم كل من `ffprobe` و`ffmpeg` قائمة بروتوكولات مسموح بها تقتصر
على `file`، وخيط تنفيذ واحدًا، ومصفوفات وسائط ثابتة، ومن دون صدفة أوامر،
مع حلّ الملفات التنفيذية من `PATH`. لا تُعد تدفقات صور الغلاف المرفقة
مرشحة قابلة للتشغيل. يجب أن تستوفي جميع التدفقات القابلة للتشغيل الحدود، ويُفضّل
التدفق الافتراضي الصريح قبل الرجوع الحتمي إلى التدفق ذي الفهرس الأدنى.
تقتصر مقاطع الفيديو على 600 ثانية، و8,192 بكسل لكل بُعد، و
33,554,432 بكسل مصدر. يأخذ FFmpeg عينات من 1–16 إطار JPEG عند نقاط المنتصف،
ويصغّر الحافة الطويلة إلى 1,024 بكسل كحد أقصى من دون تكبير المدخلات الأصغر،
ولا يتلقى عنوان URL مطلقًا. تكون سياسة أخذ العينات `uniform` افتراضيًا. تنفذ
سياستا `scene_aware` الاختيارية و`segment_aware` التجريبية تمريرة FFmpeg
ثابتة إضافية واحدة على التدفق المحلي الذي سبق التحقق منه، وتحددان طوابع زمنية محدودة
للمشاهد باستخدام `showinfo`، وتعودان بصورة حتمية إلى نقاط المنتصف المنتظمة نفسها
عند فشل الكاشف، أو انتهاء المهلة، أو وجود مخرجات مشوهة، أو فراغ مجموعة المرشحين.
يوزع وضع التقسيم المدرك عينات نقاط المنتصف تناسبيًا على فواصل المشاهد التي تم التحقق منها؛
ويرد أدناه تفصيل أدلة التقسيم المدرك وسلوك الرجوع الاحتياطي. يُطبّق الحد الأقصى الصارم
البالغ 16 إطارًا بعد التحديد في كل سياسة. عندما تكون ميزانية طلب مدرك للمشاهد
إطارًا واحدًا فقط، فإنه يستخدم نقطة المنتصف المنتظمة للفيديو الكامل النشط أو لنافذة التركيز،
ويبلّغ عن `policyEffective: uniform`: إذ لا يمكن لإطار مشهد واحد محدد أن يحافظ
على كلا الطرفين الزمنيين. يمكن للمستدعي اختياريًا توفير نافذة تركيز
محدودة (`start`/`end` بالثواني)؛ وتُقيّد الحدود بمدة الوسائط، وتُرفض النوافذ
المعكوسة أو غير المحدودة، وتُنفّذ جميع سياسات أخذ العينات داخل الفاصل المطبّع فقط.
تُضمّن النافذة الناتجة في بيانات أخذ العينات الوصفية وفي بادئة الوصف غير الموثوقة،
بحيث تستطيع النماذج اللاحقة تمييز مقتطف مركّز عن المخطط الزمني الكامل.

يُعد التركيز الدلالي للشروح إعدادًا منفصلًا وصريحًا. يحافظ وضع التحليل الافتراضي `full`
على مطالبة الإطارات الحالية ولا يمرر نص الطلب إلى نموذج الشروح مطلقًا.
في الوضع `focused`، لا يقرأ الجسر سوى أحدث `text`/`input_text` غير فارغ
أنشأه المستخدم من حاوية Chat أو Responses نفسها، ويطبّعه إلى NFC، ويختزل
محارف التحكم والمسافات البيضاء، ويقيده بـ500 نقطة ترميز Unicode. تؤدي النتيجة الفارغة
إلى الرجوع إلى مطالبة `full` المطابقة تمامًا. يُسلسل التلميح القابل للاستخدام بصيغة JSON
داخل كتلة مخصصة لسياق مستخدم غير موثوق، ولا يجوز له سوى إعطاء الأولوية للتفاصيل القابلة
للملاحظة؛ ولا يمكنه تجاوز التحذير المنفصل من اتباع التعليمات المرئية أو المسموعة
في الوسائط. لا يستنتج التركيز النصي `start`/`end` مطلقًا ولا يغيّر
آلية أخذ العينات الزمنية.

#### أدلة التقسيم الهيكلية FU-07

يستخدم `segment_aware` تمريرة تحليل مسبق واحدة محدودة على دفق الفيديو المحلي الذي تم التحقق منه مسبقًا. تبدأ سلسلة المرشحات الثابتة بتحجيم العرض إلى 320 بكسل كحد أقصى، وتكتشف تغيّرات المشاهد وفترات التجمّد، ثم تأخذ عينة بمعدل إطار واحد في الثانية لقياس الضبابية ومتوسط السطوع ومعلومات التغيّر المكاني/الزمني. تقتصر التمريرة على 600 عينة بنيوية، وخيط FFmpeg/مرشح واحد، وقوائم السماح نفسها للبروتوكول `file` فقط وللحاويات، وحدّ قدره 1 MiB لمخرجات العملية، وما لا يزيد على 30 ثانية ضمن الإلغاء/المهلة النهائية المشتركة للوسيط. ولا تقبل مطلقًا أمرًا أو مرشحًا أو مسارًا أو عنوان URL من الطلب.

القيم البنيوية هي أدلة أخذ عينات حتمية، وليست فهمًا دلاليًا للفيديو. وهي لا تستنتج الموضوعات أو الأفعال أو التسميات التوضيحية أو الكلام أو نية المستخدم. تشكّل حدود المشاهد والتجمّد مقاطع؛ ولا تؤثر تغطية التجمّد والضبابية والتعريض والتفاصيل المكانية والتغيّر الزمني إلا في كيفية توزيع ميزانية الإطارات الحالية البالغة 1–16 إطارًا. يُحدّ المقطع المتجمّد بالكامل بإطار واحد، بينما تتنافس المقاطع غير المتجمّدة على الميزانية المتبقية. عندما يفوق عدد الحدود عدد الإطارات، يُحتفظ بتغطية موحّدة للخط الزمني كي لا تتمكن الانتقالات السريعة المبكرة من إخفاء مقطع ختامي طويل. تُدمج حدود المشاهد الواقعة ضمن دقة التحليل البالغة ثانية واحدة من حد تجمّد.

يؤدي غياب المرشحات أو وجود أدلة مشوّهة/فارغة أو حدوث خطأ في الكاشف أو انقضاء مهلة التحليل المسبق المحدود إلى السماح بالمتابعة باستخدام سياسة نقاط المنتصف الموحّدة نفسها تمامًا. أما إلغاء المستدعي أو بلوغ المهلة النهائية للوسيط فلا يسمحان بالمتابعة: إذ يؤديان إلى إنهاء العملية الفرعية الجارية، ومنع استخراج الإطارات لاحقًا، وإزالة شجرة الملفات المؤقتة الخاصة في `finally`.

ينشئ `scripts/perf/video-bridge-fu07-eval.ts` تجهيزات FFmpeg فعلية وحتمية لقياس وفورات استدعاءات إنشاء التسميات التوضيحية بعد إزالة التكرار، وتوزيع الميزانية للحركة الكثيفة، وأدلة الضبابية/التعريض/SI-TI، والانتقالات السريعة ذات الذيل الطويل، والنتائج الإيجابية الزائفة للتلاشي التدريجي. ويسجّل زمن التحليل المسبق الفعلي، وحيثما يتوفر `/usr/bin/time`، وقت CPU للعملية الفرعية وذروة RSS. لا تعدو فحوصات الجودة الخاصة به كونها مراجع بنيوية. تظل جودة نموذج إنشاء التسميات التوضيحية الفعلي `HOLD` لأن أداة الاختبار هذه لا تملك نقطة نهاية مصرّحًا بها أو مُحكِّمًا ثابتًا. كما تظل الوفورات المالية `HOLD` ما لم يوفّر `--caption-cost-per-call-usd` تقديرًا صريحًا موجبًا للتكلفة لكل استدعاء؛ ولا يختلق البرنامج النصي أيًا من النتيجتين.

يُحدّ كل إطار بمقدار 4 MiB، ومجموع جميع الإطارات الخام بمقدار 23 MiB، واستجابة الوسيط المتسلسلة بمقدار 32 MiB. ويُزال دليل مؤقت خاص في `finally`. لا تضمّن OmniRoute برنامج FFmpeg ولا تقبل مسارًا مخصصًا للملف التنفيذي. قبل إنشاء التسميات التوضيحية، يطبّق الجسر تمريرة محافظة لإزالة التكرار المرئي: يُختزل كل ملف JPEG إلى مخزن مؤقت رمادي بحجم 16×16، ولا يُقارن إلا بآخر إطار تم الاحتفاظ به. بالنسبة إلى ميزانية تسميات توضيحية مطلوبة تزيد على إطار واحد، يوفّر الاستخراج مجموعة مرشحين محدودة لا تتجاوز ضعف تلك الميزانية ولا تزيد مطلقًا على 16 إطارًا. ولا يُطبّق الحد الأقصى المطلوب إلا بعد إزالة التكرار، مع الحفاظ على أول وآخر مرشحَين محددَين أثناء التقليص النهائي عندما تكون الميزانية إطارين على الأقل. تستخدم سياسة
`grayscale-16x16-mean-cells-v2` ذات الإصدار القيمة الأكبر بين متوسط فرق السطوع ونسبة خلايا الصورة المصغرة التي يبلغ فرقها المطبع 0.05 على الأقل. حد التكرار هو الثابت 0.04، وقد اختير لتوفير قابلية التنبؤ بدلًا من كشفه كإعداد في وقت التشغيل. تحافظ إشارة التباين العالي الثانوية هذه على الحركة الصغيرة وتغيّرات النص المرئي التي قد تخفيها مقارنة تعتمد على المتوسط وحده. تؤدي أخطاء المقارن أو وحدة فك الترميز إلى السماح بالمتابعة والحفاظ على التغطية. تفصل بيانات المخرجات الوصفية بين المرشحين المستخرجين، والإطارات المستخدمة بنجاح، والتكرارات المرئية المستبعَدة.

يمكن لجزء فيديو معلّم صراحةً أن يطلب لوحة صور مصغّرة ذات طوابع زمنية. ينشئ الجسر شبكة JPEG لا تزيد على 4 أعمدة و16 إطارًا. وتُثبَّت الطوابع الزمنية المصدرية لكل خلية بعرض 512 بكسل داخل شريط سفلي عالي التباين، بينما تبقى الطوابع الزمنية نفسها في البيانات الوصفية النصية لتمكين الربط والتدقيق في المراحل اللاحقة. يظل ملف JPEG الكامل محدودًا بمقدار 32 MiB. إذا تعذر على `sharp` فك ترميز الشبكة أو تركيبها، يعود الجسر إلى إطارات JPEG الفردية؛ ويظل إلغاء العميل ممتدًا عبر عملية إنشاء اللوحة.

تُفصل أدلة الترقية عمدًا عن الاختبار المصغّر التركيبي للتركيب. يعرّف `scripts/perf/video-bridge-contact-sheet-eval.ts` أداة اختبار A/B ذات مخطط محدد الإصدار لنماذج الرؤية الفعلية المتوافقة مع OpenAI. وتقيس الرموز التي يبلّغ عنها المزوّد، وزمن الاستجابة الكلي من البداية إلى النهاية بما في ذلك تركيب اللوحة، وعدد استدعاءات النموذج، والاحتفاظ بالحقائق المحددة في ملف البيان. لا تُكتب استجابات النموذج الخام في التقرير؛ بل لا يُحتفظ إلا ببصمات SHA-256 ومعرّفات الحقائق المطابَقة. لا تجري أداة الاختبار أي استدعاء شبكي أو مدفوع للنموذج ما لم يُمرَّر `--execute-real` وتُضبط `--model` و`OMNIROUTE_BASE_URL` و`OMNIROUTE_API_KEY`. ومن دون ذلك التشغيل الفعلي الصريح، يظل قرارها القابل للقراءة آليًا `HOLD`؛ ولا تُعد قياسات الحمولة الاصطناعية/عدد الاستدعاءات وحدها أدلة على الترقية.

يمكن للمستدعين إرفاق مصفوفة `transcript.cues` اختيارية بجزء فيديو مدعوم عندما يكون لديهم بالفعل نص متزامن. يجب أن يحتوي كل تلميح على `text`، وفاصل `start`/`end` محدود يقع ضمن المدة التي تم استقصاؤها، و`source` مدرج في قائمة السماح (`client` أو `embedded` أو `audio-bridge`)؛ تكون قيمة `confidence` الافتراضية `1` ويجب أن تظل بين `0` و`1`. تُدمج التلميحات المتطابقة تمامًا. لا تبدأ OmniRoute مطلقًا عملية نسخ صوتي انطلاقًا من هذه البيانات الوصفية: تُنسخ التلميحات التي تم التحقق منها إلى النتيجة الموصوفة مع المصدر والثقة والفاصل الزمني، وتُعرض كملاحظات غير موثوق بها إلى جانب التسميات التوضيحية للإطارات. يُرفض النص غير الصالح أو الخارج عن النطاق أو الخالي من معلومات المصدر بدلًا من مزجه في دفق التسميات التوضيحية. تطبّع قناتا النص المنسوخ في متن الطلب معلومات المصدر المقدَّمة إلى `client`، بما في ذلك التسميات المعلنة ذاتيًا `embedded` أو `audio-bridge`. ولا يمكن إلا لمهايئ مملوك للخادم تعيين تلك التسميات الموثوق بها عبر الوسيطة البرمجية فقط `trustedSource`؛ ولا يمكن لحقل JSON في الطلب الوصول إلى تلك الوسيطة. يظل نص النسخ محتوى غير موثوق به مشتقًا من الوسائط، بصرف النظر عن مصدره، ويجب ألا يحدد التفويض مطلقًا.

**حقول الفيديو الأولية (#12430).** عندما يكون الجسر مفعّلًا ويكون دعم الفيديو الأصلي مجهولًا أو غير متاح، فإن حقول `transcript`/`audioTranscript` المعرّفة تفعّل أيضًا `videoBridgeObserved`، حتى بعد فشل الوصف أو بلوغ حد `maxVideos`. تُحتسب `null` والسلاسل الفارغة؛ أما الحقول الغائبة والبيانات الوصفية غير المتعلقة بالفيديو فلا تُحتسب. تنقّح النسخ المحتفظ بها هذه الحقول أو تحذف الطلب، ويُتجاوز التخزين المؤقت/الذاكرة.

ولا يدّعي هذا أن كل تشخيص غير ذي صلة خاص بالموفّر/المكوّن الإضافي قد خضع
للتدقيق؛ إذ تُتبع المراجعة الأوسع لوجهات الاحتفاظ في #11658.

دورة حياة `/api/modality-bridge/video/drilldown` الداخلية هي ركيزة تخزين مؤقت منفصلة ومصادقًا عليها عبر loopback/token. تتطلب كل عملية أيضًا معرّفًا أساسيًا مبهمًا ومتعارفًا عليه. قبل تمكين أي مستدعٍ في بيئة الإنتاج، يجب عليه اشتقاق ذلك المعرّف من المستأجر المصادق عليه، ويجب ألّا يمرر مطلقًا قيمة يختارها العميل. تربط مفاتيح التخزين المؤقت ذلك المعرّف الأساسي بمعرّفات الجلسات ومراجع الفيديو المتعارف عليها، ولا تخزّن سوى مفاتيحها المشتقة باستخدام SHA-256، كما تقصر كلًا من عمليات القراءة والحذف على المعرّف الأساسي نفسه. يخزّن التخزين المؤقت 16 إطار JPEG مشتقًا كحد أقصى لكل إدخال، وتنتهي صلاحيتها بعد عشر دقائق، ويدعم عمليات قراءة محدودة باستخدام `start`/`end` أو حذفًا صريحًا للجلسة.

يقتصر كل معرّف أساسي على 16 إدخالًا و64 MiB من بيانات JPEG المتعارف عليها. هذه الحدود مستقلة عن الحد العام البالغ 64 إدخالًا/256 MiB: يؤدي ضغط حصة المعرّف الأساسي إلى طرد إدخالات ذلك المعرّف الأقل استخدامًا مؤخرًا فقط، قبل النظر في طرد LRU العام. تُزال الإدخالات منتهية الصلاحية من حسابات كل من المعرّف الأساسي والحساب العام عند حدوث نشاط في التخزين المؤقت، بينما لا يؤدي الإلغاء أو فشل التحقق إلى اعتماد استبدال جزئي.

يرفض التخزين المؤقت Base64 غير المتعارف عليه، والحشو الزائد، والوسائط غير المنسقة بصيغة JPEG، وملفات JPEG المشوهة أو المبتورة، وملفات JPEG التي تنتج تحذيرًا أثناء فك ترميز `sharp` محدود للصورة كاملة. يعيد ترميز كل صورة مقبولة بصيغة JPEG متعارف عليها، ويشتق العرض والارتفاع من البايتات المفكوك ترميزها بدلًا من الوثوق بحقول المستدعي، ويتخلص من أي بايتات polyglot لاحقة بدلًا من الاحتفاظ بها. لا يُحتسب ضمن كلتا الحصتين سوى المخزن المؤقت المضغوط والمتعارف عليه والمحدود. يشمل حد JSON السلكي الحمل الإضافي لـ Base64 ضمن سقف الإدخال المفكوك ترميزه البالغ 32 MiB. يسجل كل اشتقاق مخزّن تنسيق JPEG ودقته بعد التحقق، وسياسة أخذ العينات، وإصدار الاشتقاق، ووقت الإنشاء، وتجزئة المحتوى المحسوبة من الخادم، ومرجع الأصل المجزّأ، بالإضافة إلى تجزئة محتوى الأصل الواردة من المستدعي الموثوق. يُتحقق من الإلغاء بين مراحل فك الترميز والتجزئة غير المتزامنة، قبل الاعتماد الذري في التخزين المؤقت.

لا تربط هذه الدفعة حتى الآن منتجًا فعليًا في بيئة الإنتاج بالمسار، ولا توفر اختيار متغيرات متعددة الدقة. ولذلك لا يضيف مسار طلب Video Bridge الشفاف أي عمل إضافي، بينما يظل اشتقاق المعرّف الأساسي المرتبط بالمستأجر ودورة حياة FU-08 الكاملة متعددة الدقة عملًا لاحقًا صريحًا، بدلًا من توثيقهما كسلوك مكتمل.

تُضاف تعليقات وصفية إلى الإطارات بالتتابع باستخدام نموذج Video المُهيأ. يرث تجاوز Video الفارغ إعداد Vision؛ وإذا كان كلاهما فارغًا، يحدد الموجّه التلقائي لـ Vision النموذج الفعّال القادر على معالجة الرؤية. تستبدل التعليقات الوصفية الناجحة الجزء الأصلي ببادئة ثابتة `[Video description:` تشير أيضًا إلى أن النص ملاحظة غير موثوقة مشتقة من الوسائط، وتطلب من النماذج اللاحقة عدم اتباع التعليمات الموجودة في الوسائط. تتضمن مفاتيح التخزين المؤقت لتعليقات الإطارات بايتات JPEG، والموجّه، والطابع الزمني، والنموذج الفعّال؛ ولا تُخزّن مؤقتًا إلا التعليقات الناجحة. تحتفظ إدخالات التخزين المؤقت بالنموذج المنتج الفعلي الذي نجح، بما في ذلك نموذج احتياطي؛ وتبلغ الجسور عن `mixed` عندما تكون الإطارات المختلفة قد أُنتجت بواسطة نماذج مختلفة. تعيد إصابة التخزين المؤقت استخدام هوية ذلك المنتج بدلًا من إعادة تسميتها بوصفها خطة التوجيه المطلوبة. يُفهرس التخزين المؤقت لنتيجة الفيديو كاملًا باستخدام كل إدخال يغيّر المخرجات — الموجّه، والنموذج الفعّال، وسياسة أخذ العينات، وعدد الإطارات، ووضع التحليل الدلالي، وبصمة SHA-256 لتلميح التركيز المُطبّع، ونافذة التركيز، و`transcript`، و`audioTranscript`، وعلامة ورقة جهات الاتصال — ولذلك فإن تغيير أي من هذه الأبعاد يُعد إخفاقًا في إصابة التخزين المؤقت، ولا يؤدي مطلقًا إلى إعادة استخدام نتيجة قديمة. كما أن إصدار سياسة إزالة التكرار المرئي، والحد، والعدد المحدود لإطارات الترشيح، عناصر صريحة في مفتاح التخزين المؤقت للنتيجة وبياناته الوصفية؛ ولذلك لا يمكن لأي تغيير في السياسة إعادة استخدام وصف قديم للفيديو كاملًا. تحتفظ البيانات الوصفية للإصدار v4 من التخزين المؤقت للنتيجة بالوضع والبصمة، وليس بمهمة المستخدم الخام مطلقًا. تعرض البيانات الوصفية للحاجز الوقائي وضعي التحليل المطلوب والفعّال كليهما؛ ويُعرض وضع `focused` مطلوب دون نص مستخدم قابل للاستخدام على أنه `full` فعليًا.

يستخرج الحاجز الوقائي كل جزء فيديو مدعوم، لكنه لا يصف أكثر من `modalityBridgeVideoMaxVideos`. بالنسبة إلى هدف ثبت أن لديه `supportsVideo === false`، تتحول مقاطع الفيديو الفاشلة والمتجاوزة للحد إلى علامات نصية آمنة وصريحة، بحيث لا يبقى أي فيديو خام. عندما تكون القدرة غير معروفة، تحتفظ تلك الأجزاء بحامل الفيديو الخاص بها؛ وتتبع أي نسخة نصية احتياطية التحويل النصي المحدود أعلاه. تتجاوز الأهداف التي لديها `supportsVideo === true` الجسر. تنتشر إشارة إلغاء طلب العميل عبر التنزيل، وطابور الوسيط، والعمليات الفرعية، واستدعاءات التعليقات الوصفية؛ وتوقف عمليات الإلغاء المعالجة بين مقاطع الفيديو، ولا تفشل مطلقًا بشكل يسمح بتمرير الوسائط الخام.

إعدادات وقت التشغيل مدعومة بقاعدة بيانات ويُتحقق منها باستخدام Zod:

| المفتاح                             | القيمة الافتراضية | النطاق / السلوك                                                                                        |
| ----------------------------------- | ----------------- | ------------------------------------------------------------------------------------------------------ |
| `modalityBridgeVideoEnabled`        | `false`           | وقت تشغيل اختياري، يتطلب الاشتراك صراحةً                                                               |
| `modalityBridgeVideoAnalysisMode`   | `"full"`          | يحافظ `full` على التسميات التوضيحية العامة؛ ويستخدم `focused` سياقًا محدودًا وغير موثوق من أحدث مستخدم |
| `modalityBridgeVideoModel`          | `""`              | يرث نموذج Vision Bridge                                                                                |
| `modalityBridgeVideoFrameCount`     | `8`               | 1–16                                                                                                   |
| `modalityBridgeVideoSamplingPolicy` | `"uniform"`       | `uniform` أو `scene_aware` أو `segment_aware` التناسبي؛ ويؤدي فشل الكاشف إلى الرجوع إلى `uniform`      |
| `modalityBridgeVideoMaxVideos`      | `1`               | 1–4                                                                                                    |

تُقيَّد قيم مهلة Video القديمة المحفوظة التي تتجاوز 120 ثانية بموعد
الوسيط النهائي؛ وتُرفض عمليات كتابة الإعدادات الجديدة التي تتجاوز ذلك الحد.
يتطلب `GET /api/modality-bridge/video/runtime` محلية loopback موثوقة ومختومة
قبل المصادقة أو فحص وقت التشغيل، ثم يتطلب مصادقة الإدارة.
ولا يعيد سوى `available` وإصدارات FFmpeg/ffprobe المنقّحة وسببًا ثابتًا
عندما لا يكون وقت التشغيل متاحًا. نقطة نهاية الاستخراج الداخلية ليست
واجهة API عامة للرفع: يؤدي تشبع قائمة الانتظار إلى إرجاع `503` مع `Retry-After`،
ويؤدي قطع اتصال المستدعي إلى إرجاع `499`، بينما يؤدي الموعد النهائي الثابت للوسيط إلى إرجاع `504`. تضيف الاستجابات المحوّلة
`video->text;model=<visionModel>;parts=<videos>` إلى ترويسة
`x-omniroute-modality-bridge` المركزية من دون إزالة مقاطع Vision أو Audio.

### أداة إخفاء معلومات التعريف الشخصية (`piiMasker.ts`)

تعمل في **كلتا** المرحلتين.

- يقوم **`preCall`** باستنساخ الحمولة، واجتياز `system` و`messages` و`input` و
  `prompt` (بما في ذلك عناصر السلاسل النصية البسيطة)، وتطبيق `processPII()` (من
  `@/shared/utils/inputSanitizer`) على حقول `content`/`text` النصية. عندما تكون
  `PII_REDACTION_ENABLED=true`، تُنقَّح معلومات التعريف الشخصية المكتشفة في
  الحمولة الصادرة. وهذا مستقل عن `INPUT_SANITIZER_MODE` (الذي يتحكم فقط في
  سياسة حقن المطالبات). عندما يكون التنقيح متوقفًا، تسجّل العملية أعداد
  الاكتشافات من دون إعادة كتابة المحتوى.
- يقوم **`postCall`** باستنساخ الاستجابة استنساخًا عميقًا، وتشغيل `sanitizePIIResponse()` بالإضافة إلى
  أداة الإخفاء الخاصة ببنية Responses API (`maskResponsesOutput` — التي تغطي
  `output_text` و`output[].content[].text`). إذا حدث أي تنقيح، تحل
  الاستجابة المعدّلة محل الاستجابة الأصلية.

لا تحظر آلية الحماية أبدًا؛ بل تكتفي بإضافة التعليقات التوضيحية (`meta.detections`،
`meta.redacted`) أو إعادة الكتابة.

#### التحديد حسب النوع والأنماط المخصصة وعدادات الاكتشاف

يحدد **لوحة المعلومات ← الإعدادات ← الأمان ← إخفاء معلومات التعريف الشخصية** _ما_ يجب إخفاؤه. ولا
يؤدي ذلك إلى تشغيل الإخفاء: إذ يظل ذلك من مسؤولية `PII_REDACTION_ENABLED` (الطلب) و
`PII_RESPONSE_SANITIZATION` (الاستجابة + SSE)، وكلاهما متوقف افتراضيًا.

- **التحديد حسب النوع** — المعرّفات المضمنة مدرجة في
  `src/shared/constants/piiTypes.ts` (`PII_BUILTIN_TYPES`). عدم تعيين قيمة يعني جميع
  الأنواع (وهو السلوك السابق لوجود هذا الإعداد). يرتبط نمط محرك الطلبات
  `ssn_us` بـ `ssn`. لا تقوم القوالب (الحد الأدنى، القياسي، المالي،
  البرازيلي، الأمريكي، الكامل) سوى بملء مربعات الاختيار في واجهة المستخدم.
- **الأنماط المخصصة** — حتى 20 نمطًا من أنماط التعبيرات النمطية أو أحرف البدل (`*` = حتى 64
  حرفًا من غير المسافات البيضاء، و`?` = حرف واحد). تتحول المطابقات إلى `[CUSTOM_REDACTED]`.
  يمر كل نمط عبر `compilePiiCustomPattern()`
  (`src/shared/utils/piiCustomPatterns.ts`): بحد أقصى 500 حرف، مع اقتصار العلامات
  على `g i m s u`، ويجب أن ينجح تجميعه، وأن يجتاز `safe-regex` (التراجع
  الكارثي)، وألا يطابق سلسلة فارغة أو عنصرًا نائبًا للتنقيح.
  يُرفض النمط غير الصالح عند الحفظ والاختبار، ويُتخطى الصف
  المخزّن غير الصالح في وقت التشغيل بدلًا من تجميعه. لا تعمل الأنماط المخصصة إلا
  عندما يكون الإخفاء مفعّلًا.
- **عدادات الاكتشاف** — أعداد حسب النوع (وليست القيم المطابقة أبدًا)، محفوظة في
  الذاكرة وتُصفّر عند إعادة التشغيل (`src/lib/pii/piiDetectionStats.ts`). ولا
  تزداد إلا عندما يكون الإخفاء مفعّلًا.

توجد الإعدادات في جدول `key_value` (ضمن مساحة الاسم `pii_settings`،
`src/lib/db/piiSettings.ts`) وتُقرأ عبر ذاكرة تخزين مؤقت مدتها 1 ثانية. واجهة API:

| الطريقة | المسار                   | الغرض                                                                  |
| ------- | ------------------------ | ---------------------------------------------------------------------- |
| `GET`   | `/api/settings/pii`      | حالة العلامات و`enabledTypes` و`customPatterns` وعدادات الاكتشاف       |
| `PUT`   | `/api/settings/pii`      | استبدال `enabledTypes` (`null` = الكل) و/أو `customPatterns`           |
| `POST`  | `/api/settings/pii/test` | تشغيل تجريبي لنمط واحد مقابل عينة لا تتجاوز 8 كيلوبايت؛ لا يُخزَّن شيء |

تتطلب العمليات الثلاث جميعها مصادقة الإدارة وتتحقق من صحة النص باستخدام Zod
(`src/shared/validation/schemas/piiSettings.ts`).

### حقن المطالبات (`promptInjection.ts`)

يكتشف البُنى العدائية في المحتوى الذي يقدمه المستخدم ويفرض
السياسة المضبوطة. تحدد متغيرات البيئة وخيارات المُنشئ السلوك:

| الإعداد  | متغير البيئة                                                                                                | القيمة الافتراضية | التأثير                                                                                                                                                                                                  |
| -------- | ----------------------------------------------------------------------------------------------------------- | ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| التفعيل  | `INPUT_SANITIZER_ENABLED`                                                                                   | `true`            | عندما تكون القيمة `false`، يتوقف حاجز الحماية مبكرًا.                                                                                                                                                    |
| الوضع    | `INJECTION_GUARD_MODE` / `INPUT_SANITIZER_MODE`                                                             | `warn`            | سياسة الحقن: `block` أو `warn` أو `log`. (تُقبل `redact` للتوافق مع الإصدارات السابقة، لكنها **لا** تزيل نص الحقن؛ وتتحكم `PII_REDACTION_ENABLED` في إعادة كتابة معلومات تحديد الهوية الشخصية في الطلب.) |
| حد الحظر | خيار `blockThreshold` / ‏`INPUT_SANITIZER_BLOCK_THRESHOLD` (الاسم البديل `INJECTION_GUARD_BLOCK_THRESHOLD`) | `high`            | الحد الأدنى للخطورة المطلوبة للحظر. تكون الخطورة المتوسطة للمراقبة فقط افتراضيًا.                                                                                                                        |

**أسبقية الوضع** (`getMode`): ‏`options.mode` الخاص بالمستدعي →
**تجاوز علامة الميزة في قاعدة البيانات** لـ `INJECTION_GUARD_MODE` (لوحة المعلومات → الإعدادات →
علامات الميزات) → متغير البيئة `INJECTION_GUARD_MODE` → متغير البيئة `INPUT_SANITIZER_MODE` →
`warn`. لذلك، يتغلب تجاوز لوحة المعلومات على متغيرات البيئة، ما يتيح لواجهة
علامات الميزات التحكم مباشرةً في حاجز الحماية قيد التشغيل (من دون إعادة تشغيل). قراءة قاعدة البيانات آمنة عند الفشل:
إذا حدث خطأ، يعود حاجز الحماية إلى السلوك المستند إلى متغيرات البيئة، وعندما لا يكون هناك
تجاوز معيّن، يكون السلوك مطابقًا تمامًا للحل المعتمد على متغيرات البيئة فقط.

مصادر الاكتشاف:

1. ‏`sanitizeRequest()` من `@/shared/utils/inputSanitizer` (مجموعة أدوات الاكتشاف المشتركة
   والمستخدمة في مواضع أخرى ضمن مسار المعالجة).
2. ‏`DEFAULT_GUARD_PATTERNS` المضمّنة (حاليًا `system_override_inline` و
   `markdown_system_block`، وكلاهما بدرجة خطورة `high`).
3. ‏`customPatterns` الاختيارية التي تُمرَّر عبر خيارات المُنشئ (سلاسل نصية أو تعبيرات نمطية
   أو سجلات `{ name, pattern, severity }`).

عندما يكون `mode === "block"` **و** يطابق اكتشاف واحد على الأقل حد
الخطورة، تُرجع `preCall` القيمة `{ block: true, message: "Request rejected:
suspicious content detected" }`. في وضعي `warn`/`log`، يسجّل حاجز الحماية الحدث لكنه
يسمح بالاستدعاء. كما تُصدَّر الأداة المساعدة المشتركة `evaluatePromptInjection()`
للمستدعين الذين يحتاجون إلى تقييم المطالبات من دون المرور عبر السجل.

**حد الفحص (v3.8.20):** لا تفحص أداة الاكتشاف سوى **أول 16 KB** من
نص المطالبة المدمج — ‏`MAX_INJECTION_SCAN_BYTES = 16 * 1024` (16 384 بايت) في
`src/shared/utils/inputSanitizer.ts`. تنفّذ كل من `detectInjection()` و
`evaluatePromptInjection()` العملية `slice(0, MAX_INJECTION_SCAN_BYTES)` قبل تشغيل
حلقة الأنماط. توجد توجيهات الحقن بالقرب من بداية الإدخال، ولذلك يحدّ هذا
من استهلاك وحدة المعالجة المركزية/جامع البيانات المهملة الناتج عن التعبيرات النمطية في الحمولات التي يبلغ حجمها مئات الكيلوبايت، من دون إضعاف الاكتشاف (راجع
#3932، #4041).

### أداة إخفاء بيانات الاعتماد (`credentialMasker.ts`)

تعمل في **كلتا** المرحلتين، وتأتي أخيرةً في السلسلة الافتراضية (الأولوية `95`). تحجب
أنماط مفاتيح API / الرموز السرية المعروفة جيدًا من الحمولة الصادرة (محتوى
الرسائل، ووسائط استدعاءات الأدوات، ونتائج الأدوات) **وكذلك** من استجابة المزوّد، بحيث لا تتسرب
بيانات اعتماد ملصقة في مطالبة (أو يعيدها ناتج أداة) إلى المزوّد الخارجي
أو إلى العميل.

- **اشتراك صريح فقط**، وفق الاصطلاح نفسه المستخدم لحجب معلومات تحديد الهوية الشخصية (بالقرب من القاعدة الصارمة رقم #20):
  تكون معطّلة ما لم تكن `settings.credentialRedactionEnabled === true` **أو**
  `CREDENTIAL_REDACTION_ENABLED=true`. عند تعطيلها، لا ينفّذ حاجز الحماية أي إجراء —
  فلا يحظر أبدًا ولا يعيد الكتابة.
- تجتاز `redactCredentials()` شجرة الحمولة/الاستجابة كاملةً (`walkValue()`،
  وهي آمنة من تلوث النماذج الأولية وآمنة من الدورات عبر `WeakSet`) وتستبدل التطابقات
  بالعنصر النائب `[REDACTED:<type>]`، مع استنساخ الفروع التي
  تغيّرت فعليًا فقط.
- تغطي `CREDENTIAL_PATTERNS` مفاتيح مزوّدي نماذج اللغة الكبيرة (OpenAI وOpenAI-proj
  وAnthropic وGoogle وHugging Face وReplicate)، ورموز VCS/SaaS (GitHub وSlack
  وLinear وNotion وnpm وPostman وDiscord)، ومفاتيح الدفع (Stripe وSquare)، ومفاتيح الخدمات
  السحابية (مفتاح وصول AWS وTwilio وSendGrid وMailgun)، والمفاتيح الخاصة / رموز JWT،
  وسلاسل الاتصال التي تتضمن بيانات اعتماد (`mongodb://user:pass@...`، وما شابه)، ونمطًا
  عامًا لقيم ترويسات `Authorization`/`x-api-key`/`api-key`/`apikey`.
  تُحجب المفاتيح التي تأخذ شكل ترويسات (`authorization` و`x-api-key` و`api-key`
  و`apikey`) بنيويًا (القيمة فقط، مع الحفاظ على بادئة المخطط مثل
  `Bearer `/`Basic `) بدلًا من استخدام التعبير النمطي النصي العام.
- لا يحظر حاجز الحماية أبدًا؛ بل يعيد الكتابة فقط (`modifiedPayload` /
  `modifiedResponse`) ويضيف بيانات وصفية (`meta.credentialsRedacted` و`meta.count`).

حاجز منع الانحدار: `tests/unit/credential-masker-guardrail.test.ts`.

## العقد الأساسي (`base.ts`)

```typescript
class BaseGuardrail {
  enabled: boolean;
  name: string;
  priority: number;

  constructor(name: string, options?: { enabled?: boolean; priority?: number });

  async preCall(payload: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;

  async postCall(response: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;
}

interface GuardrailResult<TValue = unknown> {
  block?: boolean; // تؤدي القيمة true إلى إيقاف السلسلة فورًا
  message?: string; // تظهر عند الحظر
  meta?: Record<string, unknown> | null;
  modifiedPayload?: TValue; // تُرجعها preCall لإعادة كتابة الطلب
  modifiedResponse?: TValue; // تُرجعها postCall لإعادة كتابة الاستجابة
}

interface GuardrailContext {
  apiKeyInfo?: Record<string, unknown> | null;
  disabledGuardrails?: string[] | null;
  endpoint?: string | null;
  headers?: Headers | Record<string, unknown> | null;
  log?: GuardrailLog | Console | null;
  method?: string | null;
  model?: string | null;
  provider?: string | null;
  signal?: AbortSignal;
  sourceFormat?: string | null;
  stream?: boolean;
  targetFormat?: string | null;
}
```

يشير حاجز الحماية إلى «عدم وجود تغيير» عبر إرجاع `void` أو `{}` أو
`{ block: false }`. يؤدي إرجاع `modifiedPayload`/`modifiedResponse` إلى استبدال
القيمة المتدفقة عبر السلسلة لحواجز الحماية اللاحقة.
يحمل `signal?: AbortSignal` دورة حياة المستدعي إلى حواجز الحماية. يُعد إلغاء الطلب استثناءً مقصودًا يسمح بالمتابعة عند الفشل: إذ تتوقف جسور الوسائط عن العمل وتُجري التنظيف دون استعادة الوسائط الخام إلى هدف معروف بأنه لا يدعمها.

## السجل (`registry.ts`)

يكشف `guardrailRegistry` الأحادي عن:

- `register(guardrail)` — يضيف (أو يستبدل بالاسم المعياري) حاجزًا و
  يعيد الترتيب حسب `priority` التصاعدي.
- `clear()` / `list()` — مساعدات إدارية.
- `runPreCallHooks(payload, context)` — يكرر الحواجز النشطة، يمرر
  الحمولة عبر `modifiedPayload`، ويتوقف عند أول `block: true`.
- `runPostCallHooks(response, context)` — نفس التدفق على جانب الاستجابة.
- `resetGuardrailsForTests({ registerDefaults })` — يمسح الحالة و
  يعيد تسجيل الإعدادات الافتراضية اختياريًا لعزل الاختبار النظيف.

يعيد كل من المشغلين `{ blocked, payload|response, results, guardrail?, message? }`
حيث `results` هي مصفوفة من سجلات `GuardrailExecutionResult` التي تتضمن
حقول `blocked`, `skipped`, `modified`, `error`, و `meta` لكل حاجز،
مفيدة للتتبع.

### تعطيل الحواجز لكل طلب

يقوم `resolveDisabledGuardrails({ apiKeyInfo, body, headers })` بتجميع قائمة
غير مكررة لأسماء الحواجز التي يجب تخطيها للطلب الحالي. المصادر (جميعها اختيارية، وجميعها مدمجة):

- `apiKeyInfo.disabledGuardrails`
- نص الطلب `disabledGuardrails` (على المستوى الأعلى)
- نص الطلب `metadata.disabledGuardrails`
- الرأس `x-omniroute-disabled-guardrails` (أو القديم
  `x-disabled-guardrails`)

يمكن أن تكون القيم مصفوفات من السلاسل أو سلسلة مفصولة بفاصلة؛ يتم
تطبيع الأسماء إلى صيغة kebab-case بالأحرف الصغيرة (`pii_masker` ← `pii-masker`).
يتم تمرير النتيجة عبر `context.disabledGuardrails` إلى السجل، الذي يتخطى
الحواجز المطابقة (`skipped: true` في `results`).

## ترتيب التنفيذ

لكل طلب يمر عبر `src/sse/handlers/chat.ts` و `open-sse/handlers/chatCore.ts`:

1.  يقوم `resolveDisabledGuardrails(...)` بإنشاء قائمة التخطي من مفتاح API، والنص الأساسي، والرؤوس.
2.  يقوم `guardrailRegistry.runPreCallHooks(body, ctx)` بتشغيل الحواجز الأمنية بترتيب تصاعدي للأولوية:
    - يتم تسجيل الحواجز الأمنية المعطلة على أنها `skipped`.
    - قد يقوم `preCall` لكل حاجز أمني بإعادة كتابة الحمولة عبر `modifiedPayload`.
    - أول `block: true` يقطع السلسلة ويعيد المعالج استجابة رفض الحاجز الأمني.
3.  تتدفق الحمولة (التي قد تكون أعيدت كتابتها) إلى توجيه التحرير والسرد والإرسال الأولي.
4.  بعد تجميع الاستجابة، يقوم `guardrailRegistry.runPostCallHooks(...)` بتشغيل نفس السلسلة على الاستجابة. `block: true` هنا يسقط الاستجابة الأولية.

يتم تسجيل الحواجز الأمنية التي تثير خطأ بـ `error: <message>` ويتم تسجيلها عبر `logger.warn`، لكن السلسلة تستمر — تصميم يسمح بالفشل المفتوح.

## التكوين

متغيرات البيئة التي تقرأها الحواجز الأمنية المدمجة:

| المتغير | يستخدم بواسطة | التأثير |
| `INPUT_SANITIZER_ENABLED` | `prompt-injection` | تعيين `false` لتعطيل الكشف بالكامل. |
| `INPUT_SANITIZER_MODE` | `prompt-injection` | سياسة الحقن: `warn` (تحذير)، `block` (حظر)، أو `log` (تسجيل). القيمة القديمة `redact` لا تعيد كتابة نص الحقن. |
| `INJECTION_GUARD_MODE` | `prompt-injection` | وضع حماية الحقن؛ وهو أيضًا علامة ميزة قاعدة بيانات **تتجاوز** متغيرات البيئة (قاعدة البيانات > البيئة). |
| `INPUT_SANITIZER_BLOCK_THRESHOLD` | `prompt-injection` | الحد الأدنى للخطورة الذي يرفضه `MODE=block`: `high` (مرتفع، افتراضي)، `medium` (متوسط)، أو `low` (منخفض). |
| `INJECTION_GUARD_BLOCK_THRESHOLD` | `prompt-injection` | اسم مستعار قديم لـ `INPUT_SANITIZER_BLOCK_THRESHOLD`. |
| `PII_REDACTION_ENABLED` | `pii-masker` | عندما يكون `true`، يتم تنقيح معلومات التعريف الشخصية (PII) للطلب (بصرف النظر عن وضع الحقن). |
| `PII_RESPONSE_SANITIZATION` / `_MODE` | `pii-masker` (downstream) | يتحكم في سلوك قناع الاستجابة. |

تقرأ الحواجز الأمنية لـ Modality Bridge التكوين في وقت التشغيل من مخزن الإعدادات المدعوم بقاعدة البيانات (`getSettings()`)، وليس من متغيرات البيئة. المفاتيح الأساسية لـ Vision هي `modalityBridgeVisionEnabled`, `modalityBridgeVisionMode`, `modalityBridgeVisionModel`, `modalityBridgeVisionTaskAware`, `modalityBridgeVisionPrompt`, `modalityBridgeVisionTimeout`, `modalityBridgeVisionMaxImages`, `modalityBridgeVisionMaxChars`, `modalityBridgeCacheEnabled`, `modalityBridgeCacheTtlMinutes`, و `modalityBridgeCacheMaxEntries`. يتم قبول المفاتيح القديمة `visionBridge*` فقط كخيار احتياطي للقراءة لمرة واحدة كما هو موثق؛ تستخدم عمليات الكتابة في لوحة التحكم المفاتيح الأساسية. توجد القيم الافتراضية ومحلل الاحتياطي في `src/shared/constants/modalityBridgeDefaults.ts`، مع الاحتفاظ بالثوابت القديمة في `src/shared/constants/visionBridgeDefaults.ts`.

يستخدم الصوت `modalityBridgeAudioEnabled`, `modalityBridgeAudioModel`, `modalityBridgeAudioTimeout`, و `modalityBridgeAudioMaxClips`, بالإضافة إلى إعدادات `modalityBridgeCache*` المشتركة. لا يحتوي الصوت على خيار احتياطي للمفاتيح القديمة لأن هذه المفاتيح تم تقديمها مع مخطط Modality Bridge.

يستخدم الفيديو `modalityBridgeVideoEnabled`, `modalityBridgeVideoAnalysisMode`, `modalityBridgeVideoModel`, `modalityBridgeVideoFrameCount`, `modalityBridgeVideoSamplingPolicy`, `modalityBridgeVideoMaxVideos`, و `modalityBridgeVideoTimeout`, بالإضافة إلى إعدادات `modalityBridgeCache*` المشتركة. يتم تعطيله افتراضيًا لأن FFmpeg/ffprobe هي تبعيات تشغيلية اختيارية، وإضافة تسميات الإطارات تزيد من زمن الاستجابة وتكلفة النموذج.

## حواجز حماية مخصصة

```typescript
import { BaseGuardrail, guardrailRegistry } from "@/lib/guardrails";

class BudgetGuardrail extends BaseGuardrail {
  constructor() {
    super("budget", { priority: 50 });
  }

  async preCall(payload, ctx) {
    if (ctx.apiKeyInfo?.budgetExceeded) {
      return { block: true, message: "Daily budget exceeded" };
    }
    return { block: false };
  }
}

guardrailRegistry.register(new BudgetGuardrail());
```

الخطوات:

1.  أنشئ `src/lib/guardrails/myGuardrail.ts` يوسع `BaseGuardrail`.
2.  نفّذ `preCall` و/أو `postCall`.
3.  سجّل إما وقت الاستيراد (ادفع من `registerDefaultGuardrails`) أو
    استدعِ `guardrailRegistry.register(...)` في وقت التشغيل — يحل السجل محل
    أي حاجز حماية سابق بنفس الاسم المعياري.
4.  أضف اختبارات تحت `tests/unit/` (أمثلة موجودة:
    `tests/unit/guardrails-registry.test.ts`,
    `tests/unit/prompt-injection-guard.test.ts`,
    `tests/unit/guardrails/visionBridge.test.ts`).

## الاختبار

استخدم `resetGuardrailsForTests()` بين الاختبارات للبدء من حالة معروفة.
مرر `{ registerDefaults: false }` للبدء بسجل فارغ و
تسجيل حواجز الحماية قيد الاختبار فقط. يقبل Vision Bridge حقن التبعية
(`deps.getSettings`, `deps.callVisionModel`)؛ يعرض Audio Bridge
الوصلات المكافئة للإعدادات، والقدرات، واختيار نموذج STT، وفحوصات الاعتماد،
والنسخ. وبالتالي يمكن للاختبارات ممارسة كلا التدفقين بدون قاعدة بيانات
أو الوصول إلى الشبكة.

## تغطية مسار حماية الحقن والاختبار الأحمر (المرحلة 8 · الكتلة D)

يغطي حارس الحقن (`createInjectionGuard` / `withInjectionGuard`) جميع المسارات
التي تقبل مطالبات المستخدم. وهو يحترم `INJECTION_GUARD_MODE` (الافتراضي `warn` = تسجيل فقط؛
`block` = يعيد HTTP 400 `SECURITY_001`).

| النوع      | المسارات                                                                                                                                             | الوضع الافتراضي |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | --------------- |
| نص (موجود) | `/v1/chat/completions`, `/v1/completions`, `/v1/relay/chat/completions`                                                                              | warn            |
| توليدي     | `/v1/messages`, `/v1/responses`, `/v1/images/generations`, `/v1/images/edits`, `/v1/videos/generations`, `/v1/music/generations`, `/v1/audio/speech` | warn            |
| بيانات     | `/v1/embeddings`, `/v1/rerank`, `/v1/search`, `/v1/moderations`                                                                                      | warn            |

تغطية استخراج النص (`extractMessageContents`) تشمل `messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system`.

**الفريق الأحمر (ليلي، `nightly-llm-security.yml`):** يتحقق promptfoo من أن كل مسار يحظر
مجموعة OWASP-LLM في `INJECTION_GUARD_MODE=block`؛ يقوم garak بتشغيل الفحوصات (يتخطى بدون سر).
يتم تضمين `moderations` من أجل الاتساق — يمكن للمشغلين في وضع الحظر إعفائها عبر
`resolveDisabledGuardrails`.

يحتوي سير العمل الليلي (`.github/workflows/nightly-llm-security.yml`، cron +
التشغيل اليدوي) على وظيفتين:

- **`promptfoo-guard` (حظر)** — يشغل `promptfoo eval -c promptfooconfig.yaml`
  مع `INJECTION_GUARD_MODE=block`. تؤكد كل حالة عدائية (مثل "تجاهل جميع
  التعليمات السابقة..."، اختراقات على غرار DAN) أن الاستجابة تحمل
  `error.code === "SECURITY_001"`، أي أن الحارس رفض الطلب بالفعل.
- **`garak` (استشاري)** — يشغل garak `--probes promptinject,dan,leakreplay`
  مقابل مثيل OmniRoute محلي (`http://localhost:20128/v1`). يتم التحكم فيه بواسطة
  سر مزود (`PROMPTFOO_PROVIDER_KEY`)؛ يتخطى بأمان ويتم إلحاقه بـ
  `|| true`، لذلك يتم الإبلاغ عنه دون فشل CI.

تغطية مساعد الحارس (`createInjectionGuard` / `withInjectionGuard`)
تمتد عبر كل مسار `/v1` يحمل مطالبة؛ يتم سحب نص المطالبة من
`messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system` بواسطة
`extractMessageContents()` في `src/shared/utils/inputSanitizer.ts`.
