> ଏପର୍ଯ୍ୟନ୍ତ ସର୍ଭର୍ ଦ୍ୱାରା ଯାଞ୍ଚ ହୋଇନାହିଁ — #11661 ଅନୁଯାୟୀ ସ୍ପଷ୍ଟ କରାଯାଇଛି)

Guardrailଗୁଡ଼ିକ OmniRoute ଏବଂ ଅପ୍ଷ୍ଟ୍ରିମ୍ ପ୍ରଦାନକାରୀଙ୍କ ମଧ୍ୟସ୍ଥ ସୀମାରେ
ସୁରକ୍ଷା, ନୀତି ଏବଂ ବିଷୟବସ୍ତୁ ରୂପାନ୍ତରଣକୁ ବାଧ୍ୟତାମୂଳକ କରନ୍ତି। ପ୍ରତ୍ୟେକ guardrail ଅନୁରୋଧ ପେଲୋଡ୍ଗୁଡ଼ିକୁ (`preCall`) ଏବଂ
ଅପ୍ଷ୍ଟ୍ରିମ୍ ପ୍ରତିକ୍ରିୟାଗୁଡ଼ିକୁ (`postCall`) ଯାଞ୍ଚ କରିପାରେ (ଏବଂ
ଇଚ୍ଛାଧୀନ ଭାବେ ପ୍ରତ୍ୟାଖ୍ୟାନ, ରୂପାନ୍ତର କିମ୍ବା ଟୀକାଯୁକ୍ତ କରିପାରେ)।

ସିଷ୍ଟମ୍ଟି **fail-open**: ଯଦି ନିଷ୍ପାଦନ ସମୟରେ କୌଣସି guardrail ତ୍ରୁଟି ନିକ୍ଷେପ କରେ, ତେବେ registry
ତ୍ରୁଟିଟିକୁ ରେକର୍ଡ କରେ ଏବଂ ଅନୁରୋଧକୁ ବିଫଳ କରିବା ପରିବର୍ତ୍ତେ ପରବର୍ତ୍ତୀ guardrail ସହିତ ଜାରି ରଖେ।
ବ୍ଲକ୍ କରିବା ଏକ ସ୍ପଷ୍ଟ ନିଷ୍ପତ୍ତି (`block: true`), କେବେବି ଦୁର୍ଘଟଣାବଶତଃ ନୁହେଁ।

### ଭିଜନ୍ ବ୍ରିଜ୍ (`visionBridge.ts`) — ମୋଡାଲିଟି ବ୍ରିଜ୍ PR-1

**ନନ୍-ଭିଜନ୍ ମଡେଲ୍ଗୁଡ଼ିକ** ପାଇଁ ଉଦ୍ଦିଷ୍ଟ ଇମେଜ୍-ସମ୍ବଳିତ ଅନୁରୋଧଗୁଡ଼ିକୁ ଅବରୋଧ କରେ ଏବଂ ଅପ୍ଷ୍ଟ୍ରିମ୍ କଲ୍ ପୂର୍ବରୁ ସମ୍ପୂର୍ଣ୍ଣ ଅନୁରୋଧକୁ ଏକ ଭିଜନ୍-ସକ୍ଷମ ମଡେଲ୍କୁ ପୁନଃରୁଟ୍ କରେ କିମ୍ବା ଇମେଜ୍ ଅଂଶଗୁଡ଼ିକୁ ଏକ ବିନ୍ୟାସଯୋଗ୍ୟ ଭିଜନ୍ ମଡେଲ୍ ଦ୍ୱାରା ଉତ୍ପାଦିତ ପାଠ୍ୟ ବର୍ଣ୍ଣନା ସହିତ ପ୍ରତିସ୍ଥାପନ କରେ। ଏହା କେବଳ-ପାଠ୍ୟ ପ୍ରଦାନକାରୀମାନଙ୍କୁ ପାରଦର୍ଶୀ ଭାବେ ମଲ୍ଟିମୋଡାଲ୍ ପେଲୋଡ୍ ପରିଚାଳନା କରିବାକୁ ଦିଏ।

ପ୍ରବାହ:

1. ଯଦି ଲକ୍ଷ୍ୟ ମଡେଲ୍ ପୂର୍ବରୁ ଭିଜନ୍ ସମର୍ଥନ କରେ, ତେବେ ଏହାକୁ ଏଡ଼ାଇ ଯାଆନ୍ତୁ (ଯଦି ଏହା ବାଧ୍ୟତାମୂଳକ-ବ୍ରିଜ୍ ତାଲିକା `isVisionBridgeForcedModel`ରେ ଦେଖାଯାଏ, ତେବେ ବ୍ୟତୀତ)।
2. `extractImageParts(messages)`
   (`visionBridgeHelpers.ts`) ମାଧ୍ୟମରେ ଇମେଜ୍ ଅଂଶଗୁଡ଼ିକୁ ବାହାର କରନ୍ତୁ, ଯାହା `open-sse/utils/mediaParts.ts`ରେ ଥିବା **ଏକୀକୃତ ମିଡିଆ
   ଡିଟେକ୍ଟର୍** `detectMediaParts()`କୁ ଦାୟିତ୍ୱ ନ୍ୟସ୍ତ କରେ — ଏହା କମ୍ବୋ ସୁସଙ୍ଗତତା ଫିଲ୍ଟର୍ ସହିତ ଅଂଶୀଦାର ହୋଇଥିବା ଏକମାତ୍ର ନିର୍ଭରଯୋଗ୍ୟ ଉତ୍ସ।
   ଏକ୍ସଟ୍ରାକ୍ସନ୍କୁ `replaceImageParts` ପୁଣି ସ୍ପ୍ଲାଇସ୍ କରିପାରୁଥିବା ଆକୃତିଗୁଡ଼ିକର ଶୀର୍ଷ-ସ୍ତରୀୟ ଅଂଶଗୁଡ଼ିକ ପର୍ଯ୍ୟନ୍ତ ଅନୁମୋଦିତ ତାଲିକାରେ ସୀମିତ କରାଯାଇଛି (ଏକ୍ସଟ୍ରାକ୍ଟ↔ରିପ୍ଲେସ୍ ଚୁକ୍ତି): OpenAI
   `image_url`, Anthropic base64 `source.type:"base64"`, Anthropic URL
   `source.type:"url"`, ଏବଂ Responses API `input_image`। ନେଷ୍ଟେଡ୍ ମେଳ ଏବଂ କେବଳ-ସୂଚକ ଆକୃତିଗୁଡ଼ିକ କମ୍ବୋ-ଫିଲ୍ଟର୍ ସାମଗ୍ରୀ ଅଟେ ଏବଂ କେବେବି ଏକ୍ସଟ୍ରାକ୍ଟ କରାଯାଏ ନାହିଁ।
   କିଛି ନ ମିଳିଲେ ଏଡ଼ାଇ ଯାଆନ୍ତୁ।
3. `resolveVisionBridgeRuntimeSettings()`
   (`src/shared/constants/modalityBridgeDefaults.ts`) ମାଧ୍ୟମରେ ରନ୍ଟାଇମ୍ ବିନ୍ୟାସ ସମାଧାନ କରନ୍ତୁ: ନୂତନ `modalityBridge*`
   ସେଟିଂସ୍ କିଗୁଡ଼ିକୁ ପ୍ରାଥମିକତା ମିଳେ; ପୁରୁଣା `visionBridge*` କିଗୁଡ଼ିକ ଏକ **ଏକ-ଚକ୍ର

   କୌଣସି କ୍ଷମତା ପ୍ରମାଣ ନଥିଲେ `null` ରହେ। `false` ଏବଂ `null` ଉଭୟ
   ସଂରକ୍ଷଣଶୀଳ ବ୍ରିଜ୍କୁ ସକ୍ରିୟ କରେ, ଯେତେବେଳେ `true` ଏହାକୁ ବାଇପାସ୍ କରେ।
2. `modalityBridgeAudio*` ସେଟିଂସ୍ ସମାଧାନ କରନ୍ତୁ ଏବଂ ସହଭାଗୀ
   `detectMediaParts()` ଡିଟେକ୍ଟର୍ ମାଧ୍ୟମରେ ପ୍ରତ୍ୟେକ ସନ୍ଦେଶରୁ ସ୍ପ୍ଲାଇସ୍
   କରାଯାଇପାରୁଥିବା ଶୀର୍ଷ-ସ୍ତରୀୟ ଅଡିଓ ଅଂଶଗୁଡ଼ିକୁ ବାହାର କରନ୍ତୁ।
   ସମର୍ଥିତ ୱାୟାର୍ ଆକୃତିଗୁଡ଼ିକ ହେଉଛି OpenAI `input_audio`, `audio_url`,
   ଏବଂ `source.media_type: "audio/*"`। ନେଷ୍ଟେଡ୍ ଅଡିଓକୁ ରାଉଟିଂ ପାଇଁ
   ଚିହ୍ନଟ କରାଯାଏ, କିନ୍ତୁ ସ୍ପ୍ଲାଇସ୍ ପଥ ଦ୍ୱାରା ଅପସାରଣ କରାଯାଏ ନାହିଁ।
   କାର୍ଯ୍ୟ `modalityBridgeAudioMaxClips` ଦ୍ୱାରା ସୀମିତ; ପରବର୍ତ୍ତୀ ଅଂଶଗୁଡ଼ିକ
   ଅପରିବର୍ତ୍ତିତ ରହେ।
3. ବିନ୍ୟାସିତ `provider/model`କୁ ସମ୍ମାନ ଦିଅନ୍ତୁ, କିମ୍ବା
   `selectAudioBridgeModel()`କୁ ସ୍ଥିର କ୍ୟାଟାଲଗ୍ କ୍ରମରେ
   `AUDIO_TRANSCRIPTION_PROVIDERS` ମଧ୍ୟରେ ଯାଇ ବ୍ୟବହାରଯୋଗ୍ୟ ସକ୍ରିୟ
   ପ୍ରଦାନକାରୀ ପ୍ରମାଣପତ୍ର ଥିବା ପ୍ରଥମ ମଡେଲ୍ ଚୟନ କରିବାକୁ ଦିଅନ୍ତୁ।
4. `callAudioTranscription()` base64/data-URI ଅଡିଓକୁ ଏକ ମଲ୍ଟିପାର୍ଟ
   `file`ରେ ରୂପାନ୍ତର କରେ, କିମ୍ବା DNS ପିନିଂ ଏବଂ 25 MB ସୀମା ସହିତ
   ପବ୍ଲିକ୍-ଓନ୍ଲି ଆଉଟ୍ବାଉଣ୍ଡ ଗାର୍ଡ ମାଧ୍ୟମରେ ଏକ ରିମୋଟ୍ `audio_url`
   ଡାଉନଲୋଡ୍ କରେ। ତାହା ପରେ ଏହା `resolveSelfLoopBearer()` ସହ
   ପ୍ରାମାଣିକୃତ ସ୍ଥାନୀୟ `/v1/audio/transcriptions` ସେଲ୍ଫ-ଲୁପ୍କୁ ଫାଇଲ୍
   ଏବଂ ଚୟନିତ ମଡେଲ୍ POST କରେ। ବିଦ୍ୟମାନ ଟ୍ରାନ୍ସକ୍ରିପ୍ସନ୍ ରୁଟ୍ ସାଧାରଣ
   ପ୍ରମାଣପତ୍ର ଲୁକ୍ଅପ୍, କୁଲ୍ଡାଉନ୍/ରେଟ୍-ଲିମିଟ୍ ପରିଚାଳନା, ଏବଂ
   ପ୍ରଦାନକାରୀ ଡିସ୍ପ୍ୟାଚ୍ ସମ୍ପାଦନ କରେ।
5. ସଫଳ କଲ୍ଗୁଡ଼ିକ ସେମାନଙ୍କ ଅଂଶକୁ `[Audio N]: <transcript>` ସହ
   ପ୍ରତିସ୍ଥାପନ କରେ। କଲ୍ଗୁଡ଼ିକ `Promise.allSettled` ସହ ଚାଲେ: ଏକ
   ବ୍ୟକ୍ତିଗତ ବିଫଳତା ସେହି ମୂଳ ଅଡିଓ ଅଂଶକୁ ସଂରକ୍ଷିତ ରଖେ (#4012 ଚୁକ୍ତି)।
   ଯଦି ପ୍ରତ୍ୟେକ କଲ୍ ବିଫଳ ହୁଏ ଏବଂ ଲକ୍ଷ୍ୟଟି `supportsAudio === false`
   ବୋଲି ପ୍ରମାଣିତ ହୁଏ, ତେବେ ଅଂଶଗୁଡ଼ିକ
   `[Audio N]: (unavailable — no STT provider connected)` ହୋଇଯାଏ (#8430
   ଚୁକ୍ତି)। ଏକ ଅଜ୍ଞାତ ଲକ୍ଷ୍ୟ (`null`) ପାଇଁ, ସମସ୍ତ କଲ୍ ବିଫଳ ହେଲେ ଫଳାଫଳ
   ଅପରିବର୍ତ୍ତିତ ରହେ। କୌଣସି ବ୍ୟବହାରଯୋଗ୍ୟ STT ପ୍ରମାଣପତ୍ର ନଥିବା ଏକ
   ପ୍ରମାଣିତ ପାଠ୍ୟ-ମାତ୍ର ଲକ୍ଷ୍ୟ କୌଣସି ନେଟ୍ୱର୍କ କଲ୍ ନକରି ସମାନ ସ୍ପଷ୍ଟ
   ଷ୍ଟବ୍ ଗ୍ରହଣ କରେ।

ସଫଳ ଟ୍ରାନ୍ସକ୍ରିପ୍ଟଗୁଡ଼ିକ ପ୍ରକ୍ରିୟା-ବ୍ୟାପୀ Modality Bridge LRU/TTL କ୍ୟାଶ୍
ବ୍ୟବହାର କରେ। କୀ ଅଡିଓ ରେଫରେନ୍ସ, ସ୍ଥିର `audio-transcription` ଅପରେସନ୍
ଲେବଲ୍, ଏବଂ ଚୟନିତ STT ମଡେଲ୍କୁ ସଂଯୋଜନ କରେ; ବିଫଳତାଗୁଡ଼ିକୁ କେବେବି
କ୍ୟାଶ୍ କରାଯାଏ ନାହିଁ। ଅଡିଓ ପ୍ରୟାସଗୁଡ଼ିକ ସହଭାଗୀ `bridged`,
`cacheHits`, `failures`, ଏବଂ `lastUsedAt` କାଉଣ୍ଟର୍ଗୁଡ଼ିକୁ ଅଦ୍ୟତନ କରେ।
ରୂପାନ୍ତରିତ ପ୍ରତିକ୍ରିୟାଗୁଡ଼ିକରେ
`x-omniroute-modality-bridge: audio->text;model=<sttModel>;parts=<n>` ରହେ;
ଅପରିବର୍ତ୍ତିତ ଅନୁରୋଧଗୁଡ଼ିକ Audio Bridge ସେଗମେଣ୍ଟ ପ୍ରାପ୍ତ କରେ ନାହିଁ।

ରନ୍ଟାଇମ୍ ସେଟିଂସ୍ DB-ସମର୍ଥିତ ଏବଂ Zod ଦ୍ୱାରା ବୈଧୀକୃତ:

| କୀ                            | ଡିଫଲ୍ଟ  | ପରିସର                    |
| ----------------------------- | ------- | ------------------------ |
| `modalityBridgeAudioEnabled`  | `true`  | —                        |
| `modalityBridgeAudioModel`    | `""`    | ସ୍ୱୟଂଚାଳିତ କିମ୍ବା STT ID |
| `modalityBridgeAudioTimeout`  | `60000` | 1000–300000              |
| `modalityBridgeAudioMaxClips` | `3`     | 1–10                     |

ସହଭାଗୀ କ୍ୟାଶ୍କୁ ଏବେ ମଧ୍ୟ `modalityBridgeCacheEnabled`,
`modalityBridgeCacheTtlMinutes`, ଏବଂ `modalityBridgeCacheMaxEntries` ଦ୍ୱାରା ନିୟନ୍ତ୍ରଣ କରାଯାଏ।

### ଭିଡିଓ ବ୍ରିଜ୍ (`videoBridge.ts`, `videoBridgePipeline.ts`)

ଜଣାଶୁଣା ନେଟିଭ୍ ଭିଡିଓ ସମର୍ଥନ ନଥିବା ଏକ ଲକ୍ଷ୍ୟକୁ କଲ୍ କରାଯିବା ପୂର୍ବରୁ Chat Completions `messages` ଏବଂ Responses
API `input` ମଧ୍ୟରେ ଥିବା ଶୀର୍ଷ-ସ୍ତରୀୟ ଭିଡିଓ ଅଂଶଗୁଡ଼ିକୁ ଇଣ୍ଟରସେପ୍ଟ କରେ।
ସମର୍ଥିତ ଆକୃତିଗୁଡ଼ିକ ହେଉଛି `input_video`, `video_url`, `video_source`, HTTPS URL,
ଏବଂ `data:video/*;base64,...` ଡାଟା URI। ଟେକ୍ସ୍ଟରେ ଥିବା ସାଧାରଣ ଫାଇଲ୍ନାମଗୁଡ଼ିକୁ
ଭିଡିଓ ଭାବେ ବିବେଚନା କରାଯାଏ ନାହିଁ।

`VideoBridgeGuardrail.preCall` (`videoBridge.ts`) ଅନୁରୋଧ ଟ୍ରାଭର୍ସାଲ୍,
ସାମର୍ଥ୍ୟ/ନୀତି ଯାଞ୍ଚ, ପ୍ରତି-ଅନୁରୋଧ ସମାହାର, ଏବଂ ପ୍ରତିକ୍ରିୟା ପେଲୋଡ୍ର ଦାୟିତ୍ୱ ବହନ କରେ।
ପ୍ରତି-ଭିଡିଓ କାର୍ଯ୍ୟ — ଅଧିଗ୍ରହଣ, ସମ୍ପୂର୍ଣ୍ଣ-ଫଳାଫଳ କ୍ୟାଶ୍, ଏକ ଫ୍ରେମ୍
କ୍ରମକୁ ବର୍ଣ୍ଣନା କରିବା (ଯାହା କଲର୍ଙ୍କ ଦ୍ୱାରା ଘୋଷିତ ଯେକୌଣସି ଅଡିଓ ଟ୍ରାନ୍ସକ୍ରିପ୍ଟକୁ ମିଶ୍ରଣ କରେ), ଏବଂ ପ୍ରତି-ପ୍ରୟାସ
ମେଟ୍ରିକ୍ସ/ବାତିଲ୍/ପରିଷ୍କାର — `videoBridgePipeline.ts` ମଧ୍ୟରେ ଥିବା `processVideoPart` ପଛରେ ଲୁଚି ରହେ,
ଯାହାକୁ `preCall`-ର ଲୁପ୍ ଭିତରେ ପ୍ରତ୍ୟେକ ଭିଡିଓ ଅଂଶ ପାଇଁ ଥରେ କଲ୍ କରାଯାଏ।
ସେହି ମଡ୍ୟୁଲ୍ ସ୍ପଷ୍ଟ ପୋର୍ଟ ସୀମା `VideoMediaBrokerPort`
(ବାଇଟ୍ ଅଧିଗ୍ରହଣ ଏବଂ ନମୁନାଗ୍ରହଣ କରାଯାଇଥିବା ଫ୍ରେମ୍ଗୁଡ଼ିକୁ ନିଷ୍କାସନ କରିବା), `VideoAudioTranscriptionPort`
(କଲର୍ଙ୍କ ଦ୍ୱାରା ଘୋଷିତ ଅଡିଓ ଟ୍ରାନ୍ସକ୍ରିପ୍ଟକୁ ନମୁନାଗ୍ରହଣ କରାଯାଇଥିବା କ୍ୟାପ୍ସନ୍ଗୁଡ଼ିକ ସହିତ ମିଶ୍ରଣ କରିବା), ଏବଂ
`VideoDrilldownPort` (ଫ୍ରେମ୍ ଡ୍ରିଲ୍-ଡାଉନ୍ ସ୍ଥାୟିତ୍ୱ ସୀମା; ଏପର୍ଯ୍ୟନ୍ତ
`processVideoPart` ସହିତ ସଂଯୋଜିତ ହୋଇନାହିଁ — ବର୍ତ୍ତମାନ କେବଳ ପୃଥକ `/api/modality-bridge/video/drilldown`
ରୁଟ୍ଟି ଡ୍ରିଲ୍-ଡାଉନ୍ ଏଣ୍ଟ୍ରି ଲେଖେ) ମଧ୍ୟ ପରିଭାଷିତ କରେ।

ସାର୍ବଜନୀନ `/v1` ଅନୁରୋଧ ପଥ କେବେବି କୌଣସି ସବ୍ପ୍ରୋସେସ୍ ଇମ୍ପୋର୍ଟ କିମ୍ବା ଆହ୍ୱାନ କରେ ନାହିଁ। ରିମୋଟ୍
ଭିଡିଓଗୁଡ଼ିକୁ 50 MiB ସୀମା ମଧ୍ୟରେ ଡାଉନଲୋଡ୍ କରାଯାଏ; ଇନ୍ଲାଇନ୍ base64 ଭିଡିଓଗୁଡ଼ିକ ପାଇଁ
ପ୍ରତି-ଭିଡିଓ ଡିକୋଡ୍ ଆକାରର ଏକ ସତର୍କତାମୂଳକ 36 MiB ସୀମା ରହିଛି, ଯାହାଦ୍ୱାରା ମଡେଲ୍/ମେସେଜ୍/ଫ୍ରେମିଂ ଏନ୍ଭେଲୋପ୍
ସାର୍ବଜନୀନ JSON ଅନୁରୋଧ ଗ୍ରହଣ ସୀମା 50 MiB ମଧ୍ୟରେ ରହିପାରିବ। ଆବଣ୍ଟନ ପୂର୍ବରୁ ଇନ୍ଲାଇନ୍
ଦୈର୍ଘ୍ୟ ଏବଂ ଡିକୋଡ୍-ଆକାର ଆକଳନଗୁଡ଼ିକୁ ଯାଞ୍ଚ କରାଯାଏ। ପ୍ରାରମ୍ଭିକ ରିମୋଟ୍ URL ଏବଂ ପ୍ରତ୍ୟେକ ରିଡାଇରେକ୍ଟରେ HTTPS
ଆବଶ୍ୟକ, ଯେଉଁଥିରେ DNS ପିନିଂ ସହିତ ବିଦ୍ୟମାନ
କେବଳ-ସାର୍ବଜନୀନ ଆଉଟ୍ବାଉଣ୍ଡ ଗାର୍ଡ ବ୍ୟବହୃତ ହୁଏ। ତା’ପରେ ବାଇଟ୍ଗୁଡ଼ିକ ଠିକ୍ ଆଭ୍ୟନ୍ତରୀଣ
`POST /api/modality-bridge/video/extract` ବ୍ରୋକର୍ ସୀମା ଅତିକ୍ରମ କରେ। ସେହି ରୁଟ୍ ଉଭୟ
`LOCAL_ONLY` ଏବଂ `SPAWN_CAPABLE`, କେବଳ ପ୍ରତି-ପ୍ରୋସେସ୍ ପ୍ରମାଣୀକୃତ,

ଗଠନାତ୍ମକ ମୂଲ୍ୟଗୁଡ଼ିକ ନିର୍ଦ୍ଧାରଣବାଦୀ ନମୁନାଗ୍ରହଣ ପ୍ରମାଣ, ଅର୍ଥଗତ ଭିଡିଓ ବୁଝାମଣା ନୁହେଁ। ସେଗୁଡ଼ିକ ବିଷୟ, କାର୍ଯ୍ୟ, କ୍ୟାପ୍ସନ୍, କଥନ କିମ୍ବା ବ୍ୟବହାରକାରୀଙ୍କ ଉଦ୍ଦେଶ୍ୟ ଅନୁମାନ କରନ୍ତି ନାହିଁ। ଦୃଶ୍ୟ ଏବଂ ସ୍ଥିରତା ସୀମାଗୁଡ଼ିକ ସେଗ୍ମେଣ୍ଟ ଗଠନ କରେ; ସ୍ଥିରତା ଆବୃତ୍ତି, ବ୍ଲର୍, ଏକ୍ସପୋଜର୍, ସ୍ଥାନିକ ବିବରଣୀ ଏବଂ ସାମୟିକ ପରିବର୍ତ୍ତନ କେବଳ ବର୍ତ୍ତମାନର 1–16 ଫ୍ରେମ୍ ବଜେଟ୍ କିପରି ବଣ୍ଟନ ହେବ ତାହାକୁ ପ୍ରଭାବିତ କରେ। ସମ୍ପୂର୍ଣ୍ଣ ସ୍ଥିର ସେଗ୍ମେଣ୍ଟକୁ ଗୋଟିଏ ଫ୍ରେମ୍ରେ ସୀମିତ କରାଯାଏ, ଯେତେବେଳେ ଅଣ-ସ୍ଥିର ସେଗ୍ମେଣ୍ଟଗୁଡ଼ିକ ଅବଶିଷ୍ଟ ବଜେଟ୍ ପାଇଁ ପ୍ରତିଦ୍ୱନ୍ଦ୍ୱିତା କରନ୍ତି। ସୀମା ସଂଖ୍ୟା ଫ୍ରେମ୍ ସଂଖ୍ୟାଠାରୁ ଅଧିକ ହେଲେ, ସମୟରେଖାର ସମାନ ଆବୃତ୍ତି ବଜାୟ ରଖାଯାଏ, ଯାହାଦ୍ୱାରା ପ୍ରାରମ୍ଭିକ ଦ୍ରୁତ କଟ୍ଗୁଡ଼ିକ ଏକ ଦୀର୍ଘ ପରବର୍ତ୍ତୀ ସେଗ୍ମେଣ୍ଟକୁ ଲୁଚାଇ ପାରିବ ନାହିଁ। ସ୍ଥିରତା ସୀମାର 1-ସେକେଣ୍ଡ ବିଶ୍ଳେଷଣ ରିଜୋଲ୍ୟୁସନ୍ ମଧ୍ୟରେ ଥିବା ଦୃଶ୍ୟ ସୀମାଗୁଡ଼ିକୁ ଏକତ୍ର କରାଯାଏ।

ଅନୁପସ୍ଥିତ ଫିଲ୍ଟର୍, ବିକୃତ/ଖାଲି ପ୍ରମାଣ, ଚିହ୍ନଟକାରୀ ତ୍ରୁଟି କିମ୍ବା ସୀମିତ ପୂର୍ବ-ବିଶ୍ଳେଷଣ ସମୟସମାପ୍ତି ଘଟିଲେ, ଅବିକଳ ସମାନ ମଧ୍ୟବିନ୍ଦୁ ନୀତିକୁ ଖୋଲା ଭାବେ ଫେରିଯାଏ। କଲର୍ଙ୍କ ବାତିଲ୍ କିମ୍ବା ବ୍ରୋକର୍ ସମୟସୀମା ଏପରି ଖୋଲା ଭାବେ ବିଫଳ ହୁଏ ନାହିଁ: ଏହା ଚାଲୁଥିବା ଉପ-ପ୍ରକ୍ରିୟାକୁ ସମାପ୍ତ କରେ, ପରବର୍ତ୍ତୀ ଫ୍ରେମ୍ ନିଷ୍କାଷଣକୁ ରୋକେ ଏବଂ ବ୍ୟକ୍ତିଗତ ଅସ୍ଥାୟୀ ଟ୍ରିକୁ `finally` ମଧ୍ୟରେ ଅପସାରଣ କରାଯାଏ।

`scripts/perf/video-bridge-fu07-eval.ts` ଡିଡୁପ୍ଲିକେସନ୍ ପରବର୍ତ୍ତୀ କ୍ୟାପ୍ସନ୍-କଲ୍ ସଞ୍ଚୟ, ଘନ-ଗତି ବଜେଟ୍ ବଣ୍ଟନ, ବ୍ଲର୍/ଏକ୍ସପୋଜର୍/SI-TI ପ୍ରମାଣ, ଦୀର୍ଘ ଟେଲ୍ ସହିତ ଦ୍ରୁତ କଟ୍ ଏବଂ କ୍ରମଶଃ-ଫେଡ୍ ମିଥ୍ୟା ସକାରାତ୍ମକ ପାଇଁ ନିର୍ଦ୍ଧାରଣବାଦୀ ପ୍ରକୃତ FFmpeg ଫିକ୍ସଚର୍ ସୃଷ୍ଟି କରେ। ଏହା ପୂର୍ବ-ବିଶ୍ଳେଷଣର ବାସ୍ତବ ସମୟ ଏବଂ ଯେଉଁଠାରେ `/usr/bin/time` ଉପଲବ୍ଧ, ସେଠାରେ ଚାଇଲ୍ଡ CPU ଓ ସର୍ବୋଚ୍ଚ RSS ରେକର୍ଡ କରେ। ଏହାର ଗୁଣବତ୍ତା ଯାଞ୍ଚଗୁଡ଼ିକ କେବଳ ଗଠନାତ୍ମକ ଅରାକଲ୍। ପ୍ରକୃତ କ୍ୟାପ୍ସନ୍-ମଡେଲ୍ ଗୁଣବତ୍ତା `HOLD` ଭାବେ ରହେ, କାରଣ ଏହି ହାର୍ନେସ୍ର କୌଣସି ଅଧିକୃତ ଏଣ୍ଡପଏଣ୍ଟ କିମ୍ବା ସ୍ଥିରୀକୃତ ବିଚାରକ ନାହିଁ। `--caption-cost-per-call-usd` ଏକ ସ୍ପଷ୍ଟ ସକାରାତ୍ମକ ପ୍ରତି-କଲ୍ ଆନୁମାନିକ ମୂଲ୍ୟ ଯୋଗାଇ ନ ଦେଲେ ଆର୍ଥିକ ସଞ୍ଚୟ ମଧ୍ୟ `HOLD` ଭାବେ ରହେ; ସ୍କ୍ରିପ୍ଟ କୌଣସି ଫଳାଫଳ ମନଗଢ଼ା ଭାବେ ସୃଷ୍ଟି କରେ ନାହିଁ।

ପ୍ରତ୍ୟେକ ଫ୍ରେମ୍ 4 MiB, ସମସ୍ତ କଚ୍ଚା ଫ୍ରେମ୍ ମିଶି 23 MiB ଏବଂ କ୍ରମିକୀକୃତ ବ୍ରୋକର୍ ପ୍ରତିକ୍ରିୟା 32 MiB ପର୍ଯ୍ୟନ୍ତ ସୀମିତ। ଗୋଟିଏ ବ୍ୟକ୍ତିଗତ ଅସ୍ଥାୟୀ ଡିରେକ୍ଟୋରିକୁ `finally` ମଧ୍ୟରେ ଅପସାରଣ କରାଯାଏ। OmniRoute FFmpegକୁ ସହିତ ବଣ୍ଡଲ୍ କରେ ନାହିଁ ଏବଂ କୌଣସି କଷ୍ଟମ୍ ଏକ୍ଜିକ୍ୟୁଟେବଲ୍ ପଥ ଗ୍ରହଣ କରେ ନାହିଁ। କ୍ୟାପ୍ସନିଂ ପୂର୍ବରୁ, ବ୍ରିଜ୍ ଏକ ସଂରକ୍ଷଣଶୀଳ ଭିଜୁଆଲ୍ ଡିଡୁପ୍ଲିକେସନ୍ ପାସ୍ ପ୍ରୟୋଗ କରେ: ପ୍ରତ୍ୟେକ JPEGକୁ 16×16 ଗ୍ରେସ୍କେଲ୍ ବଫର୍କୁ ହ୍ରାସ କରାଯାଏ ଏବଂ କେବଳ ଶେଷରେ ରଖାଯାଇଥିବା ଫ୍ରେମ୍ ସହିତ ତୁଳନା କରାଯାଏ। ଗୋଟିଏ ଫ୍ରେମ୍ଠାରୁ ଅଧିକ ଅନୁରୋଧିତ କ୍ୟାପ୍ସନ୍ ବଜେଟ୍ ପାଇଁ, ନିଷ୍କାଷଣ ସେହି ବଜେଟ୍ର ଦୁଇଗୁଣ ପର୍ଯ୍ୟନ୍ତ ଏବଂ କେବେବି 16 ଫ୍ରେମ୍ଠାରୁ ଅଧିକ ନୁହେଁ ଏପରି ଏକ ସୀମିତ ପ୍ରାର୍ଥୀ ପୁଲ୍ ଯୋଗାଏ। ଅନୁରୋଧିତ ସୀମା କେବଳ ଡିଡୁପ୍ଲିକେସନ୍ ପରେ ପ୍ରୟୋଗ ହୁଏ; ବଜେଟ୍ ଅତି କମରେ ଦୁଇ ହେଲେ ଅନ୍ତିମ ପତଳାକରଣ ସମୟରେ ପ୍ରଥମ ଏବଂ ଶେଷ ଚୟନିତ ପ୍ରାର୍ଥୀକୁ ସଂରକ୍ଷିତ ରଖାଯାଏ। ସଂସ୍କରଣଯୁକ୍ତ `grayscale-16x16-mean-cells-v2` ନୀତି ହାରାହାରି ଲୁମା ଡେଲ୍ଟା ଏବଂ ଯେଉଁ ଥମ୍ବନେଲ୍ ସେଲ୍ଗୁଡ଼ିକର ସାମାନ୍ୟୀକୃତ ଡେଲ୍ଟା ଅତି କମରେ 0.05, ସେଗୁଡ଼ିକର ଅନୁପାତ ମଧ୍ୟରୁ ବଡ଼ଟିକୁ ବ୍ୟବହାର କରେ। ଡୁପ୍ଲିକେଟ୍ ସୀମା ସ୍ଥିରାଙ୍କ 0.04, ଯାହାକୁ ରନ୍ଟାଇମ୍ ସେଟିଂ ଭାବେ ଉନ୍ମୁକ୍ତ କରିବା ପରିବର୍ତ୍ତେ ପୂର୍ବାନୁମାନଯୋଗ୍ୟତା ପାଇଁ ବାଛାଯାଇଛି। ଏହି ଦ୍ୱିତୀୟ ଉଚ୍ଚ-କନ୍ଟ୍ରାଷ୍ଟ ସଙ୍କେତ କ୍ଷୁଦ୍ର ଗତି ଏବଂ ଦୃଶ୍ୟମାନ-ପାଠ୍ୟ ପରିବର୍ତ୍ତନକୁ ସଂରକ୍ଷଣ କରେ, ଯାହାକୁ କେବଳ-ହାରାହାରି ତୁଳନା ଲୁଚାଇପାରେ। ତୁଳନାକାରୀ କିମ୍ବା ଡିକୋଡର୍ ତ୍ରୁଟି ଘଟିଲେ ଏହା ଖୋଲା ଭାବେ ବିଫଳ ହୋଇ ଆବୃତ୍ତିକୁ ବଜାୟ ରଖେ। ଆଉଟପୁଟ୍ ମେଟାଡାଟା ନିଷ୍କାଷିତ ପ୍ରାର୍ଥୀ, ସଫଳତାର ସହ ବ୍ୟବହୃତ ଫ୍ରେମ୍ ଏବଂ ବାଦ ଦିଆଯାଇଥିବା ଭିଜୁଆଲ୍ ଡୁପ୍ଲିକେଟ୍ଗୁଡ଼ିକୁ ପୃଥକ କରେ।

ସ୍ପଷ୍ଟ ଭାବେ ଚିହ୍ନିତ ଭିଡିଓ ଅଂଶ ଏକ ସମୟମୁଦ୍ରାଯୁକ୍ତ କଣ୍ଟାକ୍ଟ ଶିଟ୍ ଅନୁରୋଧ କରିପାରେ। ବ୍ରିଜ୍ ସର୍ବାଧିକ 4-ସ୍ତମ୍ଭ ଏବଂ 16-ଫ୍ରେମ୍ର JPEG ଗ୍ରିଡ୍ ନିର୍ମାଣ କରେ। ପ୍ରତ୍ୟେକ 512-ପିକ୍ସେଲ୍ ସେଲ୍ ଏହାର ଉତ୍ସ ସମୟମୁଦ୍ରାକୁ ଏକ ଉଚ୍ଚ-କନ୍ଟ୍ରାଷ୍ଟ ତଳ ବ୍ୟାଣ୍ଡ୍ରେ ସ୍ଥାୟୀ ଭାବେ ଅଙ୍କିତ କରେ, ଯେତେବେଳେ ସେହି ସମୟମୁଦ୍ରାଗୁଡ଼ିକ ପରବର୍ତ୍ତୀ ସଂଯୋଜନ ଏବଂ ଅଡିଟ୍ ପାଇଁ ପାଠ୍ୟ ମେଟାଡାଟାରେ ରହିଥାଏ। ସମ୍ପୂର୍ଣ୍ଣ JPEG 32 MiBରେ ସୀମିତ ରହେ। ଯଦି `sharp` ଗ୍ରିଡ୍କୁ ଡିକୋଡ୍ କିମ୍ବା ସଂଯୋଜନ କରିପାରେ ନାହିଁ, ବ୍ରିଜ୍ ବ୍ୟକ୍ତିଗତ JPEG ଫ୍ରେମ୍ଗୁଡ଼ିକୁ ଫେରିଯାଏ; କ୍ଲାଏଣ୍ଟ ବାତିଲ୍ ତଥାପି ଶିଟ୍ କାର୍ଯ୍ୟ ମାଧ୍ୟମରେ ପ୍ରସାରିତ ହୁଏ।

ପଦୋନ୍ନତି ପ୍ରମାଣକୁ ସିନ୍ଥେଟିକ୍ ସଂଯୋଜନ ମାଇକ୍ରୋବେଞ୍ଚମାର୍କଠାରୁ ଉଦ୍ଦେଶ୍ୟମୂଳକ ଭାବେ ପୃଥକ ରଖାଯାଇଛି। `scripts/perf/video-bridge-contact-sheet-eval.ts` ପ୍ରକୃତ OpenAI-ସୁସଙ୍ଗତ ଭିଜନ୍ ମଡେଲ୍ଗୁଡ଼ିକ ପାଇଁ ଏକ ସ୍କିମା-ସଂସ୍କରଣଯୁକ୍ତ A/B ହାର୍ନେସ୍ ନିର୍ଦ୍ଧାରଣ କରେ। ଏହା ପ୍ରଦାନକାରୀ-ପ୍ରତିବେଦିତ ଟୋକେନ୍, ଆରମ୍ଭରୁ ଶେଷ ପର୍ଯ୍ୟନ୍ତ ବାସ୍ତବ ବିଳମ୍ବତା (ଶିଟ୍ ସଂଯୋଜନ ସମେତ), ମଡେଲ୍-କଲ୍ ସଂଖ୍ୟା ଏବଂ ମ୍ୟାନିଫେଷ୍ଟ-ନିର୍ଦ୍ଧାରିତ ତଥ୍ୟ ଧାରଣ ମାପେ। କଚ୍ଚା ମଡେଲ୍ ପ୍ରତିକ୍ରିୟାଗୁଡ଼ିକ ପ୍ରତିବେଦନରେ ଲେଖାଯାଏ ନାହିଁ; କେବଳ SHA-256 ଡାଇଜେଷ୍ଟ ଏବଂ ମେଳ ହୋଇଥିବା ତଥ୍ୟ IDଗୁଡ଼ିକ ରଖାଯାଏ। `--execute-real` ପାସ୍ କରାଯାଇ ଏବଂ `--model`, `OMNIROUTE_BASE_URL`, ଓ `OMNIROUTE_API_KEY` ବିନ୍ୟାସ କରାଯାଇ ନଥିଲେ ହାର୍ନେସ୍ କୌଣସି ନେଟୱର୍କ କିମ୍ବା ଦେୟଯୁକ୍ତ ମଡେଲ୍ କଲ୍ କରେ ନାହିଁ। ସେହି ସ୍ପଷ୍ଟ ପ୍ରକୃତ ରନ୍ ବିନା, ଏହାର ଯନ୍ତ୍ର-ପଠନୀୟ ନିଷ୍ପତ୍ତି `HOLD` ଭାବେ ରହେ; କେବଳ ସିନ୍ଥେଟିକ୍ ପେଲୋଡ୍/କଲ୍-ସଂଖ୍ୟା ମାପଗୁଡ଼ିକ ପଦୋନ୍ନତି ପ୍ରମାଣ ନୁହେଁ।

କଲର୍ମାନେ ପୂର୍ବରୁ ସମୟ-ସମନ୍ୱିତ ପାଠ୍ୟ ରଖିଥିଲେ, ଏକ ସମର୍ଥିତ ଭିଡିଓ ଅଂଶରେ ଏକ ଇଚ୍ଛାଧୀନ `transcript.cues` ଆରେ ସଂଲଗ୍ନ କରିପାରିବେ। ପ୍ରତ୍ୟେକ କ୍ୟୁରେ `text`, ଯାଞ୍ଚ କରାଯାଇଥିବା ଅବଧି ଭିତରେ ଏକ ସସୀମ `start`/`end` ଅନ୍ତରାଳ ଏବଂ ଏକ ଅନୁମୋଦିତ-ତାଲିକାଭୁକ୍ତ `source` (`client`, `embedded`, କିମ୍ବା `audio-bridge`) ଥିବା ଆବଶ୍ୟକ; `confidence`ର ଡିଫଲ୍ଟ ମୂଲ୍ୟ `1` ଏବଂ ଏହା `0` ଓ `1` ମଧ୍ୟରେ ରହିବା ଆବଶ୍ୟକ। ଅବିକଳ ଡୁପ୍ଲିକେଟ୍ କ୍ୟୁଗୁଡ଼ିକୁ ଏକତ୍ର କରାଯାଏ। OmniRoute ଏହି ମେଟାଡାଟାରୁ କେବେବି ଟ୍ରାନ୍ସକ୍ରିପ୍ସନ୍ ଆରମ୍ଭ କରେ ନାହିଁ: ବୈଧୀକୃତ କ୍ୟୁଗୁଡ଼ିକୁ ଉତ୍ସ, ବିଶ୍ୱାସ୍ୟତା ଏବଂ ଅନ୍ତରାଳ ସହିତ ବର୍ଣ୍ଣିତ ଫଳାଫଳକୁ କପି କରାଯାଏ ଏବଂ ଫ୍ରେମ୍ କ୍ୟାପ୍ସନ୍ଗୁଡ଼ିକ ସହିତ ଅବିଶ୍ୱସ୍ତ ପର୍ଯ୍ୟବେକ୍ଷଣ ଭାବେ ପ୍ରଦର୍ଶିତ କରାଯାଏ। ଅବୈଧ, ସୀମା-ବାହାର କିମ୍ବା ଉତ୍ପତ୍ତି-ସୂଚନାବିହୀନ ପାଠ୍ୟକୁ କ୍ୟାପ୍ସନ୍ ଷ୍ଟ୍ରିମ୍ରେ ମିଶାଇବା ପରିବର୍ତ୍ତେ ପ୍ରତ୍ୟାଖ୍ୟାନ କରାଯାଏ। ଉଭୟ ଅନୁରୋଧ-ବଡି ଟ୍ରାନ୍ସକ୍ରିପ୍ଟ ଚ୍ୟାନେଲ୍ ଯୋଗାଇ ଦିଆଯାଇଥିବା ଉତ୍ପତ୍ତିକୁ `client`ରେ ସାମାନ୍ୟୀକୃତ କରେ, ଯାହା ମଧ୍ୟରେ ସ୍ୱୟଂ-ଦାବିକୃତ `embedded` କିମ୍ବା `audio-bridge` ଲେବଲ୍ ମଧ୍ୟ ଅନ୍ତର୍ଭୁକ୍ତ। କେବଳ ସର୍ଭର୍-ମାଲିକାନାଧୀନ ଆଡାପ୍ଟର୍ କୋଡ୍-ମାତ୍ର `trustedSource` ଆର୍ଗୁମେଣ୍ଟ ମାଧ୍ୟମରେ ସେହି ବିଶ୍ୱସ୍ତ ଲେବଲ୍ଗୁଡ଼ିକ ନ୍ୟସ୍ତ କରିପାରିବ; ଅନୁରୋଧର JSON ଫିଲ୍ଡ ସେହି ଆର୍ଗୁମେଣ୍ଟ ପର୍ଯ୍ୟନ୍ତ ପହଞ୍ଚିପାରିବ ନାହିଁ। ଉତ୍ପତ୍ତି ଯାହାହେଉ ନା କାହିଁକି, ଟ୍ରାନ୍ସକ୍ରିପ୍ଟ ପାଠ୍ୟ ଅବିଶ୍ୱସ୍ତ ମିଡିଆ-ଉତ୍ପନ୍ନ ବିଷୟବସ୍ତୁ ଭାବେ ରହେ ଏବଂ କେବେବି ପ୍ରାଧିକରଣ ନିର୍ଦ୍ଧାରଣ କରିବା ଉଚିତ୍ ନୁହେଁ।

  ବିଫଳ ହେଉଥିବା ପ୍ୟାଟର୍ନ୍କୁ ସେଭ୍ ଓ ପରୀକ୍ଷା ସମୟରେ ପ୍ରତ୍ୟାଖ୍ୟାନ କରାଯାଏ, ଏବଂ ବିଫଳ ହେଉଥିବା ଏକ ସଂରକ୍ଷିତ ଧାଡ଼ିକୁ
  ରନ୍ଟାଇମ୍ରେ କମ୍ପାଇଲ୍ କରିବା ପରିବର୍ତ୍ତେ ଏଡ଼ାଇ ଦିଆଯାଏ। କଷ୍ଟମ୍ ପ୍ୟାଟର୍ନ୍ଗୁଡ଼ିକ କେବଳ
  ମାସ୍କିଂ ସକ୍ରିୟ ଥିବାବେଳେ ଚାଲେ।
- **ଚିହ୍ନଟ କାଉଣ୍ଟର୍** — ପ୍ରତି-ପ୍ରକାର ସଂଖ୍ୟା (ମେଳ ହୋଇଥିବା ମୂଲ୍ୟ କେବେବି ନୁହେଁ), ମେମୋରୀରେ ରଖାଯାଏ
  ଏବଂ ପୁନଃଆରମ୍ଭରେ ରିସେଟ୍ ହୁଏ (`src/lib/pii/piiDetectionStats.ts`)। ଏଗୁଡ଼ିକ କେବଳ
  ମାସ୍କିଂ ସକ୍ରିୟ ଥିବାବେଳେ ବୃଦ୍ଧି ପାଏ।

ସେଟିଂଗୁଡ଼ିକ `key_value` ଟେବୁଲ୍ରେ (ନେମ୍ସ୍ପେସ୍ `pii_settings`,
`src/lib/db/piiSettings.ts`) ରହେ ଏବଂ 1 s କ୍ୟାଶ୍ ମାଧ୍ୟମରେ ପଢ଼ାଯାଏ। API:

| ପଦ୍ଧତି | ପଥ                       | ଉଦ୍ଦେଶ୍ୟ                                                                               |
| ------ | ------------------------ | -------------------------------------------------------------------------------------- |
| `GET`  | `/api/settings/pii`      | ଫ୍ଲାଗ୍ ସ୍ଥିତି, `enabledTypes`, `customPatterns`, ଚିହ୍ନଟ କାଉଣ୍ଟର୍                       |

### ପ୍ରମ୍ପ୍ଟ୍ ଇଞ୍ଜେକ୍ସନ୍ (`promptInjection.ts`)

ବ୍ୟବହାରକାରୀ-ପ୍ରଦତ୍ତ ବିଷୟବସ୍ତୁରେ ପ୍ରତିକୂଳ ସଂରଚନାଗୁଡ଼ିକୁ ଚିହ୍ନଟ କରେ ଏବଂ
ବିନ୍ୟାସିତ ନୀତିକୁ ଲାଗୁ କରେ। ଆଚରଣ ପରିବେଶ ଭେରିଏବଲ୍ ଏବଂ କନ୍ଷ୍ଟ୍ରକ୍ଟର୍
ବିକଳ୍ପଗୁଡ଼ିକ ଦ୍ୱାରା ପରିଚାଳିତ:

| ସେଟିଂ            | Env var                                                                                               | ଡିଫଲ୍ଟ | ପ୍ରଭାବ                                                                                                                                                                                                  |
| ---------------- | ----------------------------------------------------------------------------------------------------- | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ସକ୍ଷମ            | `INPUT_SANITIZER_ENABLED`                                                                             | `true` | `false` ହେଲେ, guardrail short-circuit କରେ।                                                                                                                                                              |
| ମୋଡ୍             | `INJECTION_GUARD_MODE` / `INPUT_SANITIZER_MODE`                                                       | `warn` | Injection ନୀତି: `block`, `warn`, କିମ୍ବା `log`। (`redact` ପଛୁଆ-ସୁସଙ୍ଗତତା ପାଇଁ ଗ୍ରହଣ କରାଯାଏ, କିନ୍ତୁ injection ପାଠ୍ୟକୁ ବାଦ ଦିଏ **ନାହିଁ**; ଅନୁରୋଧ PII ପୁନର୍ଲିଖନ `PII_REDACTION_ENABLED` ଦ୍ୱାରା ନିୟନ୍ତ୍ରିତ।) |
| ବ୍ଲକ୍ ଥ୍ରେଶହୋଲ୍ଡ | `blockThreshold` ବିକଳ୍ପ / `INPUT_SANITIZER_BLOCK_THRESHOLD` (ଉପନାମ `INJECTION_GUARD_BLOCK_THRESHOLD`) | `high` | ବ୍ଲକ୍ କରିବା ପାଇଁ ଆବଶ୍ୟକ ସର୍ବନିମ୍ନ ଗୁରୁତ୍ୱ। ଡିଫଲ୍ଟ ଭାବେ Medium କେବଳ ପର୍ଯ୍ୟବେକ୍ଷଣଯୋଗ୍ୟ।                                                                                                                   |

**ମୋଡ୍ ଅଗ୍ରାଧିକାର** (`getMode`): କଲର୍ `options.mode` →
`INJECTION_GUARD_MODE` **DB feature-flag override** (Dashboard → Settings →
Feature Flags) → `INJECTION_GUARD_MODE` env → `INPUT_SANITIZER_MODE` env →
`warn`। ତେଣୁ ଏକ dashboard override, env vars ଉପରେ ଅଗ୍ରାଧିକାର ପାଏ; ଫଳରେ Feature
Flags UI ଚାଲୁଥିବା guardକୁ ସଜୀବ ଭାବରେ ନିୟନ୍ତ୍ରଣ କରେ (ପୁନଃଚାଳନ ଆବଶ୍ୟକ ନୁହେଁ)। DB ପଠନ fail-safe:
ଏଥିରେ ତ୍ରୁଟି ହେଲେ, guardଟି env-ଆଧାରିତ ଆଚରଣକୁ ଫେରିଯାଏ, ଏବଂ କୌଣସି
override ସେଟ୍ ନଥିଲେ ଆଚରଣ env-only resolution ସହ ସମାନ ରହେ।

ଚିହ୍ନଟ ଉତ୍ସଗୁଡ଼ିକ:

1. `@/shared/utils/inputSanitizer`ରୁ `sanitizeRequest()` (pipelineର ଅନ୍ୟ ସ୍ଥାନରେ
   ବ୍ୟବହୃତ shared detector set)।
2. ଅନ୍ତର୍ନିହିତ `DEFAULT_GUARD_PATTERNS` (ବର୍ତ୍ତମାନ `system_override_inline` ଏବଂ
   `markdown_system_block`, ଉଭୟର severity `high`)।
3. constructor ବିକଳ୍ପ ମାଧ୍ୟମରେ ପ୍ରଦାନ କରାଯାଇଥିବା ଇଚ୍ଛାଧୀନ `customPatterns` (strings, regex,
   କିମ୍ବା `{ name, pattern, severity }` records)।

ଯେତେବେଳେ `mode === "block"` **ଏବଂ** ଅତି କମରେ ଗୋଟିଏ ଚିହ୍ନଟ severity
threshold ପୂରଣ କରେ, `preCall` `{ block: true, message: "Request rejected:
suspicious content detected" }` ଫେରାଏ। `warn`/`log` ମୋଡ୍ରେ guardrail log କରେ, କିନ୍ତୁ
callକୁ ଅନୁମତି ଦିଏ। registry ମାଧ୍ୟମରେ ନ ଯାଇ promptଗୁଡ଼ିକୁ ମୂଲ୍ୟାୟନ କରିବାକୁ ଆବଶ୍ୟକ
କରୁଥିବା callerମାନଙ୍କ ପାଇଁ shared helper `evaluatePromptInjection()` ମଧ୍ୟ export କରାଯାଇଛି।

**Scan ସୀମା (v3.8.20):** detectorଟି ଯୋଡ଼ାଯାଇଥିବା prompt ପାଠ୍ୟର କେବଳ **ପ୍ରଥମ 16 KB**
ଯାଞ୍ଚ କରେ — `src/shared/utils/inputSanitizer.ts`ରେ
`MAX_INJECTION_SCAN_BYTES = 16 * 1024` (16 384 bytes)। Pattern loop ଚଲାଇବା ପୂର୍ବରୁ
`detectInjection()` ଏବଂ `evaluatePromptInjection()` ଉଭୟ
`slice(0, MAX_INJECTION_SCAN_BYTES)` କରନ୍ତି। Injection ନିର୍ଦ୍ଦେଶଗୁଡ଼ିକ inputର ଉପର ଭାଗ ନିକଟରେ ରହେ, ତେଣୁ ଏହା
ଚିହ୍ନଟକୁ ଦୁର୍ବଳ ନକରି multi-hundred-KB payloadଗୁଡ଼ିକରେ regex CPU/GCକୁ ସୀମିତ କରେ (ଦେଖନ୍ତୁ
#3932, #4041)।

### Credential Masker (`credentialMasker.ts`)

**ଉଭୟ** stageରେ, ଡିଫଲ୍ଟ chainରେ ଶେଷରେ (priority `95`) ଚାଲେ। Outbound payloadରୁ
(message content, tool-call arguments, tool results) **ଏବଂ** provider responseରୁ
ସୁପରିଚିତ API-key / secret-token patternଗୁଡ଼ିକୁ ଲୁଚାଏ, ଯାହାଦ୍ୱାରା promptରେ paste କରାଯାଇଥିବା
କୌଣସି credential (କିମ୍ବା tool result ଦ୍ୱାରା ପ୍ରତିଧ୍ୱନିତ) upstream provider କିମ୍ବା clientଙ୍କ
ନିକଟକୁ ପୁନର୍ବାର ପ୍ରକାଶିତ ହୁଏ ନାହିଁ।

- **କେବଳ opt-in**, PII redaction ସହ ସମାନ ପ୍ରଥା (Hard Rule #20-ସଂଲଗ୍ନ):
  `settings.credentialRedactionEnabled === true` **କିମ୍ବା**
  `CREDENTIAL_REDACTION_ENABLED=true` ନହେଲେ ଅକ୍ଷମ ରହେ। ଏହା ବନ୍ଦ ଥିଲେ, guardrailଟି no-op —
  ଏହା କେବେ ବ୍ଲକ୍ କିମ୍ବା ପୁନର୍ଲିଖନ କରେ ନାହିଁ।
- `redactCredentials()` ସମ୍ପୂର୍ଣ୍ଣ payload/response treeରେ ବିଚରଣ କରେ (`walkValue()`,
  prototype-pollution-safe, `WeakSet` ମାଧ୍ୟମରେ cycle-safe) ଏବଂ ମେଳଗୁଡ଼ିକୁ
  `[REDACTED:<type>]` placeholder ସହ ବଦଳାଏ; କେବଳ ପ୍ରକୃତରେ ପରିବର୍ତ୍ତିତ branchଗୁଡ଼ିକୁ clone କରେ।
- `CREDENTIAL_PATTERNS` LLM provider keyଗୁଡ଼ିକ (OpenAI, OpenAI-proj,
  Anthropic, Google, Hugging Face, Replicate), VCS/SaaS tokenଗୁଡ଼ିକ (GitHub, Slack,
  Linear, Notion, npm, Postman, Discord), payment keyଗୁଡ଼ିକ (Stripe, Square), cloud
  keyଗୁଡ଼ିକ (AWS access key, Twilio, SendGrid, Mailgun), private key / JWT,
  credential ଧାରଣ କରୁଥିବା connection stringଗୁଡ଼ିକ (`mongodb://user:pass@...`, ଇତ୍ୟାଦି), ଏବଂ
  ଏକ ସାଧାରଣ `Authorization`/`x-api-key`/`api-key`/`apikey` header-value
  patternକୁ ଅନ୍ତର୍ଭୁକ୍ତ କରେ। Header ଆକୃତିର keyଗୁଡ଼ିକ (`authorization`, `x-api-key`, `api-key`,
  `apikey`) ସାଧାରଣ text regex ମାଧ୍ୟମରେ ନୁହେଁ, ଗଠନାତ୍ମକ ଭାବେ redacted ହୁଏ (କେବଳ value;
  `Bearer `/`Basic ` ପରି scheme prefix ସଂରକ୍ଷିତ ରହେ)।
- guardrailଟି କେବେ ବ୍ଲକ୍ କରେ ନାହିଁ; ଏହା କେବଳ ପୁନର୍ଲିଖନ (`modifiedPayload` /
  `modifiedResponse`) ଏବଂ annotation (`meta.credentialsRedacted`, `meta.count`) କରେ।

Regression guard: `tests/unit/credential-masker-guardrail.test.ts`।

## ମୂଳ କନ୍ଟ୍ରାକ୍ଟ (`base.ts`)

```typescript
class BaseGuardrail {
  enabled: boolean;
  name: string;
  priority: number;

  constructor(name: string, options?: { enabled?: boolean; priority?: number });

  async preCall(payload: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;

  async postCall(response: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;
}

interface GuardrailResult<TValue = unknown> {
  block?: boolean; // true ଚେନ୍କୁ ତତ୍କ୍ଷଣାତ୍ ବନ୍ଦ କରେ
  message?: string; // ବ୍ଲକ୍ କରାଯିବା ସମୟରେ ପ୍ରଦର୍ଶିତ ହୁଏ
  meta?: Record<string, unknown> | null;
  modifiedPayload?: TValue; // ଅନୁରୋଧକୁ ପୁନଃଲେଖନ କରିବା ପାଇଁ preCall ଦ୍ୱାରା ଫେରାଯାଏ
  modifiedResponse?: TValue; // ପ୍ରତିକ୍ରିୟାକୁ ପୁନଃଲେଖନ କରିବା ପାଇଁ postCall ଦ୍ୱାରା ଫେରାଯାଏ
}

interface GuardrailContext {
  apiKeyInfo?: Record<string, unknown> | null;
  disabledGuardrails?: string[] | null;
  endpoint?: string | null;
  headers?: Headers | Record<string, unknown> | null;
  log?: GuardrailLog | Console | null;
  method?: string | null;
  model?: string | null;
  provider?: string | null;
  signal?: AbortSignal;
  sourceFormat?: string | null;
  stream?: boolean;
  targetFormat?: string | null;
}
```

ଏକ ଗାର୍ଡରେଲ୍ `void`, `{}`, କିମ୍ବା `{ block: false }` ଫେରାଇ "କୌଣସି ପରିବର୍ତ୍ତନ ନାହିଁ" ବୋଲି ସୂଚାଏ।
ଏକ `modifiedPayload`/`modifiedResponse` ଫେରାଇଲେ, ପରବର୍ତ୍ତୀ ଗାର୍ଡରେଲ୍ଗୁଡ଼ିକ ପାଇଁ ଚେନ୍ ମଧ୍ୟରେ ପ୍ରବାହିତ ହେଉଥିବା ମୂଲ୍ୟଟି ପ୍ରତିସ୍ଥାପିତ ହୁଏ।
`signal?: AbortSignal` କଲ୍କାରୀଙ୍କ ଜୀବନଚକ୍ରକୁ ଗାର୍ଡରେଲ୍ଗୁଡ଼ିକ ମଧ୍ୟକୁ ବହନ କରେ। ଏକ ଅନୁରୋଧ ବାତିଲ୍ ହେବା ହେଉଛି ଉଦ୍ଦେଶ୍ୟମୂଳକ fail-open ବ୍ୟତିକ୍ରମ: ମିଡିଆ ବ୍ରିଜ୍ଗୁଡ଼ିକ କାର୍ଯ୍ୟ ବନ୍ଦ କରି ସଫା କରନ୍ତି, କିନ୍ତୁ ଏହାକୁ ସମର୍ଥନ କରେନାହିଁ ବୋଲି ଜଣାଶୁଣା ଟାର୍ଗେଟ୍ରେ କଞ୍ଚା ମିଡିଆକୁ ପୁନଃସ୍ଥାପନ କରନ୍ତି ନାହିଁ।

## ରେଜିଷ୍ଟ୍ରି (`registry.ts`)

ସିଙ୍ଗଲଟନ୍ `guardrailRegistry` ନିମ୍ନଲିଖିତଗୁଡ଼ିକୁ ପ୍ରଦାନ କରେ:

- `register(guardrail)` — ଏକ ଗାର୍ଡରେଲ୍ ଯୋଡ଼େ (କିମ୍ବା ସ୍ୱାଭାବିକୀକୃତ ନାମ ଅନୁସାରେ ପ୍ରତିସ୍ଥାପନ କରେ) ଏବଂ
  ଊର୍ଦ୍ଧ୍ୱଗାମୀ `priority` ଅନୁସାରେ ପୁନଃ ସଜାଏ।
- `clear()` / `list()` — ପ୍ରଶାସନିକ ସହାୟକ।
- `runPreCallHooks(payload, context)` — ସକ୍ରିୟ ଗାର୍ଡରେଲ୍ଗୁଡ଼ିକୁ କ୍ରମାନ୍ୱୟରେ ଚଲାଏ, ପେଲୋଡ୍କୁ
  `modifiedPayload` ମାଧ୍ୟମରେ ପଠାଏ ଏବଂ ପ୍ରଥମ `block: true` ମିଳିଲେ ବନ୍ଦ କରେ।
- `runPostCallHooks(response, context)` — ପ୍ରତିକ୍ରିୟା ପକ୍ଷରେ ସମାନ ପ୍ରବାହ।
- `resetGuardrailsForTests({ registerDefaults })` — ସ୍ଥିତି ସଫା କରେ ଏବଂ ସ୍ୱଚ୍ଛ ପରୀକ୍ଷଣ ପୃଥକୀକରଣ ପାଇଁ
  ଇଚ୍ଛାନୁସାରେ ଡିଫଲ୍ଟଗୁଡ଼ିକୁ ପୁନଃ ପଞ୍ଜୀକୃତ କରେ।

ଉଭୟ ରନର୍ `{ blocked, payload|response, results, guardrail?, message? }`
ଫେରାନ୍ତି, ଯେଉଁଠାରେ `results` ହେଉଛି `GuardrailExecutionResult` ରେକର୍ଡଗୁଡ଼ିକର ଏକ ଆରେ, ଯେଉଁଥିରେ
ପ୍ରତ୍ୟେକ ଗାର୍ଡରେଲ୍ ପାଇଁ `blocked`, `skipped`, `modified`, `error`, ଏବଂ `meta` ଫିଲ୍ଡ ଅନ୍ତର୍ଭୁକ୍ତ ଥାଏ,
ଯାହା ଟ୍ରେସିଂ ପାଇଁ ଉପଯୋଗୀ।

### ପ୍ରତ୍ୟେକ ଅନୁରୋଧ ପାଇଁ ଗାର୍ଡରେଲ୍ ଅକ୍ଷମ କରିବା

`resolveDisabledGuardrails({ apiKeyInfo, body, headers })` ବର୍ତ୍ତମାନର
ଅନୁରୋଧ ପାଇଁ ଏଡ଼ାଇ ଦିଆଯିବା ଉଚିତ ଗାର୍ଡରେଲ୍ ନାମଗୁଡ଼ିକର ଏକ
ନକଲମୁକ୍ତ ତାଲିକା ସଂଗ୍ରହ କରେ। ଉତ୍ସଗୁଡ଼ିକ (ସବୁ ଇଚ୍ଛାଧୀନ, ସବୁ ମିଶ୍ରିତ):

- `apiKeyInfo.disabledGuardrails`
- ଅନୁରୋଧ ବଡିର `disabledGuardrails` (ଶୀର୍ଷ ସ୍ତର)
- ଅନୁରୋଧ ବଡିର `metadata.disabledGuardrails`
- ହେଡର୍ `x-omniroute-disabled-guardrails` (କିମ୍ବା ପୁରୁଣା
  `x-disabled-guardrails`)

ମୂଲ୍ୟଗୁଡ଼ିକ ଷ୍ଟ୍ରିଂର ଆରେ କିମ୍ବା କମା-ପୃଥକ ଷ୍ଟ୍ରିଂ ହୋଇପାରେ; ନାମଗୁଡ଼ିକୁ
ଲୋୟରକେସ୍ kebab-case (`pii_masker` → `pii-masker`) କୁ ସ୍ୱାଭାବିକୀକୃତ କରାଯାଏ। ଫଳାଫଳଟି
`context.disabledGuardrails` ମାଧ୍ୟମରେ ରେଜିଷ୍ଟ୍ରିକୁ ପଠାଯାଏ, ଯାହା ମେଳ ଖାଉଥିବା
ଗାର୍ଡରେଲ୍ଗୁଡ଼ିକୁ ଏଡ଼ାଇ ଦିଏ (`results` ମଧ୍ୟରେ `skipped: true`)।

## କାର୍ଯ୍ୟନିଷ୍ପାଦନ କ୍ରମ

`src/sse/handlers/chat.ts` ଏବଂ
`open-sse/handlers/chatCore.ts` ମାଧ୍ୟମରେ ପ୍ରବାହିତ ପ୍ରତ୍ୟେକ ଅନୁରୋଧ ପାଇଁ:

1. `resolveDisabledGuardrails(...)` API କୀ, ବଡି ଏବଂ ହେଡର୍ଗୁଡ଼ିକରୁ ଛାଡ଼ିଦେବା ତାଲିକା ତିଆରି କରେ।
2. `guardrailRegistry.runPreCallHooks(body, ctx)` ଆରୋହୀ
   ପ୍ରାଥମିକତା କ୍ରମରେ ଗାର୍ଡରେଲ୍ଗୁଡ଼ିକୁ ଚଲାଏ:
   - ଅକ୍ଷମ କରାଯାଇଥିବା ଗାର୍ଡରେଲ୍ଗୁଡ଼ିକୁ `skipped` ଭାବେ ରେକର୍ଡ କରାଯାଏ।
   - ପ୍ରତ୍ୟେକ ଗାର୍ଡରେଲ୍ର `preCall`, `modifiedPayload` ମାଧ୍ୟମରେ ପେଲୋଡ୍କୁ ପୁନଃଲିଖନ କରିପାରେ।
   - ପ୍ରଥମ `block: true` ଶୃଙ୍ଖଳକୁ ତୁରନ୍ତ ବନ୍ଦ କରେ ଏବଂ ହ୍ୟାଣ୍ଡଲର୍
     ଏକ ଗାର୍ଡରେଲ୍ ପ୍ରତ୍ୟାଖ୍ୟାନ ପ୍ରତିକ୍ରିୟା ଫେରାଏ।
3. (ସମ୍ଭାବ୍ୟ ଭାବେ ପୁନଃଲିଖିତ) ପେଲୋଡ୍ କମ୍ବୋ ରାଉଟିଂ ଏବଂ ଅପ୍ଷ୍ଟ୍ରିମ୍
   ଡିସ୍ପ୍ୟାଚ୍କୁ ପ୍ରବାହିତ ହୁଏ।
4. ପ୍ରତିକ୍ରିୟା ସଂଯୋଜିତ ହେବା ପରେ, `guardrailRegistry.runPostCallHooks(...)`
   ପ୍ରତିକ୍ରିୟା ଉପରେ ସେହି ସମାନ ଶୃଙ୍ଖଳକୁ ଚଲାଏ। ଏଠାରେ `block: true` ଅପ୍ଷ୍ଟ୍ରିମ୍
   ପ୍ରତିକ୍ରିୟାକୁ ବାତିଲ କରେ।

ତ୍ରୁଟି ଥ୍ରୋ କରୁଥିବା ଗାର୍ଡରେଲ୍ଗୁଡ଼ିକୁ `error: <message>` ସହିତ ରେକର୍ଡ କରାଯାଏ ଏବଂ
`logger.warn` ମାଧ୍ୟମରେ ଲଗ୍ କରାଯାଏ, କିନ୍ତୁ ଶୃଙ୍ଖଳ ଚାଲୁ ରହେ — ଡିଜାଇନ୍ ଅନୁଯାୟୀ ଏହା ଫେଲ୍-ଓପନ୍ ଅଟେ।

## କଷ୍ଟମ୍ ଗାର୍ଡରେଲ୍ଗୁଡ଼ିକ

```typescript
import { BaseGuardrail, guardrailRegistry } from "@/lib/guardrails";

class BudgetGuardrail extends BaseGuardrail {
  constructor() {
    super("budget", { priority: 50 });
  }

  async preCall(payload, ctx) {
    if (ctx.apiKeyInfo?.budgetExceeded) {
      return { block: true, message: "Daily budget exceeded" };
    }
    return { block: false };
  }
}

guardrailRegistry.register(new BudgetGuardrail());
```

ପଦକ୍ଷେପଗୁଡ଼ିକ:

1. `BaseGuardrail`କୁ ବିସ୍ତାର କରି `src/lib/guardrails/myGuardrail.ts` ସୃଷ୍ଟି କରନ୍ତୁ।
2. `preCall` ଏବଂ/କିମ୍ବା `postCall` କାର୍ଯ୍ୟକାରୀ କରନ୍ତୁ।
3. ଇମ୍ପୋର୍ଟ ସମୟରେ ପଞ୍ଜୀକରଣ କରନ୍ତୁ (`registerDefaultGuardrails`ରୁ ପୁଶ୍ କରି) କିମ୍ବା
   ରନ୍ଟାଇମ୍ରେ `guardrailRegistry.register(...)` କଲ୍ କରନ୍ତୁ — ସମାନ ସାମାନ୍ୟୀକୃତ ନାମ
   ଥିବା ଯେକୌଣସି ପୂର୍ବବର୍ତ୍ତୀ ଗାର୍ଡରେଲ୍କୁ ରେଜିଷ୍ଟ୍ରି ପ୍ରତିସ୍ଥାପନ କରେ।
4. `tests/unit/` ଅଧୀନରେ ପରୀକ୍ଷଣ ଯୋଡ଼ନ୍ତୁ (ବିଦ୍ୟମାନ ଉଦାହରଣ:
   `tests/unit/guardrails-registry.test.ts`,
   `tests/unit/prompt-injection-guard.test.ts`,
   `tests/unit/guardrails/visionBridge.test.ts`)।

## ପରୀକ୍ଷଣ

ଏକ ଜଣାଶୁଣା ଅବସ୍ଥାରୁ ଆରମ୍ଭ କରିବା ପାଇଁ ପରୀକ୍ଷଣଗୁଡ଼ିକ ମଧ୍ୟରେ `resetGuardrailsForTests()` ବ୍ୟବହାର କରନ୍ତୁ।
ଏକ ଖାଲି ରେଜିଷ୍ଟ୍ରିରୁ ଆରମ୍ଭ କରିବା ପାଇଁ `{ registerDefaults: false }` ପାସ୍ କରନ୍ତୁ ଏବଂ
କେବଳ ପରୀକ୍ଷଣାଧୀନ ଗାର୍ଡରେଲ୍ଗୁଡ଼ିକୁ ପଞ୍ଜୀକରଣ କରନ୍ତୁ। Vision Bridge ନିର୍ଭରତା
ଇଞ୍ଜେକ୍ସନ୍ (`deps.getSettings`, `deps.callVisionModel`) ଗ୍ରହଣ କରେ; Audio Bridge ସେଟିଂସ୍,
କ୍ଷମତା, STT ମଡେଲ୍ ଚୟନ, ପରିଚୟପତ୍ର ଯାଞ୍ଚ ଏବଂ ଟ୍ରାନ୍ସକ୍ରିପ୍ସନ୍ ପାଇଁ ସମତୁଲ୍ୟ
ସଂଯୋଗ ବିନ୍ଦୁଗୁଡ଼ିକ ଉପଲବ୍ଧ କରାଏ। ତେଣୁ ପରୀକ୍ଷଣଗୁଡ଼ିକ DB କିମ୍ବା ନେଟୱର୍କ
ଆକ୍ସେସ୍ ବିନା ଉଭୟ ପ୍ରବାହକୁ ପରୀକ୍ଷା କରିପାରିବ।

## ଇଞ୍ଜେକ୍ସନ୍-ଗାର୍ଡ ରୁଟ୍ କଭରେଜ୍ ଏବଂ ରେଡ୍-ଟିମ୍ (Phase 8 · Block D)

ଇଞ୍ଜେକ୍ସନ୍-ଗାର୍ଡ (`createInjectionGuard` / `withInjectionGuard`) ବ୍ୟବହାରକାରୀ ପ୍ରମ୍ପ୍ଟ
ଗ୍ରହଣ କରୁଥିବା ସମସ୍ତ ରୁଟ୍କୁ ଅନ୍ତର୍ଭୁକ୍ତ କରେ। ଏହା `INJECTION_GUARD_MODE`କୁ ସମ୍ମାନ କରେ (ଡିଫଲ୍ଟ `warn` = କେବଳ ଲଗ୍;
`block` = HTTP 400 `SECURITY_001` ଫେରାଏ)।

| ପ୍ରକାର             | ରୁଟ୍ଗୁଡ଼ିକ                                                                                                                                           | ଡିଫଲ୍ଟ ମୋଡ୍ |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ----------- |
| ଟେକ୍ସଟ୍ (ବିଦ୍ୟମାନ) | `/v1/chat/completions`, `/v1/completions`, `/v1/relay/chat/completions`                                                                              | warn        |
| ଜେନେରେଟିଭ୍         | `/v1/messages`, `/v1/responses`, `/v1/images/generations`, `/v1/images/edits`, `/v1/videos/generations`, `/v1/music/generations`, `/v1/audio/speech` | warn        |
| ଡାଟା               | `/v1/embeddings`, `/v1/rerank`, `/v1/search`, `/v1/moderations`                                                                                      | warn        |

ଟେକ୍ସଟ୍ ନିଷ୍କାସନ (`extractMessageContents`) `messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system`କୁ ଅନ୍ତର୍ଭୁକ୍ତ କରେ।

**ରେଡ୍-ଟିମ୍ (ପ୍ରତିରାତି, `nightly-llm-security.yml`):** promptfoo ଯାଞ୍ଚ କରେ ଯେ ପ୍ରତ୍ୟେକ ରୁଟ୍
`INJECTION_GUARD_MODE=block`ରେ OWASP-LLM କର୍ପସ୍କୁ ବ୍ଲକ୍ କରେ; garak ପ୍ରୋବ୍ଗୁଡ଼ିକ ଚଲାଏ (ସିକ୍ରେଟ୍ ନଥିଲେ ଏଡ଼ାଇଯାଏ)।
ସୁସଙ୍ଗତି ପାଇଁ `moderations`କୁ ଅନ୍ତର୍ଭୁକ୍ତ କରାଯାଇଛି — block-modeରେ ଅପରେଟର୍ମାନେ
`resolveDisabledGuardrails` ମାଧ୍ୟମରେ ଏହାକୁ ଛାଡ଼ ଦେଇପାରିବେ।

ପ୍ରତିରାତିର ୱର୍କଫ୍ଲୋ (`.github/workflows/nightly-llm-security.yml`, cron + ମାନୁଆଲ୍
ଡିସ୍ପାଚ୍)ରେ ଦୁଇଟି ଜବ୍ ଅଛି:

- **`promptfoo-guard` (ବ୍ଲକିଂ)** — `INJECTION_GUARD_MODE=block` ସହିତ
  `promptfoo eval -c promptfooconfig.yaml` ଚଲାଏ। ପ୍ରତ୍ୟେକ ପ୍ରତିକୂଳ କେସ୍ (ଉଦାହରଣ ସ୍ୱରୂପ, "ପୂର୍ବବର୍ତ୍ତୀ ସମସ୍ତ
  ନିର୍ଦ୍ଦେଶକୁ ଅଣଦେଖା କରନ୍ତୁ…", DAN-ଶୈଳୀର ଜେଲ୍ବ୍ରେକ୍) ନିଶ୍ଚିତ କରେ ଯେ ପ୍ରତିକ୍ରିୟାରେ
  `error.code === "SECURITY_001"` ରହିଛି, ଅର୍ଥାତ୍ ଗାର୍ଡ ପ୍ରକୃତରେ ଅନୁରୋଧକୁ ପ୍ରତ୍ୟାଖ୍ୟାନ କରିଛି।
- **`garak` (ପରାମର୍ଶମୂଳକ)** — ଏକ ସ୍ଥାନୀୟ OmniRoute ଇନ୍ଷ୍ଟାନ୍ସ
  (`http://localhost:20128/v1`) ବିରୁଦ୍ଧରେ garak `--probes promptinject,dan,leakreplay` ଚଲାଏ। ଏହା ଏକ
  ପ୍ରଦାନକାରୀ ସିକ୍ରେଟ୍ (`PROMPTFOO_PROVIDER_KEY`) ଉପରେ ନିର୍ଭରଶୀଳ; ସିକ୍ରେଟ୍ ନଥିଲେ ସୁଚାରୁ ଭାବରେ ଏଡ଼ାଇଯାଏ ଏବଂ ଏଥିରେ
  `|| true` ପ୍ରତ୍ୟୟ ଯୋଡ଼ାଯାଇଛି, ତେଣୁ ଏହା CIକୁ ବିଫଳ ନକରି ରିପୋର୍ଟ କରେ।

ଗାର୍ଡ ସହାୟକ (`createInjectionGuard` / `withInjectionGuard`)ର କଭରେଜ୍
ପ୍ରମ୍ପ୍ଟ ବହନ କରୁଥିବା ପ୍ରତ୍ୟେକ `/v1` ରୁଟ୍କୁ ବ୍ୟାପିଛି; ପ୍ରମ୍ପ୍ଟ ଟେକ୍ସଟ୍
`src/shared/utils/inputSanitizer.ts`ରେ ଥିବା `extractMessageContents()` ଦ୍ୱାରା
`messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system`ରୁ ନିଆଯାଏ।
